# Codex Dock for Windows 0.19.2

修复选择服务新增加的主模型后，因旧能力目录没有该模型的专用审核映射而无法保存的问题。

1. 在 Codex 配置中点击“获取服务模型”。服务返回完整原生能力时，会显示“原生能力已暂存”。
2. 选择 `gpt-6.2-sol` 等当前服务列出的模型，核对需要移除或保留的配置覆盖。
3. 点击“查看并确认修改”。主模型、能力目录和固定 `codex-auto-review` 映射一起备份、确认保存。
4. 保存后按原有入口应用到 Codex，在新聊天核对所选模型和审核行为。

获取和取消都不写配置。服务只返回模型名称时仍需导入原生能力 JSON；不会猜测模型上下文、速度或审核能力，也不会关闭自动审核来绕过校验。更换服务地址、凭据、连接方式、协议、代理或 HTTP 确认后需重新读取。手工文件导入仍保留原来选择的来源。

这是本地修复安装包。先在旧 Dock 选择“停止网关并退出”，再运行 `CodexDock-0.19.2-Setup-win-x64.exe`，选择原目录覆盖安装，无需先卸载。安装后重新输入尚未保存的草稿；安装器不读取或迁移旧窗口中的内存草稿。用户配置、登录、聊天和安卓身份保持各自的数据目录。

源码包括[三个上游的本次复用评估](upstream-reuse-review-2026-11-18.md)。本修复未合并其中的代理排除、账号库、会话迁盘或手机图表功能。安装器包含既有运行库与手机后台；安卓 APK 不因本次 Windows 修复重新发布。

如需回退，停止网关并退出后可覆盖安装 0.19.1；新保存的目录仍为兼容的原生 JSON 与已有 v1 管理记录，需要时先在“备份与恢复”恢复配置。验证范围见[本版审查](review-0.19.2.md)。
