# 旧聊天接续与连接更新

开发实现于 2026-11-14，尚未制作安装器或发布。功能默认关闭，按 Codex 配置目录分别保存。

在 **客户端增强** 中启用“更换模型入口后继续原聊天”，保存连接草稿，然后点击页面底部固定的“打开或重启 Codex 并应用”。速度档位兼容也集中在此页，两项共用一次应用。开关按当前配置目录立即保存，配置草稿仍需统一确认。连接页、模型页和应用设置保留前往此页的入口。

两项增强需要 **Dock 保持运行**，可以收起到托盘，功能本身不依赖模型网关。API Key 直连无需启动模型网关；混合连接仍需模型网关转发模型请求。关闭窗口会收起到托盘，完全退出 Dock 后增强停用，已经启动的网关继续独立运行。页面提供 Dock 开机启动设置入口；Windows 开机启动、网关自动启动、增强自动接回分别设置，互不代为开启。

现在可在 **启动与自动接回** 中选择“启用增强启动与自动接回”，默认关闭，按配置目录独立保存。开启并选择需要的增强后，可创建标准 Windows `Codex（增强）.lnk` 快捷方式，保存位置由用户选择。以后双击快捷方式，先打开或通知现有 Dock；尚未运行 Codex 时打开一次并接入增强，已有合适实例时接回并切到该窗口。首次加载、实例不明确或需要重启时保留明确确认。关闭自动选项后，已有快捷方式返回增强设置，不会重新开启开关。

自动接回只恢复上次成功接入的实例：程序文件、PID、创建时间、资料目录、本机监听者、配置摘要、增强方案及页面标记都要匹配。普通重开 Dock 不会主动启动 Codex，也不会自动关闭或刷新现有 Codex。客户端版本、身份、模型目录或其他实际配置变化时提示重新应用；合法运行管道轮换、格式变化和可核对的同账号令牌刷新允许继续。设置中只保存开关、进程和路径元数据、端口及摘要，不保存令牌、API Key 或完整命令行。接续仍有进行中的操作或旧后台的短期连接租约未结束时等待重试。

“自动接回”不等于自动重开 Codex。Codex 已退出时维持等待；需要使用时点增强快捷方式。一次性注入标记缺失或失配时也不会通过后台刷新页面来强行接入。搬动便携目录后，需要重新创建快捷方式。关闭自动选项只停止后续自动接回，当前已应用的增强仍由各自开关控制。

首次接入通过现有统一应用流程，先核对配置与安装入口，再请求 Codex 正常退出并重新打开；原来的未保存内容与退出确认保护继续生效。发现多个 Codex 主实例时，先选择重开后使用的资料目录，不默认选中。可额外勾选“同时退出其他实例，全部退出后只打开一个 Codex”。确认页列出全部待退出的主进程和资料目录；未勾选时保留其他实例。所选旧实例及其子进程必须全部退出，才启动一次；任一实例取消退出、驻留托盘或无法核对时，不打开新实例，并保留单独确认的强制结束入口。批量操作部分成功后，强制重试继续绑定最初的目标，只处理仍存在的旧进程，不扩大范围，也不因为原主实例已经退出而忘掉其他未退出实例。

更换已保存的模型入口后，下一次发送或打开旧聊天会先核对原生状态。回复进行中继续使用原连接；空闲时等待原生卸载，再使用当前入口恢复。跨 provider 的旧聊天会先加密备份并准备本机索引，再恢复同一聊天 ID。历史文件不被改写，已选模型、推理和速度设置保留，原始输入及其 UUID 只提交一次。

如果其他窗口仍使用聊天，原生可能暂不卸载。Dock 最多等待约 110 秒，再提示关闭该聊天的其他窗口后重试。准备失败不会自动重发用户输入。项目、活动 Profile 或远程执行端的独立连接继续由原生客户端管理；检测到项目覆盖与当前入口不一致时，先提示核对。

登录身份、直连 API Key 或受管模型目录改变时，当前内核仍需重开。模型目录会显示加载状态未确认，统一应用入口会重新打开 Codex。目录文件同步不会被显示为已经热更新。

模型网关协议升级为 **7**。新的 HTTP 请求逐次读取已保存的入口；已有 WebSocket 在本次响应完成后退役，后续连接使用新入口和新 Key。未完成或无法识别的响应保持保守处理，沿用连接超时保护。现有后台需通过网关管理正常重启才能加载新协议，刷新状态不会替换后台。

开关设置位于 `%LOCALAPPDATA%\CodexConfig\gateways\<目录标识>\desktop-connections.json`，只保存布尔值。逐聊天恢复记录位于当前 Codex 目录的 `codex-dock-thread-backups`，使用当前 Windows 用户的 DPAPI 加密；写入前持久化记录，事务失败保留待恢复状态。多 SQLite 库在 WAL 下无法保证掉电时整体原子提交，下次对同一空闲聊天准备时会核对并恢复，不覆盖第三方改成的供应商。

客户端模块通过当前本机调试连接在加载时适配。仅匹配已经核对的 manager 请求入口，不改 Codex 安装文件、CSP 或通用消息分发器；结构未匹配时先停止应用。关闭开关后停止接续；退出 Dock 后短期租约失效，恢复原生请求行为。再次打开 Dock，可由已开启的自动选项接回符合记录的页面，其他情况通过明确的增强启动重新应用。

Windows 程序路径核对增加卷序列号与 128 位文件 ID。路径不同但指向同一商店 EXE 时可识别，程序被替换时停止重启；原有包身份、进程句柄和创建时间检查保留。权限不足、链接不能解析或身份不明确时拒绝扩展操作范围。

实例资料目录只从已核对 GUI 进程树的启动参数中提取，不记录完整命令行。Windows 进程命令行查询是可选能力，不可用时保持保守处理。多实例的资料目录不明确、相互冲突或相同，则在退出前停止应用。进程退出后只等待所选树，启动后必须核对新的主进程及相同资料目录，不能把另一套已经运行的 Codex 当作本次成功。

增强启动与自动接回复用现有 Dock 托盘进程，没有增加后台服务或修改 Codex 安装文件。旧聊天接续需要本机索引准备和连接状态处理。面向新用户的连接页现仅填写服务地址、API Key 和协议，取消 Krill 服务商及线路预设；新方案库和“恢复内置方案”也不再自动加入 Krill 社区方案。已有用户保存的连接及自定义历史方案仍能读取，来源记录保留，不在升级时改写其地址或设置。
