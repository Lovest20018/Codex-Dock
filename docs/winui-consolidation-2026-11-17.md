# Windows 新版 UI 整合实施

本轮按 [UI 整合方案](winui-ui-consolidation-plan-2026-11-16.md) 执行，将按功能迁移批次排列的界面改为按任务组织。现有配置、授权、恢复和进程控制仍通过原 Application/Core 服务执行。

## 入口与布局

原 17 个同级入口收敛为 5 个主要任务和 2 个底部入口：

| 一级任务 | 二级内容 |
| --- | --- |
| 工作台 | 当前配置、待处理事项、增强及服务状态、下一步 |
| Codex 配置 | 连接、模型与行为、高级配置、方案与 Profile |
| 运行与增强 | Codex 与增强、模型网关 |
| 手机访问 | 连接与配对、授权设备、服务设置 |
| 诊断与恢复 | 已保存文件、配置来源、聊天参数、备份恢复 |
| 设置 | 启动与窗口、软件更新、关于 |
| 帮助 | 七类可搜索任务说明与入口跳转 |

原有功能均有对应目的地。方案与 Profile 共享资源入口，使用明确的管理对象选择区分，保留两套独立编辑与保存。导航使用包含任务、页面、说明和保存范围的路由描述；页面内容、草稿和服务继续复用。

完整目录与文件命令收进顶部配置目录菜单，长目录名可省略显示，完整路径在菜单中查看和复制。标题及二级导航固定在内容上方，内容独立滚动；窄窗口用页面选择器代替横排标签，低高度窗口省去副标题，保留主要入口。各任务记住最后访问的页面，页面滚动位置单独保留。

## 连续操作

连接页集中设置地址、认证和协议，名称与备注折叠。默认模型仅在模型与行为页编辑，服务模型发现与选择位于同一页，连接页显示同步摘要并提供跳转。缺少模型时保存会指向模型编辑区；错误输入与其他草稿继续保留。模型能力目录工具按需展开。

保存成功后，原配置区域提供应用入口，继续执行原差异确认、实例选择、外部冲突检查与重启保护。无修改且没有本轮保存结果时，连接页不常驻无关的应用栏；主动应用仍位于运行与增强。

手机访问的服务设置同时包含入口配置、独立保存并启动、启停及自动启动。连接与配对、授权设备另有明确的二级页，完成手机接入不再跳模型网关。模型服务控制与统计位于运行与增强；两种服务调用同一份网关管理状态和控制方法。停止并退出时若只有手机服务失败，返回手机服务设置展示失败结果。

工作台根据已观察到的状态提供下一步：设置连接、查看修改、应用已保存配置、重试增强或查看恢复。文件保存、本次应用与聊天实际采用情况分别表述，未确认的服务状态保留未知。

## 保存范围与状态

顶部待处理修改菜单汇总主配置、Profile、方案编辑及手机设置，并跳转到所属编辑区，不提供跨范围全部保存。

底部按钮仅对应当前对象：主配置、Profile、方案库编辑、手机服务设置。帮助、已保存文件及其他只读诊断不会因为主配置有草稿而出现主配置保存栏；`Ctrl+S` 同样遵守当前对象范围。模型配置保存与实际应用仍为两步。

增强、网关自动启动等开关继续立即保存偏好，页面明确说明保存时机与实际运行状态。切换目录、重读、增强启动和退出继续逐个处理独立草稿；每次保存使用原确认和冲突检查，取消或失败后停留。没有新增跨文件提交协议。

## 验证

本轮新增整合专项，覆盖旧目的地映射、两级导航、模型编辑与摘要、手机服务归属、只读页面快捷键、四份同时存在的草稿、资源切换、当前保存范围及大小窗口布局。原有回归保留保存、授权、外部修改、恢复、网关真实启停及实例保护的断言，并调整入口及布局相关断言。

验证数据均为隔离目录、虚构连接和认证；服务模型结果、HTTPS 检测、配对及桌面应用使用既有替身。实际自带模型和手机后台另在隔离目录执行启停，不连接公网模型或手机。剪贴板与目录命令使用内存/记录替身，不接触用户剪贴板和实际文件管理器。

最终 WinUI 完整窗口 377 项通过，其中整合专项新增 37 项；共享核心与应用层完整回归 345/345 通过。完整窗口覆盖 1120×820、900×760、720×540，并另有更窄逻辑区域的动作换行压力检查。这些布局检查不代表物理 DPI 或真实手机设备验证。

旧版 WPF 完整窗口 309 项也在本轮重新执行通过。两套窗口及测试程序引用的 Core/Application 文件 SHA-256 一致，最终 WinUI 和 WPF 报告各自匹配对应程序文件；手机后台 507 个文件与既有构建逐一匹配。构建零警告零错误，源码及交付隐私扫描、差异空白检查通过。

证据位于 `artifacts/ui-consolidation-2026-11-17`：`verification-summary.json`、`core-full.log`、`wpf-complete/report.json`、`preview-complete/ui-876d7cdc3d8942a18ade6ff35a065a35/report.json`、`preview-complete/SHA256SUMS.txt` 和 `preview-complete/screenshots/`。`verify-delivery.ps1` 可再次核对报告、共享程序集、后台及使用说明。最终测试进程全部退出，原有用户预览和安装版手机服务保持运行。

自动化任务路径对应如下，不将其描述为人工可用性试验：

| 任务 | 已验证路径 |
| --- | --- |
| 更换服务 | 地址与认证草稿 → 脱敏差异 → 取消或确认保存 → 原实例选择与应用替身 |
| 调整模型 | 同页模型编辑与目录获取 → 连接摘要同步 → 原保存 → 同区域提供应用入口 |
| 手机接入 | 服务设置独立保存 → 检测与配对替身 → 授权设备 → 隔离实际后台启停 |
| 核对聊天参数 | 诊断与恢复 → 明确选择记录 → 读取元数据、取消与旧结果拒绝 |
| 恢复备份 | 诊断与恢复 → 选择记录 → 核对差异与来源 → 取消或执行原恢复服务 |

早期回归曾在移动后的模型网关页查找手机按钮，已将布局检查更新到实际所属对象；运行页有主配置草稿时出现空操作栏的问题也已修正，现显示保存提示和不可用的应用按钮。一次隔离手机后台启动未成功，保留在 `ui-full-r2/failure.txt`，未判为通过；507 个后台文件逐一匹配，随后完整核心与最终 WinUI 的实际后台启动、重启、认证健康及停止均通过，未修改手机运行时代码或跳过断言。最终结果以匹配交付程序集的报告为准。

## 交付范围

完整预览位于 `artifacts/ui-consolidation-2026-11-17/preview-complete/app/CodexDock.WinUI.exe`，需保留整个 `app` 目录。已有预览采用单实例，先从托盘明确退出旧预览，再打开本轮程序。

WPF 仍是默认交付入口。本轮包含共享帮助说明更新，需验证旧版窗口兼容性；不更改默认安装入口或发布正式版。Android 界面、真实 Codex 重启、手机公网设备、其他物理 DPI 与 Windows 10 设备验证另行记录。本轮不将自动布局检查描述为用户可用性试验，也不宣称操作效率提高百分比。
