# Windows 更新与聊天参数迁移记录

本轮为 WinUI 预览补齐软件更新与本机聊天参数页面，WPF 改用相同应用服务。默认交付入口仍为 WPF，WinUI 保持独立预览；没有发布新版本、执行真实安装器或修改安卓资源。

## 行为

- 软件更新由用户手动检查指定 GitHub 仓库的正式发布。来源、资产名称、重定向、大小和 SHA-256 校验继续由 Core 的 `GitHubUpdates` 负责；窗口不实现第二套下载协议。检查或下载失败、取消时清除过期状态，只有校验通过后才提供安装。
- 安装先处理主配置、Profile、方案和手机设置草稿，再显示正式版安装范围、当前目录及将中断的两个网关。正式版安装器安装现有主程序，不宣称它升级 WinUI 预览界面。
- `UpdateInstallationService` 重新验证安装包并保持禁止写入/删除的文件句柄。等待自动接回释放已有租约后，占用共享安装租约，停止本窗口增强及当前目录已保存的两个网关，复核网关定义和停止状态，最后才调用安装器。安装包变化、配置变化、取消、停止不确定或启动失败均保留窗口供核对；已经停止的后台不会暗中重启。
- WinUI 的更新比较版本与 WPF 保持同为 `0.18.0`。此前未声明的预览程序集使用默认 `1.0.0`，会影响正式版比较；现显式声明版本，并由预览构建脚本核对源码版本与实际 DLL。
- 聊天参数先刷新当前目录的近期文件，再明确选择和读取。只返回模型、推理、服务档位、审批、自动审核结果和记录时间，不返回提示词、工具参数或聊天内容，不从配置推断实际审核模型。读取不会选择最新聊天或保存任何配置草稿。
- Core 从打开时固定长度的尾部读取，最多 8 MiB，避免活动文件持续追加造成无界读取；损坏 JSON、非对象元数据和半行会被忽略。列表与读取支持取消，并在完成时核对当前目录和选择，窗口关闭或条件改变后不回填旧结果。

## 使用与后续

运行 `artifacts/winui-updates-2026-11-16/preview-final/app/CodexDock.WinUI.exe`，保留整个 `app` 目录。已有预览为单实例，请先从托盘明确退出旧预览，再打开新文件。

截图与校验和位于 `preview-final/screenshots` 和 `preview-final/SHA256SUMS.txt`，验证汇总位于 `verification-summary.json`。后续继续核对首次配置、其他 WPF 入口及网关耗时/压缩指标的展示覆盖，再进行系统设备验收与默认入口决策；安卓视觉优化仍按 Windows 优先的顺序处理。
