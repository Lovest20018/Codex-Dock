# Codex 的统一应用与重启流程

Windows 0.18.0 将保存完成、概览、速度兼容和备份恢复接入同一个应用面板。应用使用当前已保存的文件；打开或刷新面板不会写入配置，也不会发起模型测试。

## 本次截图的原因

只读核对最新加密备份，按该次 `model_reasoning_effort` 编辑重建文件，SHA-256 与保存记录完全一致。保存后文件的实际变化是 `mcp_servers.node_repl.env.SKY_CUA_NATIVE_PIPE_DIRECTORY`：Codex 将本机计算机操作管道更新为另一个运行实例的地址。`auth.json` 的摘要保持不变。

此前重启入口沿用保存时的逐字节检查，因此把这项运行信息更新也报成“配置被其他程序修改”。新核心只允许该字段在两个标准 `\\.\pipe\codex-computer-use-<GUID>` 地址之间轮换，同时保留最新文件。其他 MCP 环境项、目录、模型、推理、速度、审核策略和凭据的变化仍需核对。

同一设置的注释、排版与 JSON 属性顺序变化不再阻止启动或保存。保存先将已确认的设置修改合并到最新文件，保留新注释和当前管道；在最终写入前仍核对实际文件，运行信息再次变化时有限重试，实际设置变化立即停止。官方账号的令牌刷新，仅在账号 ID、身份令牌中的发行方及用户标识一致，且其余内容未变时采用最新凭据；身份无法关联时要求核对。Dock 不将旧令牌写回文件。

2026-11-13 补查将同一规则覆盖到保存后的复核、备份恢复、中断恢复、后台状态和官方登录读取。新加密备份包含保存前后快照，可核对令牌与运行信息变化后恢复设置。旧备份继续兼容：管道变化必须重建出与原保存摘要完全一致的内容才允许恢复；无法证明差异时保留当前文件并说明原因。模型目录内容及管理索引、用户环境变量、写入锁、真实账号变化继续受到原有保护。

## 操作方式

1. 修改配置并确认保存，或在概览点击“打开／重启 Codex 并应用”。速度卡片和恢复结果进入相同面板。
2. Dock 核对当前文件、模型目录与桌面安装。API Key 直连无需本机模型网关；混合连接先准备该目录的网关，成功后才请求 Codex 退出。
3. 面板显示核对配置、准备连接、退出旧实例、打开 Codex、核对进程／加载速度兼容的进度。窗口不能在处理期间重复发起应用、切换目录或退出 Dock。
4. 完成后到 Codex 新建聊天核对。进程已经打开、兼容已加载和聊天实际采用的参数分别显示。

| 遇到的情况 | 当前处理 |
| --- | --- |
| 设置确实在确认后变化 | 列出具体字段或文件。点击“读取最新配置并核对”查看脱敏差异，再点击应用；不覆盖外部文件 |
| 文件语法或目录依赖有问题 | 在退出 Codex 前报告原因，保留现有实例 |
| 取消退出、关窗后仍在托盘 | 保留旧实例与其兼容连接，可重试正常退出；单独提供“结束该实例并重开…” |
| 明确选择结束实例 | 再次确认任务与未保存内容可能丢失；重新核对主进程路径及启动时间，只结束该实例及其子进程 |
| 确认后新建渲染子进程 | 识别为同一主实例的后代，允许正常退出；新主实例或身份变化仍阻止操作 |
| Codex 已打开，速度兼容失败 | 显示部分完成，提供“重试速度兼容”；重新连接同一实例并刷新页面，不再次重启 Codex |
| 上次的实例已退出或被替换 | 不沿用旧的兼容重试目标，要求重新核对启动 |
| 当前 Codex 已关闭或由其他方式重新打开 | 概览不继续把之前的应用记录当作当前实例已加载的证据 |

“结束该实例”不会由超时自动触发，也不会按 `ChatGPT.exe`／`codex.exe` 名称批量结束进程。正常退出未完成时，已有的速度兼容会话保持运行。如果 Dock 本身位于目标实例的进程树中，拒绝结束该树，提示从资源管理器独立打开 Dock 后再操作，防止关闭负责重开的程序。

## 对照 Codex++

本轮固定核对公开提交 [`a5d11ec5a50d62e78e94682477b6399a2fae0f94`](https://github.com/BigPizzaV3/CodexPlusPlus/commit/a5d11ec5a50d62e78e94682477b6399a2fae0f94)，没有混用不同版本的实现：

- [CodexLaunchButton.tsx](https://github.com/BigPizzaV3/CodexPlusPlus/blob/a5d11ec5a50d62e78e94682477b6399a2fae0f94/apps/codex-plus-manager/src/CodexLaunchButton.tsx)：各入口共用启动状态和动作，运行时显示重启，处理中阻止重复操作。
- [commands.rs](https://github.com/BigPizzaV3/CodexPlusPlus/blob/a5d11ec5a50d62e78e94682477b6399a2fae0f94/apps/codex-plus-manager/src-tauri/src/commands.rs#L3162)：串行启动任务、停止前准备、分阶段进度、基于实际会话目标停止，并将启动受理与最终结果分开。
- [launch-status.ts](https://github.com/BigPizzaV3/CodexPlusPlus/blob/a5d11ec5a50d62e78e94682477b6399a2fae0f94/apps/codex-plus-manager/src/launch-status.ts)：区分处理中、运行、功能待连接及失败，避免旧启动结果冒充本次完成。

Dock 用 C# 独立实现这些交互原则，并保留正常退出及单独确认结束实例的流程。没有导入或执行上游程序。应用记录当前保留在 Dock 内存中，重新打开 Dock 后采用“是否加载未确认”，不承诺恢复上次进程状态。

项目、Profile 与组织配置仍可影响实际取值，见 [OpenAI 官方配置说明](https://learn.chatgpt.com/docs/config-file/config-basic)。重新打开成功不能替代真实聊天和服务后台的核对。
