# 纯 API 的 Fast / Ultrafast 兼容

2026-11-12 本地开发实现；提交、推送和发版继续暂停。

当日最终实机进展：用户已确认图标恢复，并在重启、选择 Ultrafast 后核对真实后台，最终反馈测试正常。客户端会话记录也确认 `service_tier=ultrafast`。下文保留各阶段验证的原始边界；当前真实使用与后续产品化说明见[推理与审核核对](codex-max-auto-review-diagnosis-2026-11-12.md)和[今日 Dock 方案](progress-and-dock-plan-2026-11-12.md)。本次未进行速度倍数或费用的对照测量。

## 使用

1. 在“连接与账号”保存 API Key 直连。旧 PAT 需先显式迁移；当前功能不应用于活动 Profile、官方登录或混合网关配置。
2. 到“模型与行为 → 速度 → 桌面速度兼容”开启当前配置目录的开关，再点击“打开／重启 Codex 并应用”。应用设置保留跳转入口。正常退出提示允许取消，未保存的草稿需先确认保存。
3. 确认兼容状态显示“已应用”，在“模型与行为”启用需要的 Fast / Ultrafast 选项，然后在 Codex 新聊天中选择档位。仍保留原生模型目录、服务要求和档位解析，兼容开关本身不会强制给模型添加档位。
4. 保持 Dock 运行，可以收起到托盘。关闭开关、退出 Dock、切换配置目录或更换已保存的连接会停用兼容；重新打开 Dock 时需要再次应用。完全退出 Codex 后关闭本次调试端口。

“兼容状态”位于该卡片的说明文字下方、应用按钮上方。点击后打开统一[应用面板](codex-restart-flow-2026-11-12.md)，显示查找桌面端、等待退出、等待主页面、加载模块及最终状态，同时保留卡片反馈。Codex 已打开但兼容加载失败时可单独重试，不再次重启。商店版通过该 Codex 包的专属执行别名启动，保留商店应用身份及对应数据目录；启动入口在请求退出前核对，不使用全局同名别名，也不直接运行包内 EXE。

选项默认关闭，按规范化配置目录的摘要隔离，保存在本机应用数据目录的 `CodexConfig/gateways/<摘要>/desktop-speed.json`，仅包含布尔值。更改此选项不会写入 Codex 配置、认证、模型目录或网关凭据。

## 参考与实现

参考 CodexPlusPlus **2.6.6**，固定提交 [`fb3926fac4f9738941c57703a1fb47b7b0072cee`](https://github.com/BigPizzaV3/CodexPlusPlus/commit/fb3926fac4f9738941c57703a1fb47b7b0072cee) 的 [`native-fast-rspack.js`](https://github.com/BigPizzaV3/CodexPlusPlus/blob/fb3926fac4f9738941c57703a1fb47b7b0072cee/assets/inject/native-fast-rspack.js)、[`native-fast-unlock.js`](https://github.com/BigPizzaV3/CodexPlusPlus/blob/fb3926fac4f9738941c57703a1fb47b7b0072cee/assets/inject/native-fast-unlock.js) 和 [`bridge/native_fast.rs`](https://github.com/BigPizzaV3/CodexPlusPlus/blob/fb3926fac4f9738941c57703a1fb47b7b0072cee/crates/codex-plus-core/src/bridge/native_fast.rs)。

上游运行时代码使用 AGPL-3.0。本项目保留 MIT，未复制、嵌入或分发上游 JavaScript / Rust 文件；在现有 C# 架构中独立实现其四处认证门控的处理机制：

| 门控 | 处理范围 |
| --- | --- |
| 桌面菜单 | 本机 API 身份可进入原生档位读取 |
| 普通请求 | 读取服务要求后保留原生档位解析 |
| 排队默认档位 | 放行本机 API，保留 Copilot 检查 |
| 排队显式档位 | 同时核对实际执行端、管理端、API 身份和 Copilot |

启动前只读检查已安装客户端 `app.asar` 的四处结构及 Rspack 注册回调。缺少门控、出现重复或变量遮蔽、模块包含不支持的引用时，停止处理。当前已匹配本机 **Codex 26.1106.6628.0**；不据此承诺未来版本兼容。旧 ESM 打包格式尚未接入。

经用户在程序中确认重启后，使用随机的 `127.0.0.1` 调试端口。连接前核对监听进程与选定桌面程序一致，并唯一确认其本机页面。CDP 在原生模块注册回调执行前设置条件断点，仅替换已核对的内存工厂。四处认证门控及当前模型档位读取全部观察到后启用，再等待文档完成注册并刷新一次重算界面；每次暂停处理后恢复执行，连接退出时移除自身调试状态。

不替换安装资源，不使用导入映射、Blob 模块、CSP 绕过或持久化脚本。页面仅接收有期限的布尔许可，不接收 Key、官方令牌或供应商地址。许可每三秒更新，异常断开后最长十五秒失效；正常关闭会立即清除。未知认证、远端执行和 Copilot 均不因本机 API 配置而放行。

## 启动失败修复（2026-11-12）

用户实测反馈首次打开出现 `ChatGPT failed to start / ERR_FAILED (-2)`，随后 Dock 提示未确认桌面进程。只读检查确认：直接运行商店包内 EXE 后，进程没有包身份，旧识别逻辑将已经打开的 Codex 漏掉，兼容会话根本没有建立。启动错误日志只记录 `bootstrap-import-main` 阶段失败，未包含截图中的完整异常，因此不将该截图单独归因为 CDP 刷新。

修复使用当前用户已注册的 Codex 包路径识别无包身份的旧实例；启动改用该包专属的执行别名，并逐项核对 Windows 重解析点的包族、应用 ID 和实际 EXE。别名不匹配时在请求退出前停止。主页面完成启动前不刷新页面；只重试端口或页面尚未就绪的情况，模块编译及结构错误直接报告。启动进度同步到兼容卡片。

原版 `26.1106.6628.0` 已在独立 Electron 用户数据目录与虚构 `CODEX_HOME` 中实际启动，完成四处模块加载并返回“已应用”，测试前后的原聊天主进程保持不变。测试只使用本机无模型服务的虚构地址，没有发送模型任务或操作用户的原聊天。证据位于 `artifacts/desktop-speed-fix-2026-11-12/native-desktop/` 的成功 `result.json`。另以暂停状态启动检查确认专属别名保留包身份及目标 EXE，未执行该检查进程的应用入口。

执行别名及商店数据目录行为参考 [Microsoft 文档中的执行别名说明](https://learn.microsoft.com/en-us/sysinternals/downloads/microsoft-store#app-execution-aliases)和[商店桌面应用的运行方式](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes)。此阶段尚未核对用户原配置中的闪电入口，后续结果见末尾。

## 当前模型档位读取修复（2026-11-12）

用户再次反馈兼容状态已应用而模型选择器没有 Fast。对当前进程进行限定字段的只读诊断，确认兼容许可持续有效，实际执行的菜单函数已替换，服务要求允许 Fast，原始 `model/list` 中的 `gpt-6.1-sol` 带有 `priority / Fast`。但速度设置 Hook 经过原生界面默认模型列表筛选后只剩七个旧模型，不包含当前模型，因此它只能生成“标准”选项。

修复仅在许可有效且为本机时，为速度设置 Hook 的模型查询传入当前已选模型的 `additionalAvailableModels`。使用原生列表中该模型已有的档位元数据；不新增模型或档位，不修改原始目录、账户、服务要求及模型选择器的完整列表。切换模型立即重新读取；远端、关闭或许可失效时恢复原有查询。此前“已应用”只证明模块处理完成，不能作为真实菜单验收。

已匹配本机原版的四处认证门控和七份当前模型读取副本。浏览器回归覆盖当前模型不在默认列表、更换当前模型、未知模型无档位、远端及停用边界，并编译三份原版模块。完整核心回归 **140/140**、速度卡片界面 **12 项**通过，见 `artifacts/desktop-speed-fix-2026-11-12/catalog-core.log`、`catalog-browser-fixed/` 与 `catalog-ui/`。真实服务请求及加速效果仍未验收。

补验发现页面刷新可能使已排队的调试暂停通知失效。现在按实际暂停序号核对调用帧，只恢复当前会话拥有且仍有效的暂停；刷新后重新观察全部五类处理，才报告已应用。隔离浏览器以真实暂停、恢复及第二次暂停验证旧通知不会指向新的暂停。最终原版 Codex 独立实例通过五类处理及原生模型筛选验证：默认列表中为零，带当前模型后为一，并保留原有 `priority / Fast`。测试前后原聊天进程保持不变，证据见 `catalog-stable-browser.log`、`catalog-native-stable.log` 和 `catalog-native-stable/` 的 `result.json`。新建配置的完整聊天菜单及真实请求仍未验收。

## 用户实机确认（2026-11-12）

用户使用最新开发构建后反馈：在任务管理器完全关闭 `ChatGPT.exe` 和 `codex.exe`，重新打开后已能看到 Fast 图标。此结果为用户实机确认，说明图标显示已在其当前环境生效；不据此推断真实请求档位、计费或加速效果。

若更新兼容后仍显示旧菜单，先保存工作并完全退出 Codex，确认属于本次桌面的相关进程已退出，再从 Dock 重新打开并应用兼容。只重新打开窗口不能作为相关进程均已退出的依据。
