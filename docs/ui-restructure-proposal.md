# Codex Config 前端重构方案

日期：2026-10-28。状态：设计提案，尚未修改产品界面。

## 1. 推荐方向

将产品从“配置表单编辑器”调整为“Codex 本地连接与配置控制台”。名称仍保留 Codex Config，继续使用原生 Windows 窗口与现有浅色/深色视觉体系。

用户打开软件时，首先需要知道当前连接如何工作、网关是否运行、有没有待处理的问题；修改配置是下一层操作。因此新增“概览”作为默认首页，把配置编辑、网关即时操作和应用自身设置明确分开。

本次以现有功能重新组织为主。多账号切换、多网关实例管理、历史流量图、自动节点测速、开机自启、完整请求日志均不纳入本次改版。

## 2. 当前界面的问题

| 当前设计 | 使用上的问题 | 本次调整 |
| --- | --- | --- |
| 默认进入常用设置 | 看不到当前模型请求走哪条链路 | 默认概览，先显示连接与运行状态 |
| 服务连接同时承载认证、线路、模型 | 用户不容易理解官方身份与模型凭据的关系 | 连接页管理身份与模型来源，默认模型归入模型与行为 |
| 网关页连续堆放状态、代理、窗口说明 | 操作被长文案推到折叠区域 | 状态与启停固定在顶部，网络设置在主体，窗口行为移到应用设置 |
| 各页面常驻“保存配置” | 启停网关与编辑配置的生效时机容易混淆 | 仅有配置草稿时出现统一草稿栏，即时操作有独立反馈 |
| 字段表与连接助手可能出现重复入口 | 同一项在不同位置编辑，难以判断哪个生效 | 每项设置明确一个主编辑入口，其余位置只展示或跳转 |
| 请求计数与 Fast、审核能力并排展示 | 容易把转发计数误认为后端能力验证 | 计数放到运行详情，显示“携带参数的请求数” |
| 关闭和退出含义不同 | 用户可能以为关掉窗口就停止了服务 | 保留托盘行为，清晰区分“收起窗口”和“退出程序” |

## 3. 信息架构

左侧导航分两组，顺序固定。无需让所有分类都占据一级导航。

```text
Codex Config
  概览
  连接与账号
  模型与行为
  网关与网络

配置管理
  模板与备份       [配置模板 / 备份恢复]
  全部配置         [搜索 / 分类 / 已修改 / 未收录]

底部
  网关：运行中 / 已停止 / 检查失败 / 不适用
  应用设置与帮助
```

顶部全局栏只显示当前配置目录、目录切换入口以及未保存数量。配置目录是当前编辑目标，不称为“工作区”或“环境”，避免暗示已经支持多环境同步切换。

默认进入概览；导航切换保留各页筛选与滚动位置。全部配置中搜索到已有专用编辑入口的连接字段时，展示当前文件值并跳转到对应页面，不提供第二套冲突的编辑器。

## 4. 页面设计

### 4.1 概览：回答“现在是什么状态”

上方为当前连接模式与一条模型路由说明：

- 官方账号 + API：Codex → 本地网关 → 模型入口。
- PAT / API Key：Codex → 模型入口；网关标记为“不适用”。
- 已有官方直连配置：展示从文件读取到的官方连接摘要；第一版不新增官方直连配置向导。
- 未配置：展示“设置连接”入口，不展示虚假的健康状态。

下方使用两列紧凑信息区：

1. **连接摘要**：认证模式、服务商与线路、默认模型；“管理连接”“调整模型”跳到对应页面。
2. **运行状态**：网关监听状态、本地地址、上游代理是否配置；混合模式提供“启动网关 / 停止网关”。

状态词必须有明确证据：

- 本地健康检查成功，只显示“网关运行中”。
- 已读取 OAuth 文件，只显示“已读取官方登录凭据”，不等同于已在线验证账户。
- 模型列表获取成功，只显示“模型列表读取成功”，不宣称推理、Fast、自动审核全部可用。
- 当前软件没有探测上游时显示“上游未检测”，不展示“连接正常”。
- 模型和偏好来自文件时标记“已保存配置”，不声称正在运行的所有 Codex 会话已经加载。

底部仅在实际存在时显示待处理事项，例如网关停止、代理未检测到、保存冲突、未完成事务。没有问题时不填充无意义的告警卡片。

### 4.2 连接与账号：明确身份与模型来源

页面分为三个区域：

**连接方式**：两个模式选择，“PAT / API Key”“官方账号 + API”，每个选项附一句说明。切换仅修改草稿，保存前展示将改变的认证与路由内容。

**ChatGPT 官方身份**：只在混合模式显示。包含凭据读取状态、原生登录、取消登录、选择 Codex 程序。新登录完成但未保存时明确显示“登录已完成，待保存”。

**模型服务**：服务商 → 线路 → 地址 → 模型访问凭据。自动识别已有线路，不擅自重写地址。凭据默认隐藏；服务类型、认证方式及协议细节放到“高级连接选项”。

默认模型不在这里重复编辑，提供“默认模型：… · 前往模型与行为”。“获取模型”仍可作为连接验证动作，但结果名称保持准确，并复用模型页的列表缓存。

不新增多账号列表，也不把个人邮箱、套餐等尚无稳定读取入口的数据做成固定卡片。

### 4.3 模型与行为：围绕实际决策分组

| 区域 | 内容 |
| --- | --- |
| 模型与速度 | 默认模型、获取模型、推理强度、Fast 入口开关、请求服务档位 |
| 搜索与上下文 | 联网搜索、上下文容量、自动压缩阈值 |
| 执行与权限 | 审批策略、自动审核选择、沙箱相关配置 |
| 隐私与实验项 | 使用统计、实验项入口与来源说明 |

默认只展示常用项，其他设置通过“更多设置”进入全部配置。布尔配置保留“跟随默认 / 开启 / 关闭”，不能把未写入字段当成关闭。

Fast 的两个现有配置保持语义独立：允许显示 Fast 入口，与请求实际采用的档位分开呈现。对已验证的服务映射提供中文标签，同时可查看实际保存值；未知字符串保留原值，避免改版顺便改写配置。自动审核选项旁说明需要模型服务支持；未验证时不显示“可用”。

每个字段只常驻一句用途说明。详细解释、字段名、单位、来源与兼容性放在展开区，避免默认页面变成技术文档。

### 4.4 网关与网络：操作优先，设置其次

顶部固定运行摘要：状态、本地地址、复制地址、启动/停止、刷新。运行状态与检查失败分开；健康请求超时只能显示“暂时无法确认”，不能断言进程已停止。

主体第一组为**上游网络**：

- 连接方式：“直接连接”或“使用本机 HTTP 代理”。
- 当前检测到的代理地址与来源（Windows 固定代理 / 环境变量）。
- 修改后显示“待保存”；同一位置同时标明当前已保存方式，避免把草稿误当成已生效。
- 找不到代理时就地给出“未检测到固定 HTTP 代理”，保留设置以便用户启动代理软件后再次检测；不自动切回直连。
- PAC 与带密码代理地址的限制放在帮助展开区。

主体第二组为**运行详情**，默认折叠：本次进程请求计数、携带加速参数的请求数、审核模型请求数、最近检查时间。计数随进程重启归零，不画没有历史数据来源的趋势图。

“模型服务地址”从连接页复用，只读展示；提供“修改模型服务”跳转。网关页不再重复出现凭据或账号表单。

### 4.5 模板与备份：配置复用与恢复

两个页签分别使用现有功能，避免混成同一种“保存”：

- **配置模板**：模板列表 → 详情与字段差异 → 选择项 → 加入配置草稿。保留新增、复制、编辑、删除、恢复内置模板和保存当前设置为模板。
- **备份恢复**：显示当前可恢复的最近备份及“恢复上次配置”。当前引擎只向界面提供最近备份入口，第一版不画任意历史版本选择器。发现未完成事务时优先显示“恢复未完成的保存”。

模板编辑自己的“保存模板”按钮放在模板编辑区。它不等于写入 Codex 配置；加入草稿后才出现全局配置草稿栏。恢复操作继续经过差异说明和现有确认流程。

### 4.6 全部配置与应用设置

**全部配置**保留现有字段表、分页、分类搜索、已修改和未收录配置。以“字段中文名 / 文件值或默认 / 草稿值”解释状态。高级用户可查看字段路径和脱敏文件差异。第一版不新增原始 TOML 的直接编辑器。

**应用设置与帮助**承载软件自身的行为说明：关闭收起到托盘、最小化保留任务栏、双击恢复、退出停止网关、版本与文档。当前关闭策略按用户已确定的规则固定展示；不画尚未支持的开机自启、自动更新或行为切换开关。

## 5. 统一操作规则

| 操作 | 是否进入配置草稿 | 生效与反馈 |
| --- | --- | --- |
| 修改线路、模型、代理、行为字段 | 是 | 保存后按各配置的实际加载机制生效 |
| 完成官方登录 | 是 | 显示凭据已暂存，保存后写入目标目录 |
| 应用模板 | 是 | 合并所选字段，保留冲突处理与撤销本次应用 |
| 启动/停止网关、复制地址、刷新状态 | 否 | 立即执行，按钮忙碌态与结果就在运行区显示 |
| 保存模板 | 否 | 写入模板库，反馈“模板已保存” |
| 收起窗口 | 否 | 保留草稿和后台服务 |
| 退出程序 | 否 | 有草稿先处理；停止所有本程序管理的网关后退出；失败保留窗口和重试入口 |

**统一草稿栏**：无草稿时隐藏；有修改时出现“未保存 N 项 · 涉及连接/模型/网络”等摘要，提供“查看更改”“放弃修改”“保存配置”。配置修改继续统一提交，避免每页各自保存造成部分认证更新。

**差异抽屉**：默认字段差异，按页面归组；敏感值隐藏。完整 TOML、认证和环境变量预览作为次级页签。一个字段只计一次变化。

**保存反馈**：列出保存成功、网关是否已应用以及是否需要重新打开 Codex。代理这类网关可读取的新设置，不统一提示“必须重启 Codex”；模型/客户端偏好也不能只显示“已生效”。失败保留草稿并说明回滚状态。

**目录切换**：有草稿先保存/放弃/取消。配置目录改变后清空旧目录的探测结果，异步回调必须匹配目录和连接版本。此前启动的网关可能仍由程序管理：顶部提示“另有后台网关运行”，退出时统一停止，避免只看当前目录而遗忘旧服务。

## 6. 视觉与布局

- 保留灰白/深灰基底、蓝色强调色与已有品牌标识；强调色用于当前导航和主要动作，错误使用文字加图标，不能只靠颜色。
- 原生标题栏保留最小化、最大化和关闭，标题栏关闭行为不另造第三种定义。
- 左导航约 190–208 DIP；主内容默认宽度 760–960 DIP。概览可双列，表单维持单列，避免整页大卡片和嵌套卡片。
- 正文 14 DIP，页标题约 24 DIP；字段间距 16 DIP，区域间距 24 DIP。长地址可选择、可复制，窄窗口换行而非撑破布局。
- 960×640 下不发生横向滚动；运行主操作位于网关页首屏；代理与详情可纵向滚动。125%/150% 缩放下导航、草稿栏和弹层不遮挡。
- 正常状态使用克制的文本与小标识；只突出需要处理的问题。请求计数不做首页 KPI 大数字。
- 键盘保留 Ctrl+S、Ctrl+F、Esc；状态更新使用无障碍通知，定时刷新不抢焦点。

## 7. 实现建议与顺序

继续使用 WPF，不因改版引入 WebView 或新的前端运行时。先从 MainWindow 分离页面与共享状态，再调整视觉，避免增加更多全局事件处理。

建议共享状态边界：

- `ConfigDraft`：文件快照、字段草稿、未保存数量、差异、提交/回滚。
- `ConnectionState`：当前已保存连接、登录暂存状态、获取模型结果。
- `GatewayRuntimeState`：当前目录网关及本程序管理的其他网关、运行状态、计数、代理检测结果。
- `ShellState`：导航、目录、弹层、托盘、退出流程。

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| 一：结构调整 | 新导航、概览、页面拆分、统一草稿栏 | 原有配置能读取；导航不会改文件；保存/恢复/模板行为完整 |
| 二：流程整理 | 连接分区、模型归组、网关代理布局、状态词修正 | 草稿与运行值不混淆；健康超时不误报停止；凭据无泄露 |
| 三：桌面收尾 | 托盘反馈、目录切换提示、窄窗/深色/键盘与说明文案 | 退出释放网关；关闭保留草稿；跨目录异步结果不串台 |

不在第一阶段同时重写配置引擎、代理转发和登录协议。现有加密、备份、外部修改检查和失败回滚继续复用。

## 8. 方案验收场景

1. 新用户能找到设置连接入口，不被高级字段表迎面覆盖。
2. 只改普通配置无需填写凭据，保持已有官方认证。
3. 混合模式能看清“官方身份”和“模型服务”的不同作用。
4. 更改代理后能同时看懂已保存值和待保存值；停止网关不触发配置保存。
5. 关闭、恢复、最小化、退出与未保存修改组合操作符合既定语义。
6. 模板库保存不被误认为 Codex 配置已写入；草稿计数跨页一致。
7. 存在外部修改、登录取消、代理缺失、网关超时和旧网关替换时，反馈提供正确下一步。
8. 配置文件中的未知字段、注释、BOM、换行和未设定偏好仍保留。

配套交互草图使用示例状态，仅用于讨论页面布局；其中保存、启停和切换不会操作真实配置或网关。
