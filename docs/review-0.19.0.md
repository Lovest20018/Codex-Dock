# Windows 0.19.0 审查与发布验证

0.19.0 将已验收的 WinUI 界面作为正式安装入口，保留原安装 AppId、目录和 `CodexDock.exe`。WPF 源码与共享服务继续保留，正式 Windows 附件由 WinUI 自包含发布生成。

## 交付内容

本版汇总 0.18.0 之后的共享应用层迁移、任务导航、增强与旧聊天接续、HTTP 响应头等待、模型能力保留、实验功能观察、手机协议和连接恢复、审查修复以及新图标。不是将旧 WPF 二进制改名为新版。

正式发布使用干净提交；安装器、便携包与源码包的提交、版本、摘要和实际测试报告绑定。发布脚本要求 WinUI 报告和 manifest 声明一致，不接受 WPF 结果替代；Windows 和安卓独立标签、独立附件，发布后 Windows 保持仓库 latest。

WinUI 发布明确包含同次编译的 XBF 与 PRI 页面资源，并直接生成 `CodexDock.exe`。包内包含 .NET / ASP.NET Core、Windows App SDK 与手机服务运行时；配置、认证、日志、聊天和签名材料均排除。

## 已有验证

发布准备前，最新修复的完整 Core/应用层 364 项、WinUI 425 项、WPF 309 项、手机后端 74 项通过。当前生产安卓 Java 与资源在独立 QA 包名下通过 Android 14 模拟器 72 项完整检查和 22 项活动任务追加专项；未用该临时证书替换正式签名。模型目录同时通过本机独立内核只读 `model/list` 验证。

本地覆盖测试安装器曾在隔离目录验证 1200 个安装文件、安装后 425 项窗口检查、包内运行库加载、同目录旧手机后台停止、其他安装目录后台保留、手机设置保持，以及卸载后用户哨兵文件保留。该本地测试版保持版本基线 0.18.0；不能将其安装器摘要冒充本次 0.19.0 正式文件。

正式包在新版本提交上重新构建并运行相应检查，最终结果以附件 `installer-verification-0.19.0.json`、包内 `verification/ui-report.json` 和 CI 任务日志为准。报告包括安装器与应用 SHA-256、实际窗口计数以及升级/卸载范围。源码隐私扫描、上游清单、发布工具测试与校验清单均为发布必经步骤。

## 状态与数据保护

配置保存、文件恢复、独立草稿和后台状态核验继续使用共享服务。运行管道变化和同账号刷新只在可证明的边界内保留；真实配置、账号或模型目录变更拒绝覆盖。未知发送不重放，正在执行任务或审批不被自动接管。

安装前通过旧版“停止网关并退出”；安装器只对同安装路径且认证健康相符的手机后台发停止请求。其他安装和配置目录保留；停止无法确认时不继续覆盖。卸载不会删除安装器未写入的用户文件。

## 未覆盖环境

已完成的本机环境为 Windows 11 双屏 100%，其他物理 DPI、Windows 10、真实登录后的开机启动和实体手机公网链路仍需对应设备验收。模拟器网络和聊天使用本机替身及隔离 IPC，不宣称发送过真实模型任务。安卓正式证书与覆盖安装由本次独立 Android 发布验证，不包含在 Windows 安装报告中。
