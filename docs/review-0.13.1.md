# 0.13.1 局域网反向代理修复

## 问题与改动

0.13.0 公共手机端口固定绑定回环地址。当 TLS 代理在群晖等其他机器时，即使域名和端口正确，也无法连接 Windows 后台。实际排查中，带配置域名 Host 的回环首页和认证探测返回 200，公网首页、脚本和认证均返回群晖 502；电脑局域网地址的同端口无法连接。直接打开 localhost 的 Host 会被拒绝，不能用于登录。

新增可选的单个 RFC1918 IPv4 代理地址。留空时保持回环；填写时公共端口绑定 `0.0.0.0`，HTTP 路由在读取登录状态和静态资源之前核对真实 socket 来源，只接受此代理或 `127.0.0.1`，不能通过伪造 X-Forwarded-For 加入白名单。配置的代理可转发真实客户端 IP 供登录限速和设备显示；旧设备记录中的访问策略不能扩大传输信任范围。公网 Host/Origin/CSRF 校验继续生效，私有管理端口始终仅回环。

本机 HTTP 根页只显示诊断信息和配置的 HTTPS 入口，不签发 Cookie，不开放 HTTP 登录/API。HTTPS 检测分别显示 502 与 403 的可操作说明，不回显上游错误页或凭据。后台协议更新为 2，管理器兼容读取原 protocol 1 的 DPAPI 设置；旧 worker 在显式启动/保存时会重启升级。更改代理不改变密码、实例或设备授权。

## 验证边界

新增回归覆盖代理 IP 校验、真实来源限制、伪造转发头拒绝、真实客户端地址、原 Host/Origin 保护、本机诊断页、旧 DPAPI 设置兼容和接入方式切换。冻结 EXE 用隔离回环地址验证 wildcard 绑定与恢复回环、原有安卓登录跨重启和撤销。完整 UI 验证新增可改端口、代理草稿和错误输入不能启动服务。

本地结果：38 项手机 Python 测试、80 项核心回归、101 项完整桌面 UI 检查通过。实际冻结 EXE 还验证了另一回环来源伪造代理头时返回 403，以及公开端口监听全部 IPv4 时，管理端口依然只接受 `127.0.0.1`。构建无警告和错误，源码隐私扫描通过。发布脚本另对实际发布 EXE 和隔离安装后的 EXE 重复 UI 检查并比较文件与散列，结果记录在发布 manifest、UI 报告和本地安装验证 JSON。

上述检查均使用虚构用户和隔离文件，不向真实 Codex 聊天发送、停止或审批。实际群晖的目标配置、跨网段路由、Windows 防火墙以及安卓真机仍须在实际部署中验收；填写代理 IP 不代表这些链路已经打通。不会自动添加防火墙规则，也不修改代理设备。
