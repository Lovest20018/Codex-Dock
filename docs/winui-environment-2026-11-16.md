# Windows 本机显示与目录验收

本轮在当前 Windows 11 主机继续验证连接的显示器和原生目录入口。两台显示器均为 1920×1080、96 DPI，XAML 缩放为 1；未修改系统显示设置或用户正在运行的 Dock、Codex 和手机服务。

## 已验证范围

隔离预览按实际显示区域移动窗口，读取该窗口的原生 DPI、XAML 光栅比例和当前显示器工作区，核对初始位置及最小跟踪尺寸。每台显示器分别切换连接、模型、Profile、Windows 设置及帮助页面，检查按钮区域、未保存草稿和磁盘文件；所有操作不触发保存、备份或真实 Codex 重启。

测试目录名称包含空格和 `&`。实际“打开文件夹”入口调用既有原生运行时，通过独立进程参数传递完整路径。computer-use 在 Windows 文件资源管理器中核对路径面包屑与两份虚构文件，未打开文件内容，验收后关闭此次新窗口。

路径和认证摘要的复制改为明确设置 `ClipboardContentOptions.IsAllowedInHistory=false`、`IsRoamable=false`，避免这些副本进入 Windows 剪贴板历史或跨设备同步。正常复制仅在用户点击时执行，内容仍为当前路径或已经脱敏的只读快照。

## 剪贴板验收事故与处理

早期原生复制的回读通过，但测试试图保留再回写原 OLE 数据对象。首次恢复遇到 `CLIPBRD_E_CANT_OPEN`，未完成原内容恢复；加入重试后又触发 `ole32.dll` 的栈溢出。该恢复方式已完全移除，不进入最终交付。旧二进制和失败记录保留在 `native-v2`、`native-restoration` 对应构建目录，均不计为通过。

首轮可能将用户剪贴板留为虚构认证摘要或空内容，已在发生时向用户说明需要重新复制原内容。原私有内容没有写入工件、日志或报告；不能声称事故前内容已恢复。

最终专项不再保存或回写任意剪贴板对象。只有当前剪贴板恰好是本测试已知的纯虚构文本时，才允许短暂替换并用同一已知文本恢复；当前内容不同、格式不符或读取不可用时跳过。后续用户复制优先，不覆盖新内容。最终本轮跳过了实际复制，故不将整套原生剪贴板恢复验收标为通过。普通完整回归仍使用隔离复制替身，覆盖按钮权限和脱敏范围。

## 验证与交付

最终 WinUI 完整回归 340 项通过，本机专项 9 项通过；后者报告包含两台真实显示器的坐标、工作区、DPI 和跳过复制的原因。两份本轮报告均绑定交付 WinUI DLL。Core/Application/WPF 本轮保持不变，以 SHA-256 匹配后引用上一轮完整核心 345/345 和 WPF 309 项结果，不表述为本轮重跑。

完整验证由 `build-winui-preview.ps1 -Verify` 从交付目录启动，调用方即使保留专项筛选也必须执行完整流程。本机报告位于 `native-verified/report.json` 与 `native-verified/environment.json`，Explorer 路径核对另记为 `explorer-final-observation.json`。汇总与校验和为 `verification-summary.json`、`preview-final/SHA256SUMS.txt`；复制完整保留验收明确记录为未通过，不能用根级已完成范围的 `PASS` 取代该结果。

本轮工件位于 `artifacts/winui-environment-2026-11-16`。最终入口为 `preview-final/app/CodexDock.WinUI.exe`，需保留整个 `app` 目录。用户当前打开的上一轮预览不被替换或结束；使用新版前从托盘明确退出旧预览。

不同物理 DPI 及混合缩放的显示器移动、Windows 10、实际登录启动、真实安装器、真实 Codex 和手机公网设备仍未完成验收。当前双屏均为 100%，不能用本轮结果代替 125%/150% 或混合 DPI 验收；WPF 继续作为默认交付入口，安卓视觉仍后续处理。
