# 2026-11-12 进度与 Dock 收敛方案

2026-11-13 后续：用户已授权补查冲突逻辑、重新打包、合并主线并发布 Windows 0.18.0。当前操作以版本说明和发布验证报告为准；下文暂停发布的表述属于前一阶段记录。

今日结论：当前本机的纯 API 路线已经跑通，用户最终反馈各项测试正常。接下来优先把已验证的能力纳入 Dock 的正常保存、应用和恢复流程，再统一界面与状态。提交、推送和发布继续暂停。

本文是基于当前源码与本次实测制定的修改方案；下文标为“待实现”的内容尚未写入 Dock 程序。

后续已按用户指示实施核心目录管理、专用审核、常用模型页重组、统一应用入口、受限会话参数读取及网关分类统计。操作说明见[模型与专用审核](model-behavior-managed-catalog.md)，具体回归与交付边界见[0.18.0 审查](review-0.18.0.md)。下文保留提出方案时的状态，不能作为当前未实现清单。服务后台的自动接入、目录历史自动清理与独立审核服务商不属于本轮实现。

## 二、Dock 目前最需要补齐的地方

1. **本机审核配置已经成功，产品入口还没有。** `review-policy-tool` 位于忽略的测试目录；Dock 没有固定审核模型、生成目录和维护映射的完整流程。仅将 approvals_reviewer 设为 auto_review，不能表达用户要求的专用模型。
2. **目录是静态快照。** 现在 8 个模型中，7 个非审核模型设置了 auto_review_model_override。以后换目录、换服务或加入新模型，都需要维护这层映射；当前“获取模型”只填充连接页的下拉列表，“重新读取本地模型目录”也只刷新字段能力，二者均不是维护受管目录。
3. **同一功能的操作分散。** 速度选择在“模型与行为”，速度兼容在“应用设置与帮助”，重新应用入口又在保存成功页。用户很难判断下一步该保存、重启还是重新选聊天档位。
4. **状态来源没有统一。** 概览主要展示文件值和进程数；兼容卡片有自己的状态。文件已保存、桌面已重开、当前聊天采用什么值，还没有形成一个清楚的视图。
5. **常用模型页仍是通用字段编辑器。** 推理强度、服务速度、审批方式容易被理解成一组档位；Ultra 与 Ultra Fast 的名字尤其需要分开展示。

## 三、建议的页面调整

保留现有导航与视觉风格，首轮只调整页面职责和常用控件。

| 页面 | 调整后的内容 |
| --- | --- |
| 概览 | 当前连接、所管理的 Codex、待应用状态、最近会话参数及来源；提供“打开／重新应用配置”和“查看诊断” |
| 连接与账号 | API Key 直连优先；官方账号加独立模型入口保留；连接方式、服务类型和服务商分别说明 |
| 模型与行为 | 模型、推理强度、速度、自动审核四块；原始字段留在“全部配置” |
| 网关管理 | 保留两个网关的独立启停和自启动；直连时模型网关显示“当前连接无需启动”，不显示成故障 |
| 手机连接 | 保留 HTTPS、配对、接入管理；持续启停仍在网关管理 |
| 模板与备份 | 保留模板草稿；恢复时说明是否同时恢复模型目录及审核策略 |
| 全部配置 | 保留完整字段、未收录字段和配置来源，作为高级入口 |
| 应用设置与帮助 | 保留主题、窗口、托盘、更新和 Windows 启动；速度兼容主入口移到模型页，原位置保留跳转 |

“模型与行为”建议按如下顺序展示：

| 区块 | 常用控件与说明 |
| --- | --- |
| 模型 | 默认主模型；可用能力来源、目录更新时间；读取／更新目录 |
| 推理强度 | 低、中、高、极高、Max、Ultra，按模型声明生成；详情给出 API 标识。Ultra 的协作模式与速度分开说明 |
| 速度 | 普通、Fast、Ultra Fast，按模型真实目录生成；显示是否需要桌面兼容，以及当前兼容状态 |
| 自动审核 | 选择“帮我批准”时，显示固定审核模型 codex-auto-review；失败时停止执行并给出原因，保留本次用户指定的行为 |

审核模型使用当前模型服务和对应凭据。首轮不增加另一套审核服务商、账号池或凭据表单。普通代码审查 `/review` 的 review_model 不用于自动审批。

## 四、优先实现：审核模型与受管目录

### 4.1 把已验证机制变成正常功能

建议新增 `ReviewModelPolicy` 和 `ManagedModelCatalogStore`，由核心层负责计划生成，界面负责展示差异和用户操作。

- 用户选择固定审核模型后，按当前目录中的原生元数据生成受管目录，只增加或更新非审核模型的 `auto_review_model_override`。
- 保留模型 ID、说明、工具能力、上下文、推理档位、速度档位及未知字段，不额外补造 Fast／Ultrafast 或模型条目。
- 验证当前主模型和审核模型有可核对的目录条目；目录外模型不声称受固定审核策略保护，Dock 不保存会静默丢失该映射的组合。
- 保留已有沙箱、权限 profile 和细粒度审批规则；切换审批人不把现有 granular 策略重置成 on-request。受组织要求限制的设置按实际约束呈现。
- 用同一份保存计划写入目录、索引和 config.toml，延续现有冲突检测、差异确认、原子替换及加密备份。不能只备份一条指向日后可能被删除文件的路径。
- 恢复备份时同时恢复对应目录依赖；历史受管版本在仍被配置或备份引用时保留。
- 读取或刷新界面不写配置、不发起付费模型调用；需要同步目录时进入原有保存流程。

审核模型错误必须原样形成明确失败，保持原生阻止执行的行为，不改成主模型代审或直接放行。本机已验证的 404 路径作为产品回归依据。

### 4.2 目录更新不再丢失设置

建议分开维护“来源目录”与“Dock 策略”，再生成客户端使用的原生目录：

```text
已核对来源的模型目录 + 固定审核模型策略
                     ↓
              生成待应用目录与差异
                     ↓
               确认保存并保留旧版
                     ↓
                 重新打开 Codex
```

记录来源类型、内容摘要、更新时间、适用客户端版本及连接标识。来源不一致或无法核对时显示待确认，不能把其他服务的模型 ID 和能力直接拼成“已支持”。只有模型 ID 的远端列表不能证明速度或审核能力。

发现外部目录有变化时先标记“有更新待同步”。用户点击更新，重新在新目录上应用固定审核策略，预览增删和能力变化，再保存。首次接管用户自己的 model_catalog_json 时保留原文件；未登记的外部文件不会因为文件名像 Dock 文件就被当作自有文件覆盖。

本机今天生成的目录需在首次纳管时显示为“检测到已有专用审核配置”，通过索引和内容核对导入；不再要求手动运行测试目录里的工具。

## 五、统一状态和应用流程

使用共用状态模型驱动概览、模型页和保存成功页。至少分别保留：

| 状态 | 可以依据什么显示 |
| --- | --- |
| 已保存／有草稿 | 配置内容及受管文件校验 |
| 待重新打开 | 当前保存代次、已管理进程及上次启动记录 |
| 已重新打开 | 经确认的桌面路径、包身份和新进程；此状态本身不等同实际会话已采用 |
| 当前会话已观察 | 明确对应当前目录与会话的本机元数据，带时间和来源 |
| 服务端已确认 | 真实中转记录或用户明确反馈，并标明来源；普通直连没有后台数据时显示“未确认” |

不同事实可以并列，不用一个“正常”覆盖所有阶段。读取不到信息显示未确认，不能把未观察到的请求数写成 0 或成功。

默认流程：

1. 连接页保存模型服务；API 直连无需启动模型网关。
2. 模型页选择主模型、推理、速度与审核方式，查看目录及兼容状态。
3. 点击“查看并应用”，一次列出配置和目录的变化并确认保存。
4. 需要重启时提供统一的“重新打开 Codex 并应用”；沿用正常退出、未保存内容保护、目标路径和包身份核对。
5. 新进程启动后观察新的会话记录，展示本机实际采用的模型和 service_tier。

现有速度兼容开关不再要求用户在多个页面间猜测顺序。开关仍按配置目录管理；读取、启用偏好与已经建立兼容会话分别显示。由 Dock 显式启动／重启时统一准备并应用所需兼容，不让用户重复操作两个入口。无法安全附加到当前进程时给出可执行的重新应用步骤。

正常退出未完成时，说明仍存活的目标进程和下一步操作。不能用结束所有 ChatGPT.exe／codex.exe 的方式代替既有退出保护。托盘与退出说明同时区分：关闭窗口后 Dock 仍运行；退出 Dock 会停止其速度兼容会话；已独立运行的网关遵循各自退出规则。

## 六、诊断只展示能证明的事实

首轮复用已有文件与受限元数据读取，不为纯 API 额外架设抓包网关。

- 固定模型、推理强度和速度分别展示。解析最新可信 configuration_update 时同时保留顶层 effort，说明二者来源，避免再次把缓存基线当成当前推理选择。
- 本次已经验证 `thread_settings_applied.thread_settings.service_tier` 可读取原生会话选中的速度档位；它证明客户端选择，不能单独证明中转实际执行和费用。
- 只读取选定目录和明确关联会话的白名单元数据，不采集完整提示词、命令正文、工具参数或凭据。无法关联到当前进程／目录时不自动沿用其他聊天的结果。
- 自动审核展示配置目标、观察到的审核模型、状态和时间。没有观察到真实模型时保留未确认，不用配置目标冒充实际调用模型。
- 混合模型网关的计数需区分 Fast、Ultrafast、审核请求，结合 guardian 标识分类。纯 API 没经过该网关时显示“直连，本机网关未采集”，不把网关计数当作直连统计。
- 检查本地、检查进程、检查已保留的会话记录均不自动运行付费模型测试；确需真实调用时使用明确的测试入口。

## 八、产品化后的验收重点

- API 直连保存、重启、专用审核成功；专用模型不可用时命令阻止，没有主模型代审。
- 更新目录、加入模型、更换主模型后，审核映射保持；未知条目给出明确状态。
- 外部修改冲突、保存中断与回滚、恢复旧目录、重新打开 Dock 都保留用户文件与当前认证。
- 新聊天和会话中切换推理档位时，显示正确的当前选择；普通、Fast、Ultrafast 不混淆。
- 速度兼容关闭、断线、版本不匹配、切换目录、草稿未保存和残留进程时，显示正确状态并延续原有保护。
- 960×640、常用缩放、浅深主题和滚动布局可用；没有新增长篇技术说明挤占常用操作。
- 正式包须在产品化完成后重新验证，不能将今天的本机目录覆盖工具视为安装包已具备的功能。
