# Windows 预览审查修复

本轮修复新版 WinUI 审查中确认的两处状态同步问题。主配置保存、恢复确认、加密备份和共享服务接口继续执行原流程。

## 手机服务与配对状态

手机服务启停原先只更新网关概览，配对页面使用的独立状态仍保留旧结果，导致启动成功后继续提示启动、停止后继续显示可配对。现在手机网关命令完成后，在操作保护仍生效时等待较早的手机状态读取结束，再明确读取当前后台状态。停止或重启会继续清除旧二维码；重启后的 HTTPS 检测结果以新进程为准。

新的读取开始前先使旧运行状态失效；读取失败时不沿用旧的运行或停止结论，配对动作不可用，并展示读取错误。手机设置和模型设置草稿不会被状态刷新提交或覆盖。后台状态读取不进行公网检测或生成配对码。

## 配置恢复与来源比较

配置来源读取后，恢复备份原先只清除文件预览，仍保留恢复前的来源行。现在恢复成功后清除来源结果、分页和显示行，提示重新读取。返回来源页不会自动启动执行端；再次明确读取后，比较恢复后的已保存文件。取消恢复继续保留原文件和仍有效的来源快照。

## 回归范围

新增 11 项真实 WinUI 窗口专项，使用同一虚构后台状态连接两个既有手机/网关替身，并覆盖较早读取晚返回、读取失败和两个独立草稿；来源读取通过本机替身验证保存、取消恢复、确认恢复及再次读取。专项加入默认完整窗口回归，筛选入口为 `review-fixes`。

专项先在旧实现上复现停止后状态未同步的失败，再在修复后 11 项通过。最终修复版完整 WinUI **405 项通过**（原有 394 项加本轮 11 项），报告位于 `artifacts/winui-review-fixes-2026-11-17/ui-full/report.json`，对应 WinUI SHA-256 `EEC51D81113FC7DE2F74D2FB5B555C8A2C944539EAA8FD91362B2F1776C5BFE9`。完整回归继续包含隔离模型和手机后台的实际启停，没有连接公网模型。

Core 与 Application 文件和先前已验收版本逐字节一致，引用既有核心 345 项、WPF 309 项结果，本轮未重跑这两套检查。构建零警告零错误，源码与交付隐私扫描、差异空白检查通过。原来的物理显示、真实空白 Codex 和验证安装器结果属于前一阶段，本轮不将其表述为对新 WinUI 文件重新执行的验收。

本轮不进行真实 Codex 重启、用户剪贴板、用户手机服务或启动注册操作。Windows 10、其他物理 DPI 和安卓实机仍按原安排等待环境，不能用本轮隔离回归代替。本轮继续交付独立预览，WPF 保持默认入口；工作区尚未提交，版本比较基线保持 0.18.0。
