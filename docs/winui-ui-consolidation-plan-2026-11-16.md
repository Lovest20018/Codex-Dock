# 新版 Windows UI 与功能整合方案

日期：2026-11-16。2026-11-17 已按本方案实施，当前功能归属与验收结果见 [整合实施记录](winui-consolidation-2026-11-17.md)。下文保留设计时的判断与验收目标。

## 判断与依据

当前新版已经具备较完整的功能，但入口仍沿着功能迁移批次排列，缺少任务层级。零散主要发生在导航、操作路径和状态表达上，不能靠统一圆角或减少几个按钮解决。

本次对照当前 `src/CodexConfig.WinUI/MainWindow.xaml`、导航与保存可见性逻辑、功能实现说明，以及环境验收、文件预览、工作台、Profile 的已有真实测试截图。截图采用隔离测试数据，部分来自之前阶段；当前功能与入口数量以源码为准。本次没有操作正在运行的用户程序，也没有做用户可用性测试。以下是设计评审判断，路径与效率目标均为待验证目标。

| 观察 | 对使用者的影响 | 优先级 |
| --- | --- | --- |
| 13 个主菜单加 4 个底部菜单，共 17 个同级入口 | 高频设置、低频检查和软件管理权重相同，需要先理解内部功能分类 | 高 |
| 默认模型在“连接配置”和“模型与行为”均可编辑，模型发现入口只在连接页 | 同一项操作分散，用户需要判断两处是否一致 | 高 |
| 手机页配置、检测、配对，另跳网关页管理启停与自动启动 | 完成一次手机接入需要跨两个功能域 | 高 |
| 文件预览、配置来源、聊天参数并排独立 | 用户难以理解磁盘值、解析后的来源、聊天实际记录分别回答什么问题 | 高 |
| 多页重复展示完整目录卡、文件动作和说明 | 首屏留给主要表单的空间不足；连接页截图中 API Key 已接近底部 | 中高 |
| 主配置有草稿时，文件预览、帮助、手机等页面也可能出现主配置保存栏 | 页面内容与底部动作的作用范围不一致，即使实现正确也容易误解 | 高 |
| 工作台以信息卡、跳转和常驻说明为主 | 能看到功能，但“当前要做什么”不突出 | 中高 |
| Profile、方案库、主配置、手机各有不同保存方式；增强与启动开关立即保存 | 独立范围合理，但缺少一致的视觉提示，用户需反复阅读说明 | 高 |

不建议删除高级功能，也不建议把所有功能塞进一个长表单。采用“五个主要任务入口 + 两个底部入口”，在各任务内用有限的二级导航承载现有能力。

## 推荐导航与功能归属

| 一级入口 | 二级页面或分区 | 承接的现有能力 |
| --- | --- | --- |
| 工作台 | 当前状态、待处理事项、常用操作 | 当前连接与模型摘要、Codex 实例、保存/应用状态、增强和手机状态 |
| Codex 配置 | 连接、模型与行为、高级配置、方案与 Profile | 连接配置、模型与行为、全部配置、方案库、独立 Profile |
| 运行与增强 | Codex 与增强、模型网关 | 实例与应用、三个增强开关、增强快捷方式、模型网关启停和自动启动、压缩/耗时统计 |
| 手机访问 | 连接与配对、授权设备、服务设置 | 手机配置、检测、二维码、设备授权、本机接入管理、手机网关启停和自动启动 |
| 诊断与恢复 | 已保存文件、配置来源、聊天参数、备份恢复 | 文件预览、来源读取、选定聊天元数据、普通及中断恢复 |
| 设置（底部） | 启动与窗口、软件更新、关于 | Windows 设置、软件更新、关于预览版 |
| 帮助（底部） | 按任务组织的说明 | 现有使用说明与页面跳转 |

原有 17 个入口全部可追溯，主导航不再随功能增加继续变长。窄窗口保持导航折叠，二级导航可收为选择器，不靠挤压字体容纳标签。

“方案与 Profile”共享一个资源管理位置，但用两个明确的选择项区分：

- 配置方案：可复用的设置片段；“加入主配置草稿”和“保存方案库”是不同操作。
- Profile：独立配置文件；编辑、保存和恢复只作用于所选文件，不暗示自动切换主配置或当前聊天。

不增加第三层常驻侧栏。复杂内容使用详情区或明确的局部编辑模式。

## 页面布局

```text
┌─────────────┬──────────────────────────────────────────┐
│ Codex Dock  │ 配置目录：…\my-codex  ▾    待处理修改 2   │
│             ├──────────────────────────────────────────┤
│ 工作台      │ Codex 配置                               │
│ Codex 配置  │ 连接  模型与行为  高级配置  方案与 Profile │
│ 运行与增强  │                                          │
│ 手机访问    │ 当前任务的字段 / 内容                    │
│ 诊断与恢复  │ 常用项展开，高级项按需展开                │
│             │ 字段旁说明；异常在对应区域显示            │
│             │                                          │
│ 设置        ├──────────────────────────────────────────┤
│ 帮助        │ 主配置有修改   [查看差异并保存] [放弃修改] │
└─────────────┴──────────────────────────────────────────┘
```

此图仅说明布局与作用范围，不表示已实现，也不代表当前有两份真实草稿。

全局目录区压缩为一行，完整路径可展开查看和复制。切换目录、打开文件夹、复制路径归入目录菜单；“查看文件”跳到诊断对应页。首次设置、读取失败和中断恢复仍需明显提示，不能被折叠隐藏。

普通说明采用一句话加“了解详情”。API Key 直连只展示对应说明，官方混合方式才展开登录读取；非回环 HTTP 等需要明确确认的条件仍就地展示。卡片用于不同对象或不同操作范围，不为每个字段单独加卡片。

### 工作台：突出下一步

工作台首屏按“当前配置 → 运行状态 → 待处理事项”组织，最多突出一个主要动作：

| 观察到的状态 | 主要动作 | 辅助信息 |
| --- | --- | --- |
| 缺少可用连接 | 设置连接 | 现有认证来源与缺少的内容 |
| 主配置有草稿 | 查看修改 | 哪些区域有修改；可继续编辑 |
| 本窗口已保存，尚未应用 | 应用到 Codex | 点击后沿用实例选择和确认 |
| 有可重试的增强失败 | 重试增强 | 明确不会再次重启 |
| 没有待处理操作 | 按观测显示运行状态 | 编辑配置、管理增强、手机访问为次级入口 |
| 有未完成事务或无法读取配置 | 恢复或修复指引 | 编辑和应用保持受限 |

不把“文件已保存”“本次应用成功”“所有聊天已经采用”合并成一个绿色成功状态。无法验证的运行情况显示未知；来源或聊天核对提供明确跳转。配置已一致时仍可在“运行与增强”主动应用，不强迫用户制造修改。

### 配置：减少重复与来回跳转

连接页负责服务与认证；模型页负责默认模型、读取服务模型、推理与行为。连接页只显示当前模型摘要和“选择模型”跳转，默认模型只保留一个主要编辑入口。新连接保存前如缺少模型，在同一配置区域跳到模型页并聚焦，不另造一份草稿。

连接、模型与行为、高级配置继续共用当前主配置草稿、差异预览和保存服务。高级配置编辑相同字段后，模型页反映同一值。能力目录等低频动作放入模型页的高级分区，保留所有校验。

第一次接入可用“连接 → 选择模型 → 查看差异并保存 → 应用”的任务提示；已有配置不强制经过向导。

### 手机：一个区域内完成接入

未配置时突出入口、账号和密码；已配置时优先展示服务状态、配对和授权设备，修改端口等放入服务设置。保存仍按现有流程明确标为“保存并启动”，成功保存但启动失败时分别报告，提供仅重试启动。

手机网关的主控制入口搬到手机访问；模型网关归运行与增强。工作台和诊断只显示摘要及跳转。两处继续调用同一网关管理服务，避免复制状态与启停逻辑。保留托盘“停止网关并退出”等跨服务命令。

### 诊断：说明每份数据回答什么问题

四个二级页面使用一致的“对象 / 数据范围 / 读取时间 / 结果”布局：

- 已保存文件：磁盘上保存了什么？
- 配置来源：指定执行端、项目和 Profile 下，配置从哪里来？
- 聊天参数：明确选中的聊天记录了什么？
- 备份恢复：要恢复哪个对象、哪次备份，会影响什么？

它们可以相邻浏览，但不自动拼出未经验证的“最终实际生效值”。聊天不自动选择，网络检查不因导航触发。恢复操作仍先展示差异并确认。

## 统一操作语言，保留独立保存范围

| 当前范围 | 页面主要动作 | 保存后的表达 |
| --- | --- | --- |
| 主配置 | 查看差异并保存 | 已保存；根据实际结果提示是否待应用 |
| Profile | 查看差异并保存 Profile | 指定 Profile 已保存 |
| 方案库编辑 | 保存方案 | 本机方案库已更新 |
| 手机设置 | 查看设置并保存启动 | 设置保存、服务启动分别显示 |
| 增强偏好、启动项、自动启动 | 开关操作 | 标注“更改立即保存”，再分别展示实际运行状态 |
| 只读诊断、帮助、关于 | 读取、筛选等本页动作 | 不出现其他范围的保存主按钮 |

全局“待处理修改”只负责汇总和导航：主配置、某个 Profile、正在编辑的方案、手机设置各占一行。点击后进入所属编辑区；第一轮不新增“全部保存”或跨文件事务。

底部动作栏只表达当前编辑对象。进入帮助、文件预览或手机时，主配置草稿以顶部待处理提示保留，不把“保存主配置”作为当前页主按钮。没有本页编辑范围时，Ctrl+S 不跨范围保存；需要同步调整键盘说明和测试。

“保存”与“应用”保持两步，但保存成功后在原位置给出清楚的下一步入口，无需返回工作台寻找。应用仍保留实例选择、冲突复核、正常退出和独立强制确认。多个草稿退出时可在一个总览中列出，保存逐个调用原服务，失败或取消即停留，不能把它们包装成一个原子操作。

## 落地顺序

### 第一阶段：先解决入口与空间

- 建立五主入口、两底部入口和旧路由映射，原页面内容先复用。
- 将重复目录卡改为紧凑的全局目录栏，文件动作归入目录菜单。
- 将软件更新、关于归入设置；诊断四项归入一个区域。
- 按页面作用范围显示底部操作；跨页草稿采用待处理提示。

交付可运行的导航和布局预览。重点核对原有入口均可到达、导航保留草稿、无额外读取和写入。此阶段已可直接改善零散感。

### 第二阶段：打通三条常用任务

- 调整连接与模型的字段归属，模型发现就近放在模型选择处。
- 手机页接入服务启停与自动启动；模型网关归运行与增强。
- 重排工作台状态与下一步动作，保存后提供就地应用入口。
- 统一局部说明、立即保存标签、失败和重试表达。

交付“切换服务并应用”“修改模型”“手机配对”三条连续可用的流程。继续使用既有 Application/Core 服务，不新建配置格式或第二套网关控制。

### 第三阶段：收尾与验证

- 整理方案/Profile 局部管理和诊断解释，减少重复提示。
- 更新帮助、快捷键、托盘和旧页面跳转。
- 定向验证后运行相关完整回归；按实际可用设备检查布局。

暂不加入全局命令面板、全新仪表盘、跨范围一键保存或大规模动效。先验证导航、范围和常用路径确实更清楚。

## 验收标准（目标，尚未执行）

1. 一级常驻入口从 17 个收敛到 7 个；全部旧能力都有明确归属，任何功能不超过两层页面导航可达。
2. 修改默认模型在一个页面完成选择和编辑；从该配置区域完成差异确认和后续应用，不需到工作台找按钮。
3. 手机配置、服务启动、检测、配对和设备管理在手机访问内完成，不再跳独立网关页。
4. 帮助和只读诊断不展示无关保存主按钮；顶部仍可发现其他区域的未保存修改。
5. 切换二级页面保持草稿、错误输入与编辑状态；切换目录、重读、恢复和退出继续执行现有保护。
6. 1120×820 下连接页首屏可见连接方式、地址、密钥及下一步；720×540 下内容可滚动、主要动作可达、不遮挡输入。其他真实 DPI 在具备环境时单独验证。
7. 正常状态不用长篇提示解释保存范围；每个编辑区可直接辨认“改哪里、何时保存、是否需要应用”。
8. 用五个任务试用验证：更换服务、调整模型、手机配对、核对聊天参数、恢复备份。记录找入口的路径、误入页面和保存范围误解；在实测前不宣称效率提高百分比。
9. 原有身份、敏感值脱敏、一次性确认、外部冲突检查、共享操作锁、恢复和实例保护保持通过。

## 实现边界与建议

首要修改点是 `MainWindow.xaml` 的导航、上下文区和底栏，`MainWindow.xaml.cs` 的路由与状态投影，以及 `ConnectionConfigurationUi.cs` 中按页面决定底栏的逻辑。引入带有一级域、二级页、标题和操作范围的轻量路由描述，替代不断增加的页面身份条件；页面与现有服务继续复用。

UI 可以拆为按任务归属的视图，草稿仍由现有 ViewModel/服务持有；不要为移动控件同步重写业务层。原有隔离回归中关于页名、导航和按钮位置的断言随设计更新，关于事务、身份和数据保护的断言保留。

建议下一轮先实施第一阶段，并以第二阶段的三条任务作为设计校验。Windows 默认入口切换、正式打包发布、Android 视觉工作和设备验收不与本次信息架构整合捆绑。
