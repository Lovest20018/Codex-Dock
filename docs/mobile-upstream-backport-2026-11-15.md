# 手机网关 2.2.1 首批修复移植（2026-11-15）

本轮按 [上游评估](mobile-upstream-audit-2026-11-15.md) 实施 Windows 手机网关的协议兼容、连接恢复、模型目录及列表容错。已生成包含新网关的 WinUI 预览。安卓应用身份、Logo、原生三页导航、现有设备授权和固定 HTTPS 入口继续保留。

## 来源与边界

- 参考上游 [v2.2.1](https://github.com/try2love/codex-mobile-bridge/releases/tag/v2.2.1)，提交 `1004e5aeb6ee38a75ab18b4bad1720a38553aada`。
- 基础快照仍为 2.1.7 的 `0721aa7dafa6177751ba7e568e0ad0efee05655b`，之前选择移植的 2.2.0 修复全部保留。
- 本轮修改 8 个上游生产文件和 3 个测试文件；显式 overlay 从 25 项增至 **31 项**。新增来源记录使用 `backports`，保留原来的 `backport` 和 Dock 适配说明。
- 没有整体切换上游版本，没有引入其他 AI 客户端、多信道、上游共享 runtime、CLI 强制释放、项目外文件浏览或新安卓包名。

## 已完成的行为

| 行为 | 实施结果 |
| --- | --- |
| v13 同步 | 实时读取和退出前任务审计均接受经结构校验的 v13；v11 兼容保持。附加字段兼容的后续版本可继续读取，关键任务、审批或历史结构无法解释时保留历史与草稿并暂停控制。 |
| 异常快照隔离 | 只处理对应 host、thread 和 owner 的事件；未知会话或格式异常的无关事件不会断开所有聊天。patch 以复制修改路径的方式生成候选状态，拒绝后不污染上一份有效快照。 |
| IPC 恢复 | 初始化带 generation 校验，关闭后迟到的连接和初始化结果不能恢复旧状态。显式恢复在 host 操作锁下替换网关跟随连接，旧写入结果不自动重放，也不终止原桌面进程。 |
| 冷启动与重连等待 | 发现断线后清除旧成功读取的退避，保留有限的恢复窗口；活动读取、通知和维护循环采用一致的短期恢复节奏。读取总时限覆盖退出审计的连接、请求与跟随等待。 |
| 模型空结果 | 暂时空列表或刷新失败不覆盖同身份的上次成功目录，也不伪造新的成功时间。首次失败明确返回 unavailable；账号或项目配置变化后不借用旧目录。 |
| 目录删除 | 只读模型辅助进程可从仍存在的父目录启动，RPC 和缓存身份仍使用原项目 cwd，不修改会话工作目录。 |
| 手动模型草稿 | 刷新成功、失败以及迟到响应保留尚未应用的手动模型与有效强度选择。原生能力未知时可沿用默认强度；已知原生模型缺少能力信息时仍拒绝猜测强度，Fast 仍需明确验证。 |
| 模型账号边界 | 模型应用携带目录身份；账号变化返回明确的 `model_identity_changed`。旧账号响应不能重绘新账号窗口，旧窗口会关闭；身份失效后继续输入也不能绕过应用限制。 |
| 列表容错 | 构造单个 SSH／WSL 入口失败时保留本机及其他成功列表，返回对应入口错误。已有读取阶段的失败隔离继续保留。 |
| Windows 启动 | 保留 Dock 现有商店应用安装身份、执行别名和独立配置启动流程；本轮接入协议及冷启动恢复配套，没有增加第二套桌面 runtime。 |
| 界面语言 | 补齐本轮模型默认值和恢复提示的中英文映射，不翻译聊天内容、模型 ID 或用户输入。 |

## 保留的契约

`bridge/features/auth/auth.py` 未修改：登录失败来源限制与已授权设备仍相互独立，共享出口中的其他合法设备不会被错误清退。明确的设备撤销、账号／密码变更和授权失效规则保持。

Codex-only 过滤、固定入口、当前会话的 owner/provider/auth/cwd、账号范围草稿、IME 防误提交和未知写入不重放均保持。普通读取和通知不会因此启动桌面应用、恢复 CLI 写入服务或切换账号。

上游 v13 的 `attachedToThreadId` 展示与 `deferredOutputTurnId` 正文补取仍属于单独适配事项；本轮不宣称完整支持所有新增协议能力。图表、命令菜单及需要自有 APK 配套的功能继续放在后续批次，安卓视觉优化按 Windows 优先的既定顺序处理。

上游 HTTP 夹具在沙箱转发中出现过请求体与下条请求拼接的偶发 400；同一夹具在本机回环端口重复 40 次通过，最终 HTTP／浏览器共同回归也在本机环境完成。DPAPI 检查使用加载了 Windows 用户配置的隔离测试进程，没有放宽加密规则。测试夹具只按新契约补充必要字段和返回值断言，没有删除认证、原 owner 或缓存隔离断言。

本轮没有更改版本号、提交 Git、安装替换用户程序或发布 Release。
