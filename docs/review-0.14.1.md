# 0.14.1 审查与修复

审查基线为 0.14.0 / `a177549`。保留固定上游源码和五项已有覆盖，新增客户端状态轮询覆盖；覆盖哈希显式维护，原始来源清单不改。

## 已确认问题

1. **P1：已确认消息残留，可被再次提交。** 草稿版本原来包含光标位置，发送期间移动光标会阻止已确认草稿的清理。改为仅用文本、引用、模式与 Skill 判断内容版本，光标仍持续保存。发送期间身份由未知转为已核验时，原临时草稿被提升到账号存储，但确认仍使用旧空范围，造成第二条残留路径。本版记录本次发送第一次取得的账号范围与内容版本，按确认或匹配回执清理；不迁移未知发送 ID，不跨账号或聊天清理新内容。
2. **P2：Web 定时状态读取持续失败时反复弹出相同提示。** 原轮询捕获每次错误后都会调用 toast。改为同一故障期间首次提醒，后续后台读取按 15 / 30 / 60 秒退避；成功后复位。错误和手动重试保留在应用管理，旧登录或状态版本的延迟失败不再弹出。

## 验证与边界

已通过 26 项 Python 适配与真实隔离 HTTP 回归、81 项核心回归、上游全量 Node 1,315 项以及 10 项新增内容版本、二次确认和轮询退避检查。慢原生检查期间连续四次状态 HTTP 读取均及时返回，只启动一个后台检查。

新增浏览器夹具实际运行生产 JavaScript，25 个发送场景通过，包括移动光标、身份核验前后、新输入与改回原文、引用、Skill、发送模式、账号/聊天切换、未知送达，以及回执与 HTTP 确认之间再次输入。应用管理的真实界面另验证持续失败只产生一次后台提示、保留客户端列表、展示错误、手动重试绕过退避并清除错误。

原上游宽屏与窄屏浏览器 66 项在最终源码上通过。发布脚本重新冻结完整 worker，并强制对实际发布程序执行 108 项 UI 检查；安装验证使用独立目录与 VERIFYONLY，比较全部安装文件并验证卸载保留用户文件、真实注册表和环境变量。最终结果以包内 verification/ui-report.json、manifest 及包旁 installer/archive verification 文件为准。

测试使用虚构凭据和隔离 HTTP / 浏览器夹具，没有发送真实 Codex 消息或切换真实账号。

本机只读诊断发现已安装版本为 0.14.0，匿名状态接口返回 401 用时约 10 ms，本机控制健康检查 200 用时约 9 ms。没有使用真实浏览器会话读取账号或聊天内容。这个结果只能证明该时刻本机入口响应，不能证明手机到反代的完整链路正常。反复提示的界面原因已复现；公网超时的具体诱因尚未确认。

授权、本机管理白名单、升级和打包实现复查未发现本轮其他可确认的阻断项。安卓真机、实际公网、真实模型和实际 WSL / SSH 任务未验收。
