# Codex Dock 前端 UI 与操作流程优化方案

基线：0.14.1 / `caae4bf`。检查日期：2026-10-31。用户批准完整方案后，三个阶段已在 0.15.0 实施；下文保留设计依据与验收要求，实际结果见末尾。

范围为当前 Web 工作台、手机浏览器布局和本机接入管理页；Windows 原生主窗口另行评估。

## 结论

优先做“聊天主线清晰、状态有解释、管理入口归位”，沿用现有浅灰底、蓝色主操作和桌面双栏风格。第一阶段保留现有后端协议与发送保护，只调整信息层级、文案和状态呈现。

0.14.1 已修复的“发送确认后清除原稿、保护新草稿”“状态读取失败去重与退避、手动刷新”是此次方案的基础，不列为尚未修复的问题。

## 检查依据与边界

- 使用当前源码的隔离网关、独立临时目录和合成登录信息，查看 1440×1000 桌面与 390×844 手机页面；没有操作真实账号或发送真实聊天。
- 本机接入页、桌面首页、设置、应用管理、手机列表截图位于 `artifacts/ui-plan/`。手机列表未观察到页面横向溢出；这不代表手机键盘弹起、聊天长内容等情形已验收。
- 夹具故意不提供原生 Codex 与会话数据库，所以截图中的“未安装/找不到会话数据库”用于观察异常界面，不能推断用户电脑缺少安装，也不能解释此前公网超时的根因。
- 聊天输入区、发送与新建流程结合源码审查；方案中的聊天内容为示意，不是实际用户会话。

## 当前问题与优先级

| 优先级 | 已观察到的情况 | 用户成本 | 建议 |
| --- | --- | --- | --- |
| P0 | 输入区同时包含模型、提醒、Skill、权限、附件、发送方式、工作模式等控件 | 发一条普通消息前要分辨多个概念 | 主区保留输入、附件、模型、发送；权限显示当前摘要，修改入口可展开；低频功能收进“更多” |
| P0 | 已有发送错误与消息管理，但恢复入口分散 | 超时后难以判断是否应该再发一次 | 就近显示消息的投递状态和可执行动作；“结果待确认”独立于明确失败 |
| P0 | 同一个设置面板混合外观、全会话通知、网关级开关、传输与诊断；末尾概括“仅保存在当前浏览器” | 不清楚设置影响哪些设备、是否已经保存 | 按用途分组，并逐项显示作用范围、保存时机和结果 |
| P1 | 设置仍有 Claude / DeepSeek 的底部切换偏好；应用管理帮助文案涉及 macOS Claude | 与 Dock 的 Codex 定位不符 | 根据实际能力显示项目，删除当前产品无关文案；单应用不显示切换与滑动教学 |
| P1 | 首页列表报错时，右侧仍显示“从一条聊天继续”；同一缺失数据库信息同时出现在行内与 toast | 当前原因与下一步不集中 | 空态区分未接入、无聊天、加载中、读取失败、筛选无结果，提供对应动作 |
| P1 | 手机首行堆叠产品、电脑、新建和更多；第二行挤入搜索、来源、排序、归档 | 筛选项抢占聊天空间，视觉重点接近 | 搜索独占一行；来源/排序/归档收进筛选面板，显示当前筛选摘要 |
| P1 | 本机页中“已保存的接入”“API 接入”“应用与 WSL”长页堆叠，存在多个刷新入口 | 当前接入与编辑表单不易建立关系 | 先展示当前接入和作用范围，再展示已保存接入；新增/编辑使用独立表单 |
| P2 | 聊天顶部与列表顶部以不同符号打开同一个全局设置；诊断入口名字偏向 SSH | 入口含义依赖尝试 | 全局设置使用统一齿轮语义；聊天更多只放会话操作；诊断按连接类型展示 |

以上优先级是设计判断，不是用户研究或性能测量结论。

## 页面组织

桌面保留左侧聊天列表、右侧工作区。左侧包含“新建聊天、搜索、最近/项目、会话列表”，底部固定“连接与接入、设置”。当前电脑作为明确的设备摘要，不再和品牌、客户端选择挤在一起。

右侧顶部显示聊天名称、项目/执行环境、任务状态和会话更多操作。文件、终端等工作区能力按需展开；窄屏用独立页面或全屏面板承载，不把多栏压缩成小按钮。

手机分为聊天列表与聊天详情。详情顶部为返回、标题、状态和更多，底部为输入区。浏览器返回、收起键盘、关闭面板依次处理；返回列表保留草稿、滚动位置和搜索条件。原生宿主返回键继续走既有宿主适配。

### 聊天输入区

默认看到输入框、附件、当前模型、当前权限摘要与发送按钮。Skill、提醒、计划/目标等放在“更多”内；选中后以可移除标签留在输入区，不能因折叠而隐藏已启用状态。

“发送方式”和“工作模式”保留为两个不同概念：

- 发送方式决定何时投递。任务空闲时突出“发送”；运行时提供“完成后发送”“补充当前任务”，只展示当前环境支持的选项。用户选中的方式必须明确显示，不能悄悄把普通发送改成插入或排队。
- 工作模式决定如何执行。普通为默认，计划/目标按能力展示。目标的暂停、关闭与停止当前回复仍需分别表达，避免用户误以为暂停目标就已停止任务。
- 沿用当前 Enter 换行、Ctrl/Cmd+Enter 发送规则，增加可见提示；移动端回车保持换行。提交必须避开中文输入法合成过程，并验证重复快捷键不会重复提交。
- 当前权限配置始终可见；权限升级、待确认请求不能被“更多”或“专注阅读”折叠掉。

### 发送状态与草稿规则

| 状态 | 呈现 | 可操作行为 |
| --- | --- | --- |
| 草稿 | 输入框显示当前内容 | 编辑、添加附件、选择模式 |
| 正在发送 | 提交记录显示“正在发送”；防止同一提交重复触发 | 可继续编辑下一条草稿；不能把相同提交生成新请求 |
| 已接收 | 该条记录标记“已接收”，任务运行状态另行显示 | 只清除与此次提交匹配的原稿；保留之后的新输入 |
| 已排队 | 显示“已加入队列”及后端支持的队列状态 | 保留现有队列能力，不把它描述为已开始运行 |
| 结果待确认 | 输入附近显示“暂未确认是否接收”，关联待确认记录 | 查看原消息与核对状态；不自动重发、不生成新逻辑 ID |
| 明确未接收 | 显示具体原因，保留原稿或提交快照 | 用户手动重试，沿用现有协议保护 |
| 执行失败 | 消息已接收，但任务报错 | 展示任务错误；不把“重试执行”与“重新投递消息”混为一谈 |

实现上复用现有 pending、receipt、草稿 revision 和账号/网关/会话隔离，不另建第二套发送状态机。已接收仅代表受理，不代表模型执行完毕。忽略待确认记录不代表取消已执行的请求。刷新状态属于只读操作，不能顺带重放发送、授权、停止或切换操作。

### 连接与接入

统一查看入口，内部明确区分三个对象：浏览器到网关的连接、网关到 Codex 的连接、当前账号/API 配置。一个状态读取接口失败时，显示“状态暂未更新”和上次成功时间，不能直接推断聊天也已离线。

本机管理页按“当前接入 → 已保存接入 → 新增/编辑”组织；API 表单优先显示名称、地址、Key、模型，Key 默认掩码。Desktop 与 CLI 共用配置的影响在切换前明确展示，WSL 作用范围单独标注。

保存配置、应用接入、重启桌面分别显示进度和结果，避免一个“保存”文案掩盖不同副作用。启动/退出/切换前继续即时核验真实进程和任务；缓存状态不能充当依据。API 连接测试如以后新增，必须单独设计真实请求与计费提示，不在本阶段暗含新增。

公共 Web 与本机管理页可以共享视觉组件和命名，但保留各自权限边界。本机专属操作在远程页只说明如何到电脑端完成，不为了统一 UI 开放远程写入。

### 设置与异常反馈

设置分成“外观与阅读、聊天与通知、连接与诊断”。账号/API 的编辑归入连接与接入。主题和字号标“当前浏览器 · 即时生效”；网关共享开关标“当前网关所有设备”，写入完成后才显示已保存。重置操作仅针对当前分组，并明确范围。

被动故障以行内状态呈现并保留旧数据，沿用 0.14.1 的去重与退避；持续故障提供一次明确提示。用户主动操作的失败就在按钮附近说明原因并提供重试。页面无数据、读取失败和搜索无结果不能共用“暂无内容”。待确认授权、实际失败和过期状态都必须用文字解释，颜色只作辅助。

## 视觉规则建议

- 保留现有蓝色主操作；同一局部区域只突出一个主要动作。普通工具用中性按钮，危险操作在明确操作菜单中表达。
- 桌面侧栏初始 280–320px，聊天正文约 760–900px；这是设计初值，需结合文件/终端工作区验证。
- 统一 8/12/16/24px 间距和按钮高度；正文建议 14–16px、辅助信息不小于 12px，保留字号偏好与系统缩放。
- 手机输入控件至少 16px，触控热区约 44px；可见图标可小于热区。覆盖 320/390/768/1440px 与 200% 缩放、亮暗主题。
- 对话框桌面居中、手机整页承载；键盘焦点进入标题/首控件，关闭回到触发按钮。状态更新使用礼貌播报，错误使用可定位的提示。

## 分阶段实施与验收

| 阶段 | 交付范围 | 验收重点 |
| --- | --- | --- |
| 第一阶段：操作可理解 | 发送状态、输入区收敛、作用范围标签、按能力隐藏无关应用设置、异常空态 | 接收后仅清原稿；迟到确认不清新稿；未知结果不重发；低频配置选中后可见；共享设置不标为本地设置 |
| 第二阶段：布局一致 | 桌面导航、手机列表/详情、设置分组、连接入口与本机管理表单重排 | 普通消息路径无新增必填项；查看连接状态不超过两次操作；390px 主要按钮不溢出；返回与刷新保留正确上下文 |
| 第三阶段：细节与性能 | 字号/暗色/焦点、键盘和安全区、长列表与长聊天性能分析 | 先记录现有耗时再设目标；慢网下有准确等待状态，不用统一“连接失败”掩盖所有错误 |

建议第一阶段作为一个可独立回退的小版本，验收后再推进布局改动。此处不直接承诺工期；第二阶段需先确认文件/终端面板在新布局中的行为。

必须保留并扩展现有关键回归：正常/拒绝/超时发送，HTTP 与 receipt 到达顺序，多标签页、账号/聊天切换、新草稿与相同文本重输，排队/补充/目标模式，断线恢复与手动刷新。布局覆盖列表、聊天、长文本、附件、设置、审批与手机键盘弹起。截图和空跑不能代替交互断言。

## 实施定位

- 页面结构：`src/CodexMobile/upstream/web/index.html`。
- 发送和新建流程：`web/shell/app.js`；草稿与恢复：`web/features/chat/composer-drafts.js` 等既有模块。
- 客户端入口与状态：`web/features/clients/client-navigation.js`；工作模式：`web/features/chat/modes.js`。
- 宽窄布局：`web/layouts/`；宿主能力：`web/hosts/`。布局尺寸与原生宿主类型分开判断。
- 本机管理：`src/CodexMobile/manager/index.html`、`app.js`、`app.css`。

保持上游资源 URL、加载顺序及资源清单契约；产品改动进入现有 overlay 核验。首轮不引入新前端框架，不修改认证、配对、CSRF 或发送协议。

## 实施与核验结果

三个阶段已合并实施。Dock 展示模块整理输入区、导航、空态、连接分层、设置分类和范围标签；本机页拆分已保存接入、API 编辑和应用 / WSL。原有控件继续处理业务操作，发送反馈使用原 pending / receipt / 草稿版本，不另建发送状态机。手机返回、已有宿主适配与工作台尺寸规则继续复用。

生产 Dock 资源的隔离浏览器检查通过 17 个交互流程，包括迟到确认保护新稿、未知结果不重发、明确拒绝保留草稿、排队确认、IME 合成不发送、模式摘要、设置范围、API Key 掩码与切页保留编辑、对话框焦点返回。320 / 390 / 768 / 844 / 1440px 调整宽度保留聊天草稿和合成文件 / 终端标签的内容与焦点；另外检查亮暗主题、200% CSS 布局缩放与 24px 聊天字号。前端无未处理异常。

同一生产网关、1440×1000 Chromium、合成内容，移除精确追加资源作为基线；每项预热一次后测七次，记录 render + layout 中位数：

| 场景 | 基线 | 0.15.0 | 差值 |
| --- | --- | --- | --- |
| 100 条聊天列表 | 8.5 ms | 8.8 ms | +0.3 ms |
| 1000 条聊天列表 | 79.5 ms | 80.1 ms | +0.6 ms |
| 500 条格式化消息 | 69.4 ms | 70.6 ms | +1.2 ms |

本轮目标为保持相近的本机渲染成本，观察结果满足该目标；未增加虚拟列表或改变历史分页。数据不涵盖网络、原生执行端或图片解析耗时，不作为公网速度承诺。机器可读样本在 `artifacts/ui-performance.json`，界面检查与截图在 `artifacts/dock-ui/`；这些测试产物不进入源码包。

原有回归与发布验证范围见 [0.15.0 审查](review-0.15.0.md)。安卓注入脚本在隔离 Chromium 里回归；真实 Android / iOS 键盘、系统返回、安全区和 200% 系统缩放仍需设备验收，CSS 缩放不能替代它们。没有真实账号切换、消息发送或部署。
