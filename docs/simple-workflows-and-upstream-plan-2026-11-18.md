# Codex Dock 普通用户操作与上游更新方案

2026-11-18 · 设计提案。Windows 以 WinUI 版 0.19.2 本地修复包为基线，Android 以 Lovest Code 0.2.5 为基线。下文的页面、按钮和操作次数是下一版的设计目标。

## 1. 先解决哪一步

先做 **在首页换一次模型**。用户知道自己要用 `gpt-6.2-sol`，现在却要找到“模型与行为”、点“获取服务模型”、选模型、看文件差异、确认保存，再点“打开或重启 Codex 并应用”核对实例。0.19.2 已修复新模型与固定审核一起保存的问题。下一步要让用户在选择模型的地方就能做完整个操作。[0.19.2 修复说明](release-0.19.2.md)

| 用户想做的事 | 新版正常路径 | 达成的结果 |
| --- | --- | --- |
| 继续在电脑上用 | 首页 → **回到 Codex**，尚未运行时显示 **打开 Codex** | 聚焦已匹配的窗口，或启动一次 |
| 换默认模型 | **更换模型** → 点选模型 → **保存并重启 Codex** | 同一任务页完成选择、核对、保存和打开 |
| 第一次用服务商给的密钥 | **设置连接** → 填地址和密钥 → **读取可用模型** → 选模型并保存打开 | 用户只填服务商交给自己的信息 |
| 让手机连上一台已准备好的电脑 | 电脑点 **生成配对码** → 手机点 **扫码添加电脑** | 手机显示已授权的电脑，可进入已启用的 Codex |

“换模型三步”按三次有意义的操作计，适用条件是连接已设置、服务有可用资料、目标实例明确。多实例选取、原生登录、网络准备和故障处理分别验收。

## 2. 用户打开软件会看到什么

日常侧栏收为 **首页、连接与模型、手机连接**。底部放 **高级工具** 和 **设置与帮助**。新老用户共用一套页面和一份草稿，展开“更多选项”即可查看专业内容。

| 入口 | 首屏内容 | 按需展开或直达 |
| --- | --- | --- |
| 首页 | 当前资料名称、已保存的默认模型、Codex 是否运行、一项主操作。下方两个轻量入口“更换模型”“连接手机” | 待处理的其他草稿、配置目录、查看上次结果 |
| 连接与模型 | 使用哪种连接、服务地址、密钥状态、默认模型 | 协议、代理、等待时间、推理与速度、审批与模型能力资料 |
| 手机连接 | 未配置时进入准备流程，已配置时展示服务状态及配对入口，已配对时显示设备 | 端口、执行环境、授权设备与撤销 |
| 高级工具 | 按名称或原字段搜索 | 全部配置、Profile、方案、增强、两个网关的管理、配置来源、聊天参数、备份与恢复 |

首页的主按钮取决于当前能完成的动作。已有配置且没有待处理修改时，直接显示“打开 Codex”或“回到 Codex”。空配置显示“设置连接”。有未保存的主配置显示“继续编辑”。已保存待应用显示“打开 Codex 使用新设置”或“重启 Codex 使用新设置”。需要恢复时，显示“查看恢复记录”。手机、Profile、方案草稿各自有入口，由用户进入相应任务处理。

首页根据实际进度显示 **已读取本机设置、已保存、Codex 已打开、已在指定聊天核对模型** 四种结果。最后一种需要实际聊天参数作为依据。确认页用友好名称标明目标资料，多套同名资料再补可辨识的路径。旧页面入口、搜索结果、帮助链接和键盘快捷键应能到达对应内容。

## 3. 三条具体流程

### 首次连接，已有用户直接用

1. 启动时读取当前资料和本机运行状态。识别到现有官方登录、服务密钥或客户端管理的凭据时，首页提供“打开 Codex”。凭据来自系统或自定义供应商时，沿用原来的登录渠道。只有确实缺设置时才显示向导。已有文件读取失败时，直接给出对应的修复或恢复入口。
2. 向导先让用户选择连接方式。选 **用 ChatGPT 账号登录** 就打开原生 Codex。登录后回到 Dock，可点“我已登录，重新读取”。选 **用服务商给的密钥**，用户在同页填写“服务地址”和“密钥”，读取按钮旁写清目标站点。
3. 对已有 ChatGPT 登录又要使用服务密钥的人，显示明确选择 **保留 ChatGPT 登录，模型使用此密钥**，说明模型请求发往哪个服务。选择切换为纯密钥时，先展示登录身份的变化。只有使用明文 HTTP 地址时才展示该站点的传输确认。
4. 点击“读取可用模型”后就地选择，随后按实际运行状态显示“保存并打开 Codex”或“保存并重启 Codex”。“手动填写模型”在更多选项中。网络临时不可用时，满足本地能力校验的现有模型或手填模型仍可仅保存。

### 日常换模型，一页完成

以已有服务、已固定专用审核、Codex 正在运行、目标唯一为例。

1. 首页点 **更换模型**。对已设置的 API 服务，入口提示“从当前服务读取模型”。一次读取同时获取可用名称和服务明确提供的原生能力，选择列表保留当前值。只有用户发起这项任务才访问服务。纯官方登录或客户端管理凭据时，优先展示当前来源可核对的原生模型列表。缺少可读来源时提供“到 Codex 中选择”，由客户端管理该次选择。
2. 点选 **gpt-6.2-sol**。列表下方立即显示本次变化、拟操作的实例和影响。例如“新聊天的默认模型将改为 gpt-6.2-sol。本次一起更新专用审核所需的模型资料。将重新打开这台电脑上的 Codex，进行中的任务可能中断。”文件差异可展开。
3. 主按钮 **保存并重启 Codex** 就是最终确认。Dock 先创建加密备份、保存，再准备此连接所需的模型网关，正常退出并打开刚才确认的实例。当 Codex 尚未运行，按钮显示 **保存并打开 Codex**。有任务想继续做，可点 **仅保存**，稍后从首页继续应用。能确认有任务进行时将“仅保存”设为主操作。任务状态未知时，确认区提示重启可能中断工作。
4. 成功后显示“已保存 · Codex 已重新打开。可在新聊天中核对模型”。网关或重启失败时，显示已经完成的步骤，只给出从失败处继续的按钮。返回编辑保留本次选择，放弃修改才清除草稿。

| 遇到什么 | 用户看到什么 | 接下来怎么做 |
| --- | --- | --- |
| 读取模型时服务拒绝密钥，或连接超时 | 根据实际结果显示“服务未接受这把密钥”或“暂时连不上这个地址” | 前者点“检查密钥”回到对应输入框，后者可“重试连接”。已填写的内容留在原处 |
| 服务只返回名称，现有资料足以支持所选设置 | 模型可选，可正常保存 | 继续完成选择 |
| 已固定审核，新模型缺少必需资料 | “这个模型缺少审核所需的资料。你已保存的默认模型仍是原来的选择。” | 有兼容项时可“选择其他模型”，否则可“保留原模型”。另提供“重新读取”及高级入口“导入服务方资料” |
| 主配置中还改了审批策略等其他字段 | 同页列出实际会一起保存的其他修改，包括移除覆盖后的含义 | “核对全部修改”，允许返回逐项调整。Profile、方案和手机草稿单独保存 |
| 找到多套 Codex、目标变化或正等待退出确认 | 显示资料名和运行状态，或“请先到 Codex 完成退出确认” | 明确选一个目标，或完成提示后继续。强制结束只放在失败详情中，单独确认 |
| 已保存，启动失败或用户取消重启 | “设置已保存，Codex 尚待打开”或“设置已保存，Codex 尚待重启” | “重试打开／重启”。如果只有增强加载失败，按钮只重试增强 |
| 编辑期间其他窗口改了配置 | “其他窗口也修改了设置，你的选择已保留” | 显示冲突项，读取新版本并重新核对。恢复备份有独立入口 |

### 手机连接，让人知道自己做到哪一步

- **已有配对码的人**直接在 Lovest Code 的“电脑”页点“扫码添加电脑”。已授权的手机下次直接选电脑，断线回到电脑列表，正在输入的内容留在原账号草稿。
- **首次配置这台电脑**只需填写手机可以访问的 HTTPS 地址、独立账号和密码。本机端口预填到高级选项。先说明需要受手机信任的证书，且地址已能转到这台 Windows 电脑。“我还没有这个地址”打开一页准备说明，可复制给网络管理员，也可先用电脑端。
- **明确点“保存并准备配对”后**，本页依次显示保存、启动服务、检查 HTTPS 是否指向本机后台、生成一次性二维码。修改已有账号或密码时，提交前说明已配对设备需要重新登录。已有配置、服务已启动时，主按钮简化为“生成配对码”，按需复核入口。流程停在失败的步骤。入口异常显示“重新检测”，过期显示“重新生成”。
- **扫码成功与能看到聊天分开显示。** 已扫码但还没有可用 Codex 时，电脑端给出“选择允许手机访问的 Codex”，通过现有本机管理入口登记并启用。完成后回到原步骤。手机显示已授权的电脑和可访问的聊天。多个执行端及 WSL、SSH 由电脑的高级工具管理。

入口返回 502 时，首屏提示“这个地址还连不到电脑上的手机服务”，并给出“检查电脑服务”和“复制转发设置说明”。公网域名、证书和网络通路需要事先准备，扫码本身只负责配对。[手机连接说明](mobile-connection.md)

## 4. 把三方更新排进同一份交付计划

以下编号沿用上一份清单，方便逐项验收。来源固定为 Codex++ 2.7.2、Superba 0.1.2-alpha.3 和 Codex Mobile Bridge 2.2.1。本次手机基线是上游 2.1.7 加 31 项显式覆盖，已有 v13 基础兼容和重连进入回归。[原更新清单](upstream-update-plan-2026-11-18.md) · [三方源码对照](upstream-reuse-review-2026-11-18.md)

| 批次 | 工作项 | 交付及判定条件 |
| --- | --- | --- |
| 一 · Windows 常用流程 | **W1 已有底层修复**，本批开发首页、首次连接及换模型的合并确认 | 先交一条可点通的换模型路径。复用 0.19.2 服务原生能力与审核映射，通过 0.19.1 的正常退出流程重开 Codex，然后接入首次连接 |
| 一 | **W2 · Codex++ 回环代理排除** | 从 Dock 打开、重启或启动独立资料时，只为该子进程合并 `NO_PROXY`，包括 localhost、IPv4/IPv6 回环。核对原例外、未设置时已启用的 Windows 代理例外及外部服务代理 |
| 一 | **W3 · Superba Windows 执行端发现** | 区分桌面窗口与读取功能所需的内核。优先发现运行进程、已有路径和商店安装。确需副本时校验内核及配套文件大小和 SHA-256。商店更新后重新匹配，失败才给“选择安装位置” |
| 一 | **W4 · Superba 配置资料更新** | 高级搜索可查新字段、中文含义及适用内核版本，需核对旧内核的显示和实际写入范围。普通页只放能在当前环境使用的选项 |
| 二 · 出错能继续 | **D1 · Codex++ 最终响应 ID** | 断流详情可复制时间、阶段、请求 ID 和确实收到的最终响应 ID。只从 HTTP、SSE 或 WebSocket 中标明响应完成的完整事件提取。数据截断时标“未收到”。诊断摘要仅含脱敏元数据 |
| 二 | **D2 · Codex++ 纯密钥连接创建聊天分支卡住** | 在隔离桌面版本复现分支停在加载的条件。确认受影响的构建后才适配，并实际进入分支验证。未复现则交付环境与结果 |
| 二 | **D3 · Superba 重启后沙箱状态检查** | 先复现已打开窗口却无法确认沙箱状态的场景。有复现才做原生状态重查和有限重试，超时提供“查看状态” |
| 三 · 手机配对与聊天 | **M3 · Mobile Bridge 探测取消与返回** | 先核验现有 Android 逻辑，接入上面的手机流程。探测中可返回，迟到的结果只属于发起探测的页面，离线和授权撤销后可重新选电脑 |
| 三 | **M1 · Mobile Bridge 聊天内交互图表** | Windows 手机后台、Web、自有 APK 配套交付。核对会话鉴权和预览隔离，横竖屏、全屏返回及重新打开能恢复状态。图表追问先进入草稿 |
| 三 | **M2 · Mobile Bridge 聊天小操作** | 输入框支持当前 Codex 执行端可用的 `/` 命令，新聊天标题可留空，消息显示时间。中文输入法选词后由用户发送，连续点击只创建一个聊天。发送结果未知时先查状态，保留草稿 |
| 三 · 独立专项 | **M4 · Mobile Bridge 附属会话与延迟输出** | 按真实会话归属补取延迟正文，核验侧聊关闭和历史分页。验收主聊、侧聊、工作目录及消息的对应关系。遇到未知关键结构时保留历史和草稿并暂停控制 |

第一批先交付换模型样板，再按 **W2 → W3 → W4** 接入并验证首次连接。第二批 D1 可直接实施，D2、D3 的交付取决于复现结果。第三批顺序为 **M3 → M1 → M2 → M4**。账号库、会话迁盘、微信扩展及未发布分支的候选功能单独排期。

## 5. 开发落点与中途中断

- **页面共用现有服务。** 首页和任务页复用 WinUI 导航与下一步状态、主配置草稿及模型读取服务。普通表单与高级表单编辑同一份值。服务地址、密钥、协议、代理、资料目录或 HTTP 授权改变后，废弃旧读取结果。用户明确选择的本地能力文件优先。
- **一次确认分两段执行。** 用现有保存服务生成不可变修改清单，与预先核对的资料、目标实例、打开或重启动作一起展示。用户点击时固定这份选择，保存服务负责备份和写入，桌面应用服务使用保存后的快照完成打开。操作前再次核对目标进程身份、配置和已选增强，影响范围发生变化就停下来重新展示。每份确认只消费一次，重复点击只启动一个操作。
- **记录实际完成的那一步。** 保存失败回到编辑现场。已保存但桌面操作失败，从已保存快照重试。若 Codex 已打开而增强失败，只重试增强。跨 Dock 重开需要按资料目录重新读文件和运行状态，“待应用”提示只用于导航。回滚走现有加密备份恢复流程。
- **安装更新前说明影响。** 正式版有更新时在设置显示“下载安装包”，校验通过后显示“安装更新并退出”。复用现有草稿处理和当前资料的网关停止流程，在确认处说明会中断哪些连接。本地体验包在交付说明中标明安装方式。

主要代码入口见 [WinUI 导航](../src/CodexConfig.WinUI/WorkspaceNavigationUi.cs)、[配置草稿](../src/CodexConfig.Application/ConnectionDraftViewModel.cs)、[配置保存](../src/CodexConfig.Application/ConfigurationSaveService.cs)、[桌面应用](../src/CodexConfig.Application/DesktopApplicationService.cs) 和 [手机连接](../src/CodexConfig.Application/MobileConnectionService.cs)。

## 6. 怎样判断真的变简单了

1. **给普通用户试用。** 建议请 5 位没用过 Dock 的人分别完成三个任务。先用提供的地址和密钥打开 Codex，再将模型换成指定项并说出是否需要重启，最后用准备好的 HTTPS 入口配对手机。记录完成率、跨页次数、误点与卡住的文案。目标是每项至少 4 人独立完成。没有地址的人能准确指出缺少的条件，也能返回电脑端继续用。
2. **记录实际操作次数。** 已配置的用户正常打开或回到 Codex 只需一次点击。目标唯一、模型资料充足时，换模型从首页三次操作、一次最终确认。服务已启动且入口有效时，新增手机只需电脑生成一次码、手机扫码一次。记录原生登录和系统相机授权等额外步骤。
3. **验证错误路径与数据。** 固定审核且新增 `gpt-6.2-sol`、仅名称列表、离线已有模型、同时移除审批覆盖、外部冲突、多实例、Codex 在托盘、用户取消退出、保存成功但打开失败，都要从正式入口走通。比对配置、凭据来源、能力目录和备份，确认重试后只有一份有效修改。手机另外检查二维码过期、撤销后重连、网络中断、返回、草稿和聊天归属。
4. **逐批验收。** 每批用同一提交验证安装包内程序集、相应窗口与协议回归、覆盖升级与回退。界面覆盖键盘、屏幕阅读器标签、窄窗口和 Windows 缩放。手机批使用自有包名与发布签名核验覆盖升级，再用实体手机检查扫码、中文键盘、网络切换和真实 HTTPS。报告区分模拟器、真机和公网实测。

首个可评审交付物是 Windows 换模型体验包。请评审者先在 Codex 开着时换到指定模型，再试一次“仅保存”并从首页继续。两条路径的按钮文案和结果都说得清楚，再把同一套交互推广到连接与手机任务。
