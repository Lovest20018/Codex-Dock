# 审查修复与手机连接验收

本轮修复模型目录与直连保存的两处 P2，并复验 Windows 手机访问和当前安卓源码。没有改动手机接口、安卓包名、发布签名或版本号，也没有替换用户正在运行的服务。

## 修复

普通模型目录中的推理选项需要原生必需的 `description` 字符串。现在对于缺失、空字符串、超长或含控制字符的说明保留空字符串，不再输出缺少该字段的条目；模型声明的推理选项和默认值继续保留。独立本机内核只读 `model/list` 验证中，无能力字段、完整说明、缺失说明及未知 effort 字符串四种目录均成功读取目标模型，没有退回默认目录。

API Key 直连不再校验或保存隐藏的网关等待草稿，而是沿用已保存的有效秒数。切回“官方账号 + API”时，未完成的输入仍保留且继续校验。回归覆盖空值、59、非数字、3601，以及有效但尚未保存的 900 秒；直连的模型、名称与其他更改正常进入原有确认保存流程。

## 手机连接结果

手机后端的 74 项回归通过，包含 v11/v13 同步与结构检查、真实隔离 IPC、显式重连、迟到连接取消、未知发送不自动重发、账号与模型目录隔离、配对兑换并发、失效与撤销规则。

完整 Core/共享应用层 364 项通过，其中打包手机后台验证了启动与停止、登录保持、修改端口后保留设备、重启后保持授权、共享出口登录失败不会清退合法设备，以及设备撤销后旧 Cookie 被拒绝。WinUI 完整窗口 425 项通过，包含检测、配对与启停状态同步，以及本轮新增两项隐藏等待输入的实际保存检查。WPF 兼容窗口 309 项通过，三套 Windows 构建均零警告、零错误，Core/Application DLL 摘要一致。

Android 14 隔离模拟器使用当前生产 Java、资源和 Web 适配代码，编译为独立 `connectionqa` 包，使用临时测试证书。生产 Java 未修改，测试断言不变；仅测试包名、ContentProvider authority、instrumentation 目标和输出路径适配，跳过原发布证书的跨版本安装步骤。测试后两只 QA 包均卸载，临时签名已销毁。

- 完整安卓检查 **72 项通过**：真实 WebView 密码登录、重新连接时登录和存储保留、Activity 重建后的草稿恢复、页面切换、通知、文件选择与下载、键盘和窄屏布局、离线返回。
- 追加输入专项 **22 项通过**：通过实际 HTTP 与隔离原生 IPC 三次追加到同一活动任务，每次文本和提交 ID 一致；任务完成后拒绝追加，保留草稿，不启动或中断其他轮次。

这里的“真实”指使用产品实现和实际进程/设备运行，不代表连接了真实用户账号或模型。安卓网络经过仅供测试的本机代理，替换 Host 并为本机 HTTP 去除 Secure Cookie 属性；产品 HTTPS 与认证代码未变更。没有实体手机、二维码摄像头、公网 HTTPS、路由器、真实模型任务或原证书覆盖安装验收，不能用模拟器结果替代这些边界。

## 安卓除了 LOGO 是否需要更新

截至本次核对，上游最新正式版仍为 [2.2.1](https://github.com/try2love/codex-mobile-bridge/releases/tag/v2.2.1)，固定提交 `1004e5aeb6ee38a75ab18b4bad1720a38553aada`。我们的 Windows 手机网关已经选择移植其 v13 同步、连接恢复、模型缓存和列表容错，见 [已有移植记录](mobile-upstream-backport-2026-11-15.md)。这些修复通过网关提供给手机，不要求现有安卓应用同步改包。

本轮没有发现必须升级安卓 APK 才能解决的新连接缺陷。当前自有应用已具备 Cookie 恢复时的身份/代次检查、退出取消、12 秒连接提示与离线返回，完整模拟器回归也通过；无需整体覆盖为上游的新包名或多信道架构。

后续可单独选择的功能是聊天内交互图表与全屏导航、命令入口和音视频展示。图表需要后端只读资源接口、鉴权与隔离页面和安卓导航一起适配；设备查看/消息/完全控制分级需要服务端逐操作校验，不能只改 APK。上述可选项不属于本轮连接修复，也未被记为已经实现。

正式安卓覆盖安装包仍需要原发布签名目录；此次 QA 证书无法替代。安卓版本保持 0.2.4 / versionCode 7，本轮未发布新 APK。
