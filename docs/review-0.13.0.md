# 0.13.0 手机网关审查

## 实现边界

基于 Codex Mobile Bridge 2.1.7，固定上游提交 `0721aa7dafa6177751ba7e568e0ad0efee05655b`。只提取 Codex IPC、认证、配对和历史模块，必要辅助函数隔离；选取与修改记录见 `src/CodexMobile/UPSTREAM.md`。专用 HTTP 路由、网页和 WPF 管理由 Dock 集成，不打包上游 Electron、安卓 APK、隧道或多客户端服务。

公开监听默认 `127.0.0.1:13090`，端口可改。已有 HTTPS 反向代理转发原 Host 与客户端地址；单独的本机管理端口使用随机令牌。手机设置使用 DPAPI 并按 Codex 配置目录隔离。启动参数从标准输入传递，不把控制令牌放入命令行。公网路由和静态资源使用白名单，不提供任意桌面 RPC 或文件路径。

只从本机 Desktop 历史发现会话，再通过原 owner 的快照确认 session ID、cwd 和 provider，发送时继承原会话设置。订阅失效、版本/修订不一致和身份不符时停用写入。操作 UUID 在发送前持久化；丢失响应保持 unknown，只有保存的原生消息标识可确认发送回执，重连不会重放。审批以原请求和当前有效决策为准，不扩大为长期授权。

## 本地证据

- 手机 Python：34 项通过，覆盖真实回环 HTTP 的 Host/Origin/CSRF、Cookie、密码和配对、持久化与撤销、入口实例检查，以及假 Codex owner 下的状态、身份、回执和审批处理。全部使用临时目录与虚构凭据。
- .NET：79 项通过，包含每目录 DPAPI 保存、输入校验和实际冻结的手机 EXE 启停。实际 EXE 验证并发启动只保留一个 worker、管理器退出后继续服务、安卓持久设备授权跨重启、撤销后无法恢复以及原 Codex 文件不变。
- 浏览器：10 项通过。独立无头 Chrome 使用全请求内存拦截，覆盖登录事件、DOM 文本显示、草稿、未确认结果不重放、原生提问、搜索竞态、移动布局、hash 配对和实际上游 APK 四个注入脚本。独立 jsQR 解码器确认二维码内容。浏览器测试依赖只用于开发。
- WPF：完整隔离 UI 检查通过，新增手机页独立保存、导航草稿、URL 校验、数据隔离、960×640 与深色布局、设备撤销/解封控件和 Codex 配置不变。沙箱内原混合网关无法启动导致首次 UI 检查失败；允许回环和测试子进程后相同检查通过。
- 发布脚本：从已提交的源码重建手机 worker 和自包含 .NET 程序；发布 EXE 再运行 UI 检查，安装验证核对完整文件树、卸载和用户环境，生成散列清单并扫描私有文件与凭据。实际打包及安装结果保存在发布附件的 manifest、UI 报告及本地 installer-verification JSON。

## 尚未完成的验收

上游安卓真机的扫码、手动密码登录、杀进程/重启恢复、撤销后恢复失败以及蜂窝/Wi-Fi 切换仍需实际测试。自动检查证明协议和注入脚本匹配，不证明 Android OS Cookie/密钥存储、相机或网络行为。

本轮未对真实 Codex 聊天发送、停止或批准操作，也未改动用户登录或模型连接。实际桌面 IPC 与真实模型能力需在专用测试聊天验收。用户 HTTPS 域名检测到有效 TLS，但 `/api/auth` 返回 502；尚未启用本机真实手机服务，也未验证代理能到达端口。域名和反向代理不由工具自动部署。

首版文字界面只展示最近记录；不支持新建聊天、附件、外部表单、计划实现等额外动作。上游原生附加菜单不裁剪 APK。完整接入与升级行为见 [手机连接说明](mobile-connection.md)。
