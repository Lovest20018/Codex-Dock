# Windows WinUI 界面与开发入口

Windows 0.19.0 已将 WinUI 作为默认安装界面，入口为 `CodexDock.exe`。下文保留独立开发程序 `CodexDock.WinUI.exe` 的运行与验证说明；此前“尚未作为默认入口”的描述属于迁移阶段记录。正式安装与覆盖升级以 [0.19.0 更新说明](release-0.19.0.md) 为准。

WinUI 3 壳层是独立的开发预览程序 `CodexDock.WinUI.exe`，尚未作为默认交付入口。当前按五个任务组织：工作台、Codex 配置、运行与增强、手机访问、诊断与恢复；底部为设置与帮助。原有功能都保留在二级页面中，页面标题和二级导航固定在内容区上方。整合说明见 [UI 整合记录](winui-consolidation-2026-11-17.md)。打开页面只读取本地文件；修改字段先保留为草稿，确认差异后才写入；点击“打开或重启 Codex 并应用”并确认后，才会启动桌面操作。侧栏图片与 EXE、窗口、托盘统一使用桌面版 Codex Dock 标识，未修改安卓资源。

任务流程复查又修正当前页滚动和指定字段定位，并区分工作台的应用失败、冲突、取消与独立草稿状态。手机服务保存成功后可直接进入连接与配对，状态引导随检测结果变化；HTTPS 检测和二维码生成仍需明确操作。详情见 [任务流程复查](winui-task-flow-2026-11-17.md)。

后续审查修复了手机服务启停后配对状态未同步，以及恢复配置后来源页继续显示旧文件值的问题。服务状态刷新会等待较早的读取结束，再核对当前状态；刷新失败时保留未确认状态及草稿。恢复成功后清除旧来源结果，需要再次明确读取。见 [审查修复记录](winui-review-fixes-2026-11-17.md)。

本轮又按复用方案加入混合连接的 HTTP 响应头等待、普通模型目录的能力保留，以及配置来源页的实验功能读取与草稿修改。实验功能读取明确区分独立执行端观察与当前桌面状态；修改仍需查看差异并确认保存。压缩兼容完成边界验证，产品继续透明转发。入口、适用范围和测试记录见 [复用实施记录](codexplusplus-reuse-implementation-2026-11-17.md)。

当前图标已按用户选定的组合更新：开口 D 与接入箭头，配浅绿底和深墨绿；Windows 两套界面及安卓源码共用同一份矢量定义。窗口、侧栏、EXE 和托盘均已更新，详见 [图标统一记录](brand-refresh-2026-11-17.md)。

最新审查修复了普通模型推理选项缺少必需说明时目录无法读取，以及隐藏的网关等待输入阻止直连保存的问题。手机后端、Windows 配对流程与 Android 模拟器连接验收见 [修复与手机验证](review-fixes-mobile-validation-2026-11-17.md)。

首次打开空目录时，工作台与连接页提供设置入口，读取和取消不会创建目录或配置。没有可用凭据时先完成连接设置，保存前不能应用或自动接回 Codex；已有官方文件登录、进程环境凭据、供应商认证或系统凭据设置继续保留，读取不做在线验证或执行认证命令。首次保存同样先显示文件目标与脱敏差异，确认后创建加密备份并写入，随后等待单独应用。

配置格式、认证或加密数据无法读取时，清除旧工作区快照与运行状态，结束忙碌并禁用编辑、应用；界面提供修复后重新读取、切换目录与查看恢复记录的路径。错误说明不展示源文件内容，原文件不会自动重置。修复后可在同一窗口重新读取。主连接密钥与手机密码通过同步 `PasswordChanging` 保存草稿，避免邻近字段输入或周期回填覆盖尚未同步的密码。

“Codex 配置 → 连接”修改服务地址、API Key 和协议，名称与备注按需展开；默认模型摘要通过“选择模型”进入唯一的模型编辑入口。API Key 默认隐藏；差异确认会隐藏认证内容、连接备注和地址中的敏感参数。服务为非回环 HTTP 时，沿用现有按站点确认的规则，更换站点会清除旧确认。旧 PAT 通过明确的“迁移为 API Key”加入草稿；仅修改模型或备注会保留原认证和供应商配置。

混合连接在原生 Codex 完成 ChatGPT 登录后，可读取当前目录的官方文件登录，也可明确选择本目录的加密登录备份。当前登录优先；备份只进入内存草稿，确认保存后才采用。读取保留服务密钥、模型、备注与行为草稿；读取期间目录、设置或登录再次改变时丢弃结果。切换为直连不提交暂存身份，放弃修改或切换目录会清除暂存。凭据有效期和刷新仍由 Codex 管理，本页不进行在线登录验证。

“Codex 配置 → 模型与行为”中的“获取服务模型”只向当前选择的服务读取目录，不发送对话或自动选择模型。支持取消；连接信息变化会丢弃旧结果，空目录和失败均保留当前模型。这个 ID 列表不能替代专用审核所需的原生能力文件。

“模型与行为”与连接页共享同一草稿和保存确认，可设置推理、摘要、详细程度、服务档位、搜索、Fast、上下文管理、沙箱与审批。未设置项显示跟随 Codex；保留原有未知值和结构化审批规则。已有能力目录时按所选模型展示支持的推理和服务档位，并保留当前未列出的值。专用审核固定使用 `codex-auto-review`；导入、读取客户端能力目录和同步均先暂存，校验主模型与审核能力后，目录、配置和管理记录一起备份并保存。

`ConnectionDraftViewModel` 持有内存草稿，`ConfigurationSaveService` 为两个界面生成方案、整理差异并提交确认的副本。保存沿用 Core 的加密备份、事务回滚、模型目录约束和冲突检查，并再次读取核对结果。同账号令牌刷新、运行管道轮换和外部注释会保留；实际设置或身份改变会阻止覆盖。保存与桌面应用共用同一操作锁。保存成功只进入“等待应用”，不会自行启动网关或重启 Codex。

有草稿时显示固定的保存/撤销操作区，并暂停自动接回与桌面应用。切换页面保留草稿；切换目录、重新读取、明确退出或执行增强快捷方式时，可选择先查看并保存、放弃修改或继续编辑。普通关闭仍收起到托盘并保留草稿；取消保存或保存失败也保留草稿。

“Codex 配置 → 高级配置”按已配置、全部和已修改范围查询同一份本地配置目录，支持搜索、分类、高级项与每页 20 行的分页。普通布尔和枚举用选项编辑，其他类型按 TOML 值编辑；可以添加带引号名称的动态字段。连接管理字段、父表和已移除项沿用现有只读规则，不适用平台的字段不进入列表；添加子字段不会执行其中的命令。敏感环境值用密码框显示，摘要和保存确认递归隐藏凭据及地址参数。输入错误留在草稿并阻止保存，逐项撤销、移除覆盖或修正后再确认；翻页和导航保留输入。

“方案库”与 WPF 共用本机 `%LOCALAPPDATA%\CodexConfig\templates.json`。支持新建、编辑、复制、删除、恢复内置方案及从当前普通设置创建；模型、连接和嵌套凭据不写入方案。方案差异默认保留相同值、已有草稿和未默认选择的历史项。加入方案只更改配置草稿，撤销时保留之后手动编辑的字段。编辑方案有独立的固定保存区；页面切换保留编辑，切换目录、重新读取、明确退出和增强启动前先处理未保存方案。方案库提交在文件锁内核对读取时的摘要，其他窗口改动会阻止旧编辑覆盖；库损坏时保留原文件并禁用写入。

“备份与恢复”先读取当前目录的最新加密备份或未完成事务记录，再展示恢复差异、备份时间、来源和写入目标。取消不会写文件；确认只执行这份恢复计划，记录、配置或身份发生实际变化时拒绝旧确认。正常恢复沿用 Core 事务，并加密备份恢复前状态；中断恢复使用原事务记录并归档为 `.recovered`。运行管道、注释及可证明的同账号登录刷新会保留，所需模型目录按现有规则恢复，外部修改不会被覆盖。未完成保存会显示提示，并禁用配置编辑、自动接回和桌面应用，恢复后再解锁。恢复不会启动网关或重启 Codex。

“配置来源”明确选择本机原生 `codex.exe`、项目目录和可选 Profile 后，通过短时 `app-server` 读取配置层，显示比较文件值、执行端读取值、来源和作用范围。不会开始聊天、轮次、登录或工具调用；选中的程序会实际启动为一个单独的本机进程。结果经过敏感值隐藏，支持筛选和每页 20 行。读取使用磁盘文件，主配置和 Profile 的未保存草稿不参与；读取中条件或比较文件改变时丢弃结果，切换条件立即清空旧快照。可取消读取；执行端不支持所选 Profile 时明确显示未确认，不推断现有聊天的参数。

“Profile 文件”独立读取或新建 `<名称>.config.toml`。编辑区使用 TOML，只展示通过普通模型与行为字段校验的内容；原有连接、权限、嵌套凭据或不可编辑字段留在源文件并保留。保存与恢复各自先展示具体差异、文件目标及恢复来源，确认一次后才写入并加密备份。外部文件或备份变化、确认期间草稿变化会阻止覆盖。主配置草稿和当前聊天不会切换；使用 Profile 需由执行端明确选择 `codex --profile <名称>`。导航保留草稿，切换目录、重新读取、明确退出或增强启动前先处理未保存 Profile。独立的固定保存区区分 Profile 与主配置草稿。

“Windows 设置”的开机启动绑定当前 EXE 与配置目录，并以 `--start-in-tray` 登录启动 Dock。开关立即保存，独立于配置和 Profile 草稿。同一 Windows 用户只有一个 `CodexDock` Run 项，WPF 和预览共用；登记到其他程序或目录时会先确认替换，确认后复核读取到的命令，避免覆盖另一个窗口的新改动。关闭只移除与当前程序和目录匹配的项，不删除其他注册。程序与目录路径过长时保留原状态并提示；Windows 是否禁用启动项仍需在系统“启动应用”核对。

“聊天参数”先刷新当前目录的近期记录，再手动选择并读取。只展示模型、推理、档位、审批、审核结果和记录时间，不展示提示词、工具参数或对话文本，也不从配置推断实际审核模型。读取当前固定大小的文件尾部，支持取消；选择、目录或窗口生命周期改变后拒绝旧结果。导航与读取不会保存主配置、Profile 或其他草稿。

网关管理中的“压缩与连接耗时”读取正在运行的本机模型网关统计：配置允许的协议、客户端触发次数、服务返回条目和确认成功次数分开显示，HTTP 200 本身不代表压缩成功。最近触发和最近完成各有协议、传输与时间；另显示排队/活跃数、队列、响应头、首数据、总耗时和结束原因。无法完整检查的数据会明确标注；旧后台缺失的字段显示未知。统计只覆盖本次模型网关进程，重启后重新累计；停止、读取失败、未确认监听者或切换目录后清除旧统计。刷新不写草稿、启动网关或主动发送模型探测请求。

“软件更新”手动检查指定 GitHub 仓库的正式版，使用与 WPF 相同的来源、重定向、大小和 SHA-256 校验。下载支持取消，成功后才提供安装入口；安装前再次校验并持有禁止写入/删除的文件句柄，先处理全部草稿、确认安装范围与当前目录，再等待客户端增强和已保存的两个网关退出。停止状态不确定、安装器变化或启动失败时保留可访问的预览窗口，并提示核对后台状态。这里的正式版安装器安装现有主程序；WinUI 仍为独立预览入口，不宣称该安装器升级预览界面。预览版本与 WPF 正式版比较基线一致，构建脚本同时核对源码版本与实际 DLL。

三个增强开关使用与 WPF 相同的按目录隔离的设置文件。点击开关会保存偏好；读取、导航、重绘和切换目录不会保存开关。手动应用、实例选择、批量退出确认、配置冲突检查和增强失败重试均通过共享的 `DesktopApplicationService`。实际调试连接由共享的 `DesktopEnhancementRuntime` 持有，WPF 与 WinUI 不再各自实现接入过程。

多个 Codex 实例不会预选目标；勾选“同时退出其他实例”后，必须全部退出才打开一次。正常退出失败时提供独立的强制重试，仍需再次确认；它只操作之前捕获的实例。增强接入失败时，保留已确认的新实例，只重试增强，不再重启。应用期间不能重复启动、编辑开关、切换目录或退出窗口。确认后配置或增强选项被另一窗口更改时，会拒绝继续。

API Key 直连无需模型网关；混合连接先检查或启动本机模型网关，再退出 Codex。预览程序通过自己的 `--model-bridge` 后台入口维持模型网关，完整目录同时包含 `mobile` 手机后台程序。“运行与增强 → 模型网关”管理模型服务状态、启停和统计；手机服务的启停与自动启动位于“手机访问 → 服务设置”。“手机访问”另有连接与配对、授权设备两个页面，统一完成入口设置、检测、扫码和设备管理。

手机设置由共享的 `MobileConnectionService` 和 `MobileSetupDraftViewModel` 管理。保存前展示不含密码的差异，确认后加密保存并启动后台；密码留空沿用同账号已有密码，只改端口保留已有设备身份，修改域名、账号或密码按原有规则使旧授权失效。保存使用确认时的设置摘要，Core 在手机管理锁内复核，避免覆盖另一窗口的改动。若设置保存成功但启动失败，页面会明确保留“设置已保存”，清空密码并提供网关管理重试入口。

手机草稿与模型连接草稿互相独立，切换页面和状态刷新不会覆盖草稿；切换目录、重新读取或明确退出时会分别询问保存、放弃或继续编辑。切换工作区会清空密码和二维码。字段变化在文本更新时同步记录到草稿，后台刷新不会覆盖尚未提交的文本。手机控制、保存和其他应用操作共用同一租约。

HTTPS 检测和配对只在明确点击时执行；二维码由已有本机后台生成，不上传到图片服务，5 分钟有效且只能使用一次。配对使用、过期、撤销、设置更改或网关停止后会清除显示。设备撤销和解除登录限制需要确认，并在操作前重新核对当前设备成员。Codex 接入管理地址必须是已保存控制端口上的 `127.0.0.1/manager/` 地址，使用一次性片段在本机浏览器打开，禁止转到外部站点。

两个界面通过共享的 `GatewayManagementService` 控制网关。刷新不启动进程；启停只使用保存值，不改连接或手机草稿。状态不能通过认证健康检查确认时，只有端口已释放才显示停止，否则保留“暂未确认”。重启必须先确认旧进程退出，配置在中途变化时不启动新进程；未知监听者不会被结束。网关控制与配置保存、桌面应用共用操作锁。

自动启动默认关闭，开关立即保存，下一次打开 Dock 时对初始目录执行一次。关闭开关不会停止服务；手动停止后刷新、换页或重复启动回调不会重开。一类网关启动失败不阻止另一类尝试，错误按服务保留。正常退出后网关继续运行；网关页和托盘提供“停止网关并退出”，确认当前目录的两类网关停止后再走退出流程，一类停止失败时保留窗口。

关闭窗口会收起到托盘，增强继续运行。点击托盘图标可恢复窗口，右键菜单提供打开窗口、客户端增强、网关管理、停止网关并退出及正常退出。退出已接入增强的预览时会确认，取消退出保留连接。托盘创建失败或 Explorer 重启后图标恢复失败时保留可访问的窗口，关闭窗口改走正常退出流程。确认退出或切换目录会释放当前增强连接。后续核对剩余入口、首次配置与系统设备覆盖，再决定默认入口切换；安卓应用本体未在本阶段修改。

自动接回默认关闭、按配置目录保存，启用后通过共享的 `AutomaticEnhancementService` 调度。只有上次实际应用的配置摘要、进程创建时间、程序、资料目录和增强方案均匹配时，才会以 `resumeOnly` 接回原页面；不会自动启动、退出或刷新 Codex。每次核对最多 12 秒，失败后至少间隔 20 秒；重复检查共用一次任务。应用、目录切换、选项变化和退出与接回互斥或先取消并等待。

开启自动接回并选择增强后，可在页面创建 Windows 增强启动快捷方式，保存位置由用户选择。快捷方式传递 `--enhanced-launch --home <目录>`；已关闭该目录的增强启动时只展示设置。明确启动时可打开尚未运行的 Codex；需重启已有实例时仍会确认。每个 Windows 用户只运行一个 WinUI 预览，普通重复启动恢复原窗口，增强启动通过当前用户的命名管道转交配置目录。预览与 WPF 使用独立的单实例作用域，模型网关 worker 与隔离测试不参与窗口单实例限制。

“已保存文件预览”只读取当前目录磁盘上的 `config.toml`、`auth.json` 和当前 Windows 用户的 `CODEX_AUTHAPI_BASE_URL`，主配置、Profile、方案及手机草稿均不参与。配置展示规范化的脱敏字段副本，去掉注释与原排版，递归隐藏敏感字段及 HTTP/HTTPS 地址的用户信息、查询参数和片段；认证只显示已知方式、凭据字段是否存在和其他字段数量，不展示账号身份或令牌。单文件读取上限 8 MiB，单页显示上限约 100 万字符。读取可取消，文件或目录在读取期间改变会拒绝结果；损坏项单独标记，其余可读项仍可查看。本窗口保存、恢复、重读或切换目录后清除旧预览，外部更改需重新读取。脱敏副本供核对和复制，不用于回写原文件。WPF 原保存预览仍按当前保存计划展示，含尚未保存的草稿，两个入口明确保留各自范围。

顶部配置目录菜单提供切换目录、查看文件、打开目录及复制路径入口。全局待处理修改菜单列出主配置、Profile、方案编辑和手机设置，分别跳到所属编辑区，不跨范围保存。打开与复制只在明确点击时执行；目录不存在时不自动创建。“使用说明”提供七类可搜索主题，快捷按钮跳转到已有页面，各页沿用原确认和保存流程。本轮实现与隔离验证见 [文件预览与帮助记录](winui-information-2026-11-16.md)。

文件预览和路径复制的 Windows 剪贴板内容禁止加入历史及跨设备同步。本机双屏 100% 缩放和实际目录打开的验证、复制验收的失败记录及剩余范围见 [本机环境验收](winui-environment-2026-11-16.md)。

后续 [本机剩余项验收](windows-local-acceptance-2026-11-17.md) 已在用户明确提供的测试文字上完成路径与脱敏摘要回读、测试文字恢复及正常退出；另完成真实 Codex 空白独立资料的打开、退出受阻保护与确认重启，以及验证安装器的安装/394 项窗口回归/卸载。该复制结果不代表恢复任意图片、文件或富文本剪贴板，也不能恢复此前事故前的原内容。其他物理 DPI、Windows 10、手机公网和实际登录启动仍需相应环境。

## 运行

键盘操作：`Ctrl+S` 仅保存当前编辑对象；主配置、Profile、方案和手机服务设置分别保存。帮助与只读诊断页面不会保存其他区域的草稿；`Ctrl+F` 在帮助和来源页聚焦本页筛选，其余页面进入全部配置搜索；`F1` 或 `Ctrl+Shift+H` 打开帮助。全局截图等工具可能占用 F1，可使用备用组合键。模态框和正在执行的操作会阻止这些页面命令。

“Windows 设置”还提供收起到托盘、最小化到任务栏和退出入口。窗口初始与最小跟踪尺寸按当前 DPI 缩放，并限制在当前显示器工作区；窄窗口的按钮组按需换行。入口对照、17 页尺寸矩阵和本机系统验收见 [Windows 收尾核对](winui-final-audit-2026-11-16.md)。

本地开发预览需要 Windows x64、.NET 8 与 ASP.NET Core 8 运行时（安装 .NET 8 SDK 已包含）。Windows App SDK 文件随输出目录携带，无需另外安装 Windows App Runtime。请保留 EXE 的整个同目录内容。

```powershell
& 'C:\path\to\app\CodexDock.WinUI.exe' --home 'D:\path\to\codex-home'
```

未指定 `--home` 时，按现有 Core 规则读取 `CODEX_HOME`，否则读取当前用户的 `.codex`。界面中的“切换目录”可选择另一个配置目录。预览不会更改默认配置目录或系统环境变量。

可加 `--start-in-tray` 启动后收起到托盘。只有托盘图标创建成功才隐藏窗口；此参数不会注册 Windows 开机启动。

## 编译与验证

构建需要 Windows、.NET 8 SDK 和 Windows SDK 10.0.26100 工具。当前锁定 `Microsoft.WindowsAppSDK` 1.8.260317003；目标系统下限保持 10.0.17763。WinUI 项目单独清除仓库的 `RuntimeFrameworkVersion` 全局值，以免 .NET 运行时版本被误用为 Windows SDK 引用版本。其他项目的构建设置不变。

```powershell
pwsh -NoProfile -File scripts/build-winui-preview.ps1 -Verify
```

脚本在 `artifacts` 下创建独立输出目录，复制许可文件，启动隔离测试并核对报告与交付程序集 SHA-256。已还原依赖时可传 `-NoRestore`。测试配置、虚构认证和三套增强设置均位于测试输出目录；测试拒绝同时传入 `--home`，不会读取实际用户环境变量或增强偏好。所有桌面重启使用替身；另实际启停一个使用虚构连接的隔离模型网关，只检查本机控制入口，不请求远端模型。DPAPI 与进程检查需在正常 Windows 用户上下文运行。

完整预览需要先通过 `scripts/build-mobile.ps1` 生成 `artifacts/mobile-worker/CodexDock.Mobile`；WinUI 构建将其复制到输出的 `mobile` 目录，缺少后台时构建脚本会报错。隔离测试实际通过当前预览的共享网关服务启停、重启模型和自带手机后台，核对认证健康、进程退出、端口释放与设置保留，不联系远端模型或手机公网入口。

手机连接专项使用虚构的入口与替身控制来渲染真实确认和二维码页面、取消授权及草稿离开流程；二维码是固定无访问权限的本地测试图。实际后台专项另核对 DPAPI 保存、状态和设备读取、端口修改后保留测试安卓登录、撤销后无法恢复。测试不检测真实 HTTPS 域名，也不打开用户浏览器；实际公网路由和手机扫码仍需按用户自己的入口实机核对。

`--smoke-test <输出目录>` 检查导航、开关保存、回填无写入、目录隔离、损坏设置、保存失败、无效 TOML 恢复、目标选择与取消、批量退出、强制确认、仅增强重试、操作锁定、关闭保护和外部变更复核；还创建并移除测试托盘图标，在测试目录创建实际 `.lnk`，核对窗口收起恢复、自动接回、明确启动及单实例转交。连接页另检查真实差异弹窗、确认前无写入、取消保留草稿、实际加密备份、冲突与失效确认、未保存离开选择、HTTP 站点确认、混合连接身份保留和旧 PAT 迁移。生成浅色、深色、紧凑、真实确认弹窗及应用结果截图。测试拒绝混用 `--home`、`--enhanced-launch` 或 `--start-in-tray`。实际 Codex 的增强协议沿用 Core 已有隔离浏览器与原生内核回归；本轮不结束或注入用户的真实 Codex。原生系统文件选择器的人工点击、Explorer 重启、其他 DPI、多显示器和 Windows 10 设备仍需后续实机验收。

模型专项另检查继承值无修改、唯一模型编辑入口与连接摘要同步、行为与审批差异的真实弹窗、原生能力导入及主模型覆盖、专用审核、既有结构化审批不变、官方登录刷新、显式备份只暂存、丢弃清理、请求取消和连接改变后拒绝旧模型列表。模型响应均为内存替身，不使用真实凭据或远端服务。

配置工具专项覆盖字段错误保留、引用名称、父子路径冲突、嵌套敏感值、方案默认选择和撤销、跨目录撤销拒绝、方案库并发/损坏、恢复取消与一次性确认、备份替换、过期记录、中断事务与模型目录依赖。另验证确认后发生的合法管道轮换、注释与账号令牌刷新仍被保留。WinUI 验证真实恢复弹窗、独立方案保存区、分页、字段掩码、导航和离开保护及中断恢复解锁；WPF 原有完整回归也继续运行。

应用层定向测试：`CodexConfig.Tests.exe --application-unit <隔离输出目录>`；登录与模型可单独运行 `--login-model-unit <隔离输出目录>`，字段、方案与恢复使用 `--configuration-tools-unit <隔离输出目录>`，启动项、配置来源及独立 Profile 使用 `--windows-tools-unit <隔离输出目录>`。Windows 工具专项通过内存启动项、替身读取结果和实际加密 Profile 备份验证冲突、取消、敏感值与草稿隔离；不修改真实 Windows Run 项，不运行真实服务进行端到端验证。测试程序对所有专项入口和初始化失败统一捕获异常、输出日志并以退出码 1 结束，避免验证失败时打开 Windows 应用程序错误框；独立子进程用例验证了此退出路径。
