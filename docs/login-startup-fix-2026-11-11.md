# ChatGPT 登录启动修复（2026-11-11）

此页保留历史修复记录。2026-11-12 已按用户要求移除其中的 CLI 登录、设备码与自动回退；当前流程见[官方登录收敛](official-login-convergence-2026-11-12.md)。

本机复现：点击“使用 ChatGPT 登录”后，原生 Codex 立即以 socket 错误 10013 退出，未打开浏览器。回调端口 1455 无法监听。原实现丢弃了 CLI 输出，并在刷新时将登录卡片恢复为未登录说明，使失败原因难以辨认。

修复行为：

- 浏览器回调端口不可用时自动改用原生 `codex login --device-auth`，也可直接选择设备码登录。
- 在登录卡片显示进度、官方登录页面入口和本次设备码；可重新打开浏览器或复制设备码。
- 失败原因保留在登录卡片，取消、完成或重试时清除临时登录信息；退出或切换直连时取消等待。
- 仅识别官方登录 URL、设备码和固定错误类别；原始 CLI 输出、授权 URL、设备码不写入日志或配置预览。
- 登录结果仍在独立目录暂存，需经过现有“查看并确认修改”流程后才写入所选配置目录。

验证：Release 构建零警告、零错误；6 项登录进程回归、4 项程序发现回归、5 项 WPF 登录专项检查通过。测试覆盖 10013 自动切换、显式设备码、浏览器链接、分段与 ANSI 输出、错误脱敏、403 提示、取消后退出及临时文件清理、刷新后错误保留；核对 960×640 浅色与深色截图。

另使用本机真实 Codex 0.167.0-alpha.4.1 验证自动切换并成功取得官方设备登录链接与设备码，随后取消，未代替用户完成账号授权。整套旧 WPF 回归在测试网关后台进程识别环节失败，因此本轮只将登录专项记为通过。

此为 Windows 0.17.1 本机登录热修复，未发布新的 GitHub Release。运行文件改动仅为 CodexDock.dll 与 CodexConfig.Core.dll；旧文件和 SHA-256 清单随热修复记录保留，可用于回退。

官方登录机制参考：https://learn.chatgpt.com/docs/auth
