# Android 0.2.4 应用内更新审查

本轮将原先只打开网页的“版本与更新”接入本项目 GitHub Release。Android 版本为 0.2.4 / versionCode 7，Windows 保持 0.16.2。

## 来源与安装边界

独立的 Android `MobileRelease` 适配器只接受 `Lovest20018/Codex-Dock` 仓库的 `android-v<数字版本>` 正式版本、完全匹配的 APK 文件名与下载 URL；不会使用指向 Windows 的 `/releases/latest`。版本按数字比较，拒绝草稿、预发布、当前版本和降级。元数据读取有大小和超时限制，下载地址重定向仅允许指定 GitHub HTTPS 域名。

复用已固定上游的下载器与待安装会话，下载必须提供有效长度及 SHA-256，支持暂停、继续与明确取消。更新请求独立于电脑账号，不向 GitHub 或附件 CDN 发送电脑 Cookie。待安装记录只位于应用私有目录，恢复时重新验证长度和摘要，安装成功后的同版本记录自动清理。

交给系统安装器前重新校验摘要，核对包名、versionName、更大的 versionCode，以及固定的既有证书 SHA-256。新增 `REQUEST_INSTALL_PACKAGES` 权限用于系统确认流程；首次按系统设置授权，用户拒绝可保留下载后重试。APK 通过现有只读内容提供器授予临时读取权限。不会卸载应用或改写电脑连接、登录和草稿。

## 验证

主机 Java 回归 33 项通过，覆盖 Android/Windows 标签选择、版本排序、降级和预发布排除、URL 与重定向限制、缺失摘要及超大文件拒绝、待安装会话恢复、重复回调、权限返回和损坏文件拒绝；发布 CI 执行同一入口。

独立 instrumentation 在隔离 Android 14 模拟器中运行生产更新代码，18 项检查通过。只存在于测试 APK 的网络替身和签名安装包夹具覆盖最新版本、网络错误后重试、新版检查不打开浏览器、摘要校验、拒绝不可信跳转、安装包身份、拒绝错误证书、安装权限、待安装恢复、安装器交接及真实系统安装确认页；生产 APK 不包含这些替身和测试安装包。完整导航、草稿、剪贴板、下载和通知回归 72 项通过，验证从 0.2.3 覆盖升级；原下载器 61 项检查和发布脚本 13 项回归通过，工作流语法校验通过。

正式包从干净提交生成，沿用固定签名证书，校验非调试 APK、v2/v3 签名、源码输入和发布附件摘要；实际提交、大小和 SHA-256 记录在发布 manifest。实体手机、厂商安装策略及手机公网链路未作为本轮通过的证据。
