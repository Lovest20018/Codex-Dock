## 已配置、来源与 profile

**全部配置 → 已配置** 展开文件和草稿中的具体路径，保留多个实例、含点名称、未知字段、显式 false 与删除草稿。**更多选项 → 添加 MCP / 供应商 / 权限方案** 提供对应表单；新权限方案不会自动设为默认，自定义供应商不能新建为内置 provider ID。行内“取消本文件覆盖”明确执行删除该文件值。

展开 **来源与 profile**，选择本机原生 `codex.exe` 和项目目录，点击 **读取配置来源**。独立短时 app-server 仅执行初始化和 `config/read(includeLayers, cwd)`；页面显示本文件值、执行端读取值、来源层、作用端和读取时间。嵌套凭据及带认证参数的 URL 会遮盖，未知来源保持未知。可重新读取本地模型目录，查看来源与更新时间；推理 / 档位选项采用所选模型已声明能力，不推断 Fast 支持，也不验证远端实际能力。

**管理 Profile 文件** 使用 `$CODEX_HOME/<名称>.config.toml`。普通模型与行为设置独立预览、保存、加密备份和恢复，支持冲突检测与关闭草稿处理；认证、路由、MCP 和权限不在此编辑器修改，原有其他字段原样保留。保存后通过 `codex --profile <名称>` 选择，不会自动切换当前聊天或主配置。

当前核查内核明确拒绝在 app-server 使用 `--profile`。主配置和项目层来源已用实际原生执行端验证；指定 profile 的生效来源显示“未确认”，没有退回主配置并冒充 profile 结果。来源快照也不包含已有聊天的会话参数、未保存草稿或所有组织强制要求。

## 压缩与连接诊断

模型网关识别旧 `/compact` 和普通 `/responses` 请求中的 v2 `compaction_trigger`，覆盖 HTTP JSON、SSE 与 WebSocket，包括分片消息。状态区区分配置允许的协议、客户端请求、返回 compaction 条目与确认成功完成次数；HTTP 200 不能单独计为压缩成功。条目与完成事件分别去重，最近触发协议与最近成功协议分开记录。

增加等待 / 活跃请求数、队列等待、上游响应头、首数据与总耗时，以及完整转发、上游错误、断流、超时和握手失败等结束原因。现有并发、大小和超时限制未调整。

指标仅在当前网关进程内存中保留计数、时间和固定标签，不落盘保存聊天、压缩正文或凭据。单个响应事件检查缓存上限 **2 MiB**；超大或不可解析事件仍原样转发，并增加“无法完整检查”计数。统计只覆盖经过此网关的流量，网关重启后重新累计；不能据此证明直连、其他进程或最近真实 Krill 压缩成功。
