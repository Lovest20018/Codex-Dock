# Android 0.2.2 输入区修复与验收

用户截图中，模型栏右侧箭头朝上、高级选项展开、文字输入与发送区域消失，与生产页面 `composer-body.hidden` 的折叠状态一致。默认比例下，原 0.2.1 的连续发送并未自动复现此状态；通过原折叠入口可重现相同外观。尚未锁定该手机在发送时触发折叠的事件顺序，本次按手机输入区始终展开的交互规则修复。

## 修改

APK 自有 `lovest-shell.js` 隐藏并阻止文字输入区的折叠入口。发现旧折叠状态后，优先通过原呈现控制器恢复展开，同时保持样式类与无障碍状态一致，保留阅读位置。高级“选项”仍独立展开和收起；没有改变文字发送、草稿、账号、权限或服务端接口。注入仅在原生版本握手成功后启用，不改变旧页面的回退入口。

Windows 版本仍为 0.15.1；固定上游 1,264 个文件和七项覆盖未修改。Android 使用 versionName 0.2.2 / versionCode 5，沿用包名、签名和 Logo。

## 验证

- Android 14 隔离模拟器的完整检查为 57 项，包含网关登录、桥接拒绝、导航、草稿、下载、通知、重启、横屏、320dp 和 130% WebView 文字。
- 直接安装实际 APK，在生产页面使用触摸点击真实发送按钮；测试传输拦截为确认结果，不发起真实模型任务。
- 展开高级选项后连续发送三次，分别核对输入区和发送按钮在键盘弹出、收起及长回复后的可见范围。另恢复旧折叠状态，确认文字输入、折叠样式和 `aria-expanded` 一致恢复，选项状态保留。
- 生产状态渲染器补充“运行中”的状态与停止按钮，以覆盖用户截图中的任务阶段。
- 从正式 0.2.1 覆盖安装，核对连接、主题与持久化标记保留。生产 APK 排除两个测试脚本、测试类和签名私钥。

正式构建来自干净提交，包旁 manifest、验证 JSON 与 SHA-256 记录对应的实际输入和文件。相机扫码、厂商键盘、真机缩放、公网和真实模型任务仍须在对应环境验证。
