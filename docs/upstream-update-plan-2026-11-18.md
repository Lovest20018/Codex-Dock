# 上游更新实施清单（2026-11-18）

建议按三个交付批次推进：**先完成 Windows 模型与连接可靠性，再做诊断和桌面兼容，最后做手机体验**。每批独立提交、测试和打包；当前主模型保存修复作为独立的 0.19.2 本地包交付，其他项目仍为后续实施计划。

本清单依据 [Codex++ 2.7.2](https://github.com/BigPizzaV3/CodexPlusPlus/releases/tag/v2.7.2)、[Superba 0.1.2-alpha.3](https://github.com/krill-lab/superba/releases/tag/v0.1.2-alpha.3) 和 [Codex Mobile Bridge 2.2.1](https://github.com/try2love/codex-mobile-bridge/releases/tag/v2.2.1)。固定提交、源码差异与已有功能对照见[完整评估](upstream-reuse-review-2026-11-18.md)。Codex++ 的 main 另有 16 次未发布提交，单独列为候选，不与 2.7.2 混算。

## 第一批：Windows 必要修复与资料

| 编号 | 更新项 | 来源与原因 | 实施范围 | 验收条件 |
| --- | --- | --- | --- | --- |
| W1 | **新模型能力刷新与固定审核同时保存** | Superba 的模型快照刷新思路；当前服务新增加 `gpt-6.2-sol`，旧受管目录缺少映射。 | 已在 0.19.2 实现：服务原生能力先暂存，与模型、审批覆盖一起确认和备份；只在用户已固定或主动勾选专用审核时更新映射。 | 新模型可以保存；固定 `codex-auto-review` 保留；不推断缺失能力、不启用未选择的固定审核；取消、换连接、外部冲突和回滚均保留原状态。 |
| W2 | **启动 Codex 的回环代理排除** | **Codex++ 2.7.2，优先复用。** 本地模型网关可能被继承代理或 Windows 代理配置接管。 | 合并子进程环境的 `NO_PROXY`；保留用户原排除项。未设置时保留启用的 WinINET `ProxyOverride` 语义，再补 localhost、IPv4/IPv6 回环。覆盖打开、重启和独立资料启动的共同入口。 | 本机网关始终直连；原有内网例外不丢失；外部服务仍遵守已选代理；不修改用户全局环境或注册表。 |
| W3 | **Windows 原生执行端发现与匹配副本** | Superba alpha.2；部分商店安装不再生成旧位置的 Codex 副本。 | 统一查找运行内核、PATH、商店包与明确选定的安装位置；必要时才复制匹配内核及 helper。GUI 启动继续使用已有安装身份/执行别名。 | 没有旧副本时仍可读取模型、配置来源和功能列表；逐文件大小与 SHA-256 匹配；商店升级不沿用过期内核；错误有具体修复入口。 |
| W4 | **配置资料、中文说明与常用项更新** | Superba 更新到 Codex 0.171.0-alpha.5，并保留桌面内核版本。 | 依据官方 schema 更新本地字段、枚举、版本标记及中文解释；补子代理、终端等待、压缩和审批等常用分类；保留 Dock 自己的约束与草稿流程。 | 新字段可查、版本清楚；旧字段保留可解释；升级和浏览资料不自动写配置、不把新版默认值带入旧内核。 |

推荐先做 **W2 → W3 → W4**。W1 单独交付，便于立即解决当前保存问题。W3 的复制缓存按实际系统条件启用，先验证当前安装能否直接执行，避免所有用户都额外复制大体积内核。

## 第三批：手机端的可见收益

手机工作台确实来源于 Codex Mobile Bridge。当前基础为 2.1.7，叠加 2.2.0/2.2.1 的 **31 项 overlay**。v13 基础兼容、连接恢复、模型失败保留草稿及账号隔离已经移植，不重做整库升级。

| 编号 | 更新项 | 修改范围 | 验收条件 |
| --- | --- | --- | --- |
| M1 | **聊天内 visualize 交互图表** | 网关的会话授权接口、预览资源及隔离壳、Web 渲染、自有安卓全屏导航；保留当前原生三页外壳。 | 重新打开聊天恢复图表状态；手机竖横屏/全屏返回正常；图表追问只进入草稿；跨会话资源、CSP、sandbox 和鉴权检查通过。 |
| M2 | **`/` 命令菜单、可空聊天名称、消息时间** | 适配当前 Codex 能力与现有输入框；不引入其他客户端的命令。 | IME 不误提交；创建幂等；操作结果不明不重发；手机与宽屏、中英文均可用。 |
| M3 | **安卓探测取消与返回补测** | 先核对自有 MainActivity、ConnectionDiscovery 的现有时限、generation 和取消处理；只补确认的缺口。 | 连接探测中能返回电脑列表；迟到响应不拉回旧页面；设备撤销和失效凭据不恢复旧绑定；离线可重新选择电脑。 |
| M4 | **v13 附属会话与延迟输出专项** | 单独核对 `attachedToThreadId` 归属、`deferredOutputTurnId` 正文补取及侧聊生命周期。 | 主/附属会话身份和工作目录不混用，分页不漏/重消息；旧版本可读历史，未知关键结构保留草稿并停止控制。 |

顺序建议 **M3 核验 → M1 → M2 → M4**。M1 需要网关与自有 APK 配套；既有安卓包名、签名和数据继续保留，不用上游 APK 替换。M4 的复杂度独立于普通 UI 改进，不塞进图表批次。

## 暂不安排或无需重复移植

- Codex++ 的 WebSocket 续接修复：Dock 已原字节转发 `previous_response_id` 与工具结果；保留针对性回归，不引入它的订阅请求转换器。
- 官方模型上下文：继续尊重明确配置和服务原生能力；不把上游示例中的 272K/500K 写成所有用户的默认值。
- Codex++ main 的低价压缩模型、图片改发模型、自定义请求头和微信专注会话：尚未发布，且扩大当前产品范围。后续若有具体需求再单独规划。
- Superba 多官方账号、会话迁盘、每轮消息预测与上传失败重发：单独评估其凭据、恢复或请求行为，不随本次可靠性修复带入。
- 手机其他 AI 客户端、多信道部署、项目外文件浏览及批量 CLI 释放：保留现有 Codex-only、固定 HTTPS 入口和未知写入不重放规则。

## 每批交付要求

1. 在同一源码提交上跑相关核心、窗口和协议回归；生成本地可覆盖安装包，核对实际包内程序集。
2. Windows 检查配置、登录、受管目录、备份与现有手机后台；手机改动另外核验上游逐文件清单及自有 APK 身份。
3. 在隔离目录验证升级、回退、取消、断线和外部变更。源码与安装包做隐私扫描和 SHA-256；真实设备与公网未验收部分单列。
4. 每批注明已实现、已测试及适用的桌面/内核版本。更新安装与发布仍按后续明确安排进行，不自动安装到用户正在使用的目录。
