# 0.19.6 验收记录

本批基于 0.19.5，覆盖 [手机与 Windows 联合方案](simple-workflows-and-upstream-plan-2026-11-18.md) 的第二批诊断及第三批手机工作。两批共用一份本地 Windows 安装包，手机端另提供 Lovest Code 0.2.6。

| 项目 | 实现与验收范围 |
| --- | --- |
| D1 · 最终响应 ID | 回环模型网关覆盖完整 HTTP、SSE、WebSocket 完成事件、取消、失败、截断及重用连接。请求 ID 单独显示。诊断只记录有界元数据。 |
| D2 · 纯 API Key 分支 | 隔离商店版使用虚构 API Key 和回环模型，独立 Electron 资料目录。分支适配以能复现 execution-config-loading 为前提。 |
| D3 · Windows 沙箱状态 | 隔离商店版冷启动和正常重启后读取原生查询。状态检查与沙箱自身安装结果分别记录。 |
| M1 · 图表 | 交互 HTML 使用受鉴权的固定预览壳，源文件按当前 host、聊天引用和工作目录核验。状态使用登录、会话、消息和内容摘要的范围键。追问复用草稿入口。 |
| M2 · 聊天操作 | 命令调用现有且当前可用的界面。桌面空标题使用独立运行时持久化后复读，CLI 和 WSL 沿用可落盘的默认名称。前端先查创建回执，再决定是否允许用同一请求重试。 |
| M3 · 配对与探测 | Windows 可在原页保存并准备配对，分别显示入口、扫码与 Codex 接入状态。Android 的返回操作取消当前探测，迟到结果不能驱动旧页面。 |
| M4 · 附属与延迟输出 | 附属关系来自原生存储，按 host 和资料目录核对。展开输出才调用 thread/items/read，按 thread、turn、item 和类型校验，复用分页。v11 继续按既有方式读取历史，未知的控制关键结构会使新版实时快照停在只读状态。 |

手机上游基线仍为 2.1.7，本轮选择移植 2.2.1 的图表、输入和时间相关工作。基线摘要、改动摘要和对应的上游摘要分别记录在 upstream-manifest.json 和 upstream-overlay.json。附属列表使用现有标准聊天控制器，创建临时侧聊沿用原有入口。

本地交付限于隔离的 Windows、浏览器和模拟器验证。正式发布、实体手机和公网 HTTPS 使用独立验收环境。
