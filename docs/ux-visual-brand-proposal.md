# Codex Dock：UX、视觉与品牌修改方案

2026-10-28 · 设计提案，承接 `ui-restructure-proposal.md`。本次只产出方案与设计稿，不直接替换正在运行的软件名称、图标或配置。

## 一、名称建议

**推荐：Codex Dock**

- 显示名称：Codex Dock；不在导航与标题栏混用多个中英文品牌。
- 中文副标题：本地连接与配置中心。
- 语义：Dock 是连接、停靠与集中管理的地方，适合当前的账号身份、模型入口、本地网关、代理和配置管理。
- 相比 Codex Config，不再把软件限定为静态配置文件编辑器；相比 Gateway，不会让用户误以为它只有转发功能。
- 保留现有用户熟悉的 Codex 关联，但使用自己的图形标识，不模仿 OpenAI 标识。“关于”页明确为独立工具，避免暗示官方产品关系。

两个备选：

| 名称 | 侧重点 | 取舍 |
| --- | --- | --- |
| Codex Dock | 连接与管理 | 推荐；覆盖当前功能，名称简短 |
| Codex Bridge | 网关、转发 | 易理解，但弱化配置与模板能力 |
| 栈桥 / StackPier | 独立中文品牌 | 品牌独立性强，但初次看到时不容易知道服务于 Codex |

以上是产品命名提案，尚未完成同名项目、域名或商标可用性核查；不据此宣称名称具有独占性。

## 二、Logo 修改

### 当前标识的问题

原标识以紫色圆角底、左右代码括号和中间滑块构成，重点表达“代码配置”。新增网关与托盘后，小尺寸中括号、滑块和圆点互相挤压，视觉语义也偏向代码编辑。

### 推荐图形：停靠接口

使用一个简化的 U 形承接结构，配一条从右侧接入的短连接条：承接结构代表集中管理，接入条代表模型与网络连接。图形不直接描绘船、锚或网络拓扑，避免小尺寸复杂化。

- 应用图标：深石墨蓝圆角底 + 白色承接结构 + 青蓝连接条。
- 界面品牌区：24–28 DIP 图标 + Codex Dock 字标；不常驻副标题。
- 托盘：独立设计单色 16/20 px 版本，不把彩色大图简单压缩后使用。连接状态另用托盘提示和菜单文字表达。
- 状态指示不是 Logo 的一部分：绿色仅表示有证据的运行状态，不能把品牌青蓝连接条当成“在线”灯。
- 安装器与关于页：可使用图标、字标和中文副标题组合。
- 单色版用于浅色/深色托盘。纯白版在深色底，深石墨版在浅色底。
- 安全留白至少为图标边长的 1/8；不加渐变、投影、光晕、代码花纹或细小文字。

本次提供 SVG、WPF DrawingImage、16–512 px PNG、单色托盘预览和 ICO 草案。它们存放在提案目录，尚未覆盖现有品牌资源。

## 三、视觉方向

**推荐“安静的桌面控制台”**：让状态和操作清楚，保持表单密度，减少重复卡片和说明文字。

配套草图包含两种布局：

- **状态总览**：连接链路在上方，身份、模型和网关按阅读顺序展开。更适合默认首页，推荐采用。
- **操作工作台**：主区域展示连接配置摘要，右侧常驻窄网关运行区。适合频繁切换模型与网络的用户，但在小窗口需要折叠，作为布局备选。

两者沿用同一导航和数据语义，不发展成两套产品。

### 颜色令牌

| 用途 | 浅色 | 深色 |
| --- | --- | --- |
| 内容底色 | #FFFFFF | #1D2025 |
| 应用背景 / 导航底色 | #F4F6F8 | #171A1F |
| 次级底色 | #EEF2F6 | #262C34 |
| 主文字 | #202A36 | #E8EDF3 |
| 次级文字 | #596779 | #A8B4C3 |
| 分隔线 | #DDE3EB | #38424E |
| 主操作蓝 | #245CC5 | #9BBEFF |
| 选中底色 | #EAF1FE | #273951 |
| 成功状态 | #247044 | #8AD2A6 |
| 需注意状态 | #865C12 | #E6C47A |
| 错误状态 | #B43434 | #FFA3A3 |

品牌图标的青蓝色只用于标识，不蔓延到所有按钮。浅色主按钮用蓝底白字，深色主按钮用浅蓝底深字；正式实施时逐项检测文字与背景的对比度。

### 字体与尺寸

- 继续使用 Windows 系统字体回退；中文优先 Microsoft YaHei UI，英文 Segoe UI；地址和字段路径用 Consolas。
- 页标题 24 DIP / 半粗；分区标题 16 DIP / 半粗；正文和表单 14 DIP；辅助文字 12 DIP；不使用小于 12 DIP 的业务说明。
- 控件高度 36–40 DIP；表单项间距 16 DIP；区域间距 24–28 DIP；标题与内容间距 20 DIP。
- 普通输入和按钮圆角 6 DIP，必要的状态容器圆角 8 DIP；不将每个字段都放入卡片。
- 页内一个主要操作组只突出一个主按钮，其余动作使用普通按钮或文字按钮。红色只用于实际破坏性操作或错误，不给普通“停止网关”默认涂红。

## 四、桌面布局修改

### 窗口外壳

保留原生 Windows 标题栏和系统最小化/最大化/关闭按钮。窗口标题改为 Codex Dock，不重新实现一套标题栏交互。

左导航保持约 192 DIP，分为“日常使用”和“配置管理”。底部仅放网关摘要与应用设置入口。顶部内容栏显示配置目录和目录切换；目录用中间省略、完整路径提示和复制入口，避免标题栏被长路径撑满。

默认窗口建议 1180×800 DIP；支持 960×640。小窗口下两列合并，不把整套界面缩小。每页只保留一个主要纵向滚动区域；保存栏固定在内容区域底部，避免出现相互争抢滚轮的卡片内滚动。

### 首页

- 页标题“概览”，副标题压缩为一句或省略。
- 顶部状态行：当前连接方式、网关状态、最近检查时间；不使用大尺寸 KPI 数字。
- 路由区：Codex → 本地网关 → 模型服务。官方身份单独作为关联信息呈现，避免暗示 OAuth 被转发给模型服务。
- 下方为紧凑的连接摘要与快捷入口。只对真实问题展示提示条，如网关停止、代理缺失或文件冲突。
- “运行中”明确指本地监听；上游未测试就显示“未检测”。默认模型旁标注“配置值”，避免暗示所有正在运行的 Codex 会话已经切换。

### 表单页面

左侧字段名宽 132–148 DIP，右侧输入区域保持一致。连接页按“方式 / 官方身份 / 模型服务”分区，混合模式才展开身份区。

已保存凭据只显示“已保存”，编辑时再提供输入；显示明文按钮与凭据输入邻接。账号卡不展示没有可靠来源的套餐、额度或头像。

模型页集中放默认模型与速度，Fast 入口开关和服务档位以两个明确字段呈现。字段说明先给一句用途，再按需展开技术细节。

### 网关页

运行条与启停按钮位于首屏；本地地址提供复制。紧接着是代理方式、检测到的地址和来源；计数放到默认折叠的“本次运行详情”。

“当前已保存：直连”和“待保存：使用代理”在同一区域呈现。草稿不触发真实网络变化；启停操作不进入草稿。长篇窗口关闭说明迁到应用设置，只保留必要的托盘提示。

### 模板、备份和高级配置

模板用紧凑列表 + 详情视图，优先查看差异；详情无需套三层卡片。模板的“保存模板”与全局“保存配置”位置和措辞不同。

备份展示目前引擎支持的最近恢复点，保持准确的恢复范围说明。高级配置继续使用紧凑列表、分类与搜索，当前文件值/草稿值分列或用相邻对照表达。

## 五、UX 状态与反馈

| 场景 | 展示与动作 |
| --- | --- |
| 初次使用 | 首页显示“设置连接”，介绍两种模式；可直接前往编辑已有配置 |
| 正在检查 | 中性“检查中”，保留上次结果时间；不先显示失败 |
| 本地健康成功 | “网关运行中”，不推断上游能力 |
| 健康超时 | “暂时无法确认”，提供重试；不直接写“已停止” |
| 代理未检测到 | 地址区域给出下一步：启用系统代理后重新检测 |
| 有草稿 | 底栏显示数量与涉及页面；侧边导航相应项加小圆点，并有可读文本 |
| 保存成功 | 就地反馈保存范围及加载要求，不一律声称已生效 |
| 保存失败 | 保留草稿，展示外部修改/回滚结果与下一步 |
| 关闭窗口 | 收起到托盘，草稿保留；首次收起可显示一次非打断提示 |
| 退出程序 | 有草稿先处理，再停止网关；停止失败时留在应用并提供重试 |

对长耗时动作使用按钮内忙碌态和短文本；禁止重复提交，但不禁用与操作无关的导航和查看功能。默认不播放动画；必要的状态变化只使用短促反馈，遵循系统减少动画偏好。

### 草稿与差异

无草稿时隐藏底栏。有草稿时显示“未保存 3 项 · 模型、网络”，主操作“保存配置”，次操作“查看更改”“放弃修改”。查看更改打开约 480–560 DIP 的右侧抽屉，按页面分组，底部仍能触达保存。

所有敏感值统一脱敏。不是每个页面单独保存，沿用现有配置事务、备份和回滚机制。应用模板后提供“撤销本次模板”，与“放弃所有修改”分开。

## 六、名称与图标的实施范围

第一阶段只改显示层：窗口标题、导航品牌、托盘提示、关于页、安装器展示名、快捷方式名称、图标和说明文档。

保留现有配置格式、保留的 provider ID、DPAPI entropy、备份识别和数据目录。尤其不能仅因改名变更 `CodexConfig.mixed.v1`，否则既有加密连接会无法解密。

`CodexConfig.exe` 与内部程序集名可在首版继续保留；是否改为 `CodexDock.exe` 属于安装升级工作，需验证旧快捷方式、更新路径和单实例处理后再做。不能只改文件名就宣称完成迁移。

## 七、交付与验收

1. **视觉基础**：确认名称、标识、颜色、控件密度；建立浅/深色资源与图标尺寸规范。
2. **主路径**：实现概览、连接与账号、模型与行为、网关与网络，以及统一草稿栏。
3. **管理与桌面行为**：迁移模板与备份、全部配置和应用设置，完成托盘、键盘、缩放与安装展示检查。

验收要求：960×640、1180×800、125%/150% 缩放下无遮挡；深浅色文字可读；托盘 16/20 px 清晰；键盘可操作全部主流程；健康状态不误导；运行值与草稿分离；旧认证、加密连接、模板和备份能继续使用。

配套图稿均为设计提案。示例地址、状态与操作只帮助讨论布局，不连接真实网关。
