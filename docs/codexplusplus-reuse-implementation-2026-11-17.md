# Codex++ 2.7.1 方案复用与验证

本轮按 [复用评估](codexplusplus-reuse-review-2026-11-17.md) 实现三项 Windows 能力：按连接保存 HTTP 响应头等待、保留普通模型目录声明的能力，以及读取实验功能并通过现有草稿确认流程修改。压缩兼容完成独立原型与本机内核边界验证，产品继续透明转发；手机设备权限留在安卓阶段。

参考版本固定为 Codex++ 2.7.1、提交 `d5dcad3b3b9d1ef1dc83ba76a3b8f4c4098d2abe`。复用的是能力与约束设计，当前实现使用现有 C# Core、共享应用层与 WinUI 控件；没有引入其 Rust 服务或页面注入运行时。

## HTTP 响应等待

在“Codex 配置 → 连接”选择“官方账号 + API”后，可设置模型网关等待响应头的秒数，默认 **120**，范围 **60–3600**。输入先进入连接草稿；保存确认明确列出前后秒数，确认后与现有连接详情一起加密保存和备份。只改等待时间会保留原生配置、账号、网关端口和本地身份。

该设置只作用于经过本网关的 HTTP 请求。建立连接最多 30 秒；收到响应头后结束响应头计时，后续每次数据到达会重新开始独立的 5 分钟空闲计时。目录响应和错误响应也遵守这个数据间隔规则。直连请求由 Codex 自己管理，WebSocket 沿用原有握手及空闲规则。

每个请求固定采用开始转发时的设置，保存变化不会缩短已经进行的请求。新版后台协议为 8；从旧预览换用本包后，需要通过模型网关页重启旧后台，才能由新进程使用新等待逻辑。仅保存配置不会主动结束用户现有请求。

响应头超时与流空闲超时有不同错误码及诊断结束原因。断开客户端会取消对应上游，不自动重发模型请求；上游错误正文与凭据不进入界面诊断。

## 普通模型目录的能力

`data/id` 等普通目录转换为原生目录时，现在保留有效声明的文本/图片输入、上下文窗口、推理选项、默认推理、服务档位及有限的布尔能力。采用字段白名单、类型与长度上限；未提供或格式无效的能力不补成支持，未知字段不复制。原生 `slug/supported_reasoning_levels` 描述继续保留未来元数据。

这是目录转换行为的修复，不证明服务端真正支持某项能力，也不自动开启 Fast、图片或 1M 上下文。界面选择和实际调用仍受当前模型与服务约束。

## 实验功能支持与观察值

入口位于“诊断与恢复 → 配置来源”的“实验功能支持与观察值”。先明确选择本机执行端、项目、配置目录和可选 Profile，再点击读取。读取启动一个短时独立 `app-server`，只发送初始化和分页 `experimentalFeature/list`；支持取消，最多 20 秒、20 页、2000 项。没有自动读取、聊天、轮次、登录或工具调用。

页面分别展示执行端观察值、执行端报告的默认值、主配置已保存值与当前主配置草稿。遗漏的开关显示“未提供”，不当作关闭；未知和已移除阶段不提供快捷修改。带点号等复杂名称允许只读显示，并按完整名称引用，避免误改为另一个嵌套配置。

已确认阶段的普通布尔项可选择开启、关闭或移除主配置覆盖，只加入同一份主配置草稿。现有结构化值保留，需到配置编辑器核对。选择 Profile 时只读观察，避免把 Profile 的运行值误写进主配置。条件、配置或目录发生变化时拒绝旧结果；保存或恢复会清除旧观察，必须再次明确读取。

修改继续使用原有查看差异、取消、加密备份与确认保存流程。保存后的重新读取只证明**新启动的所选执行端**读到了什么，不代表已经运行的桌面实例、远程开关或现有聊天采用了该值；桌面应用仍由原有独立操作完成。

## 压缩兼容边界

本轮在新建隔离目录中运行本机 `0.169.0-alpha.11.1` 内核，所有模型和账号接口均指向回环替身，环境中不继承真实密钥。三个原生案例均符合预期：原生 V2 压缩成功；明确的 422 能力拒绝导致失败；带自有标记的本地摘要可被内核接收，并在保留翻译器时接续，但模拟移除翻译器后，后续请求会继续携带该标记并被替身拒绝。

这个原型只验证协议和历史依赖，摘要内容由替身固定生成，未验证真实模型的摘要质量。空摘要、未完整结束、失败状态均拒绝变成检查点；单独的合成工具调用与结果配对保持原样；未知密文不被伪装成可读历史。本轮没有执行 Codex++ 的上游运行时代码。

因此按方案保留产品透明转发：不偷偷移除触发项，不生成需要持续翻译的产品历史，也不以占位提示替代无法读取的密文。Core 回归覆盖 400/422 明确拒绝、无关 400、原生成功和未完成流，验证请求中的工具历史及密文原样抵达替身，且不增加重试或伪造完成事件。完整降级若后续实施，还需明确持久格式、切换供应商后的读写规则与恢复机制。

## 验证范围

本轮的产物与报告位于 `artifacts/upstream-reuse-2026-11-17/`。完整 Core/应用层 362 项、WPF 兼容窗口 309 项、WinUI 完整窗口 423 项均通过。Core 包含新增的 17 项专项，WinUI 包含新增的 18 项等待设置、读取/取消、分页、只读 Profile、草稿、保存与重新读取检查；三套程序的 Core 与共享应用层 DLL 摘要一致。本机实际执行端只读列出了 215 项功能，配置字节不变，未创建聊天或登录。

首次完整 Core 回归有一项旧原生窗口重启超时；串行、正常桌面权限下完整复验 362 项通过，未改动产品退出逻辑。WPF 首次停在旧文案断言，改为检查真实草稿内容与目标文件后完整复验 309 项通过。原始失败记录均保留。预览 ZIP 的逐文件清单、SHA-256 与解压迁移检查以同目录 `archive-verification.json` 为准。

本包是版本基线为 0.18.0 的未提交预览快照，不是正式安装器。真实模型服务、已登录活动聊天、Windows 登录启动、Windows 10、其他物理 DPI 与安卓设备验收没有在本轮重新完成。
