# Android 0.2.5 审查与验证

0.2.5 仅更新自有图标资源及版本标识，版本名 0.2.5、versionCode 8，包名仍为 `io.github.lovest20018.codexdock`。Java 连接、认证、草稿、通知、更新逻辑与 0.2.4 保持当前实现。

## 图标与构建

选定的形状和颜色由 `assets/brand-refresh-20261117/selected.json` 定义，`scripts/apply-brand.ps1` 生成 Windows 与安卓资源。安卓覆盖层包含应用内图标、108dp 自适应前景、浅绿背景、API 33 单色层与白色透明通知图。固定上游资源未原地替换，构建时只覆盖自有资源。

Android 14 模拟器中的独立资源探针已通过 13 项检查，包含自适应 drawable、中央安全区、前景尺寸、配色、单色和通知透明度。当前生产 Java 在独立 QA 身份下通过 72 项完整连接/导航/草稿/通知检查与 22 项活动任务追加检查；测试包运行后卸载，临时证书不参与发布。

## 正式 APK

CI 从干净提交构建，恢复仓库已有发布签名，结束后清除签名材料。发布检查固定证书 SHA-256 为 `0c31e8dc7e29b7e835343db7551df5a505498959e87d4462f1b6bd9b5e72098e`，要求 v2/v3、非调试状态、版本与 manifest 一致，以及所有源码输入摘要一致。APK 不包含测试 instrumentation、测试 JS、测试升级包或私钥。

签名与相同包名允许直接覆盖旧版；最终 APK 摘要与签名结果在 `LovestCode-Android-0.2.5.manifest.json` 记录，发布附件包含源码和 SHA-256。不得把 QA 签名或重打包旧 APK 当成可覆盖的正式升级文件。

## 边界

保留原应用数据目录；不增加权限、不切换上游包名、不导入多信道架构。图标更新不要求重新登记 HTTPS 入口。Window 手机服务与 Web 页面随 Windows 0.19.0 更新。

模拟器不代表所有启动器、主题引擎、厂商省电行为或相机扫码；公网 HTTPS、真实模型和实体设备的最终效果需相应环境核对。先前本地缺少原签名不影响本次 CI 使用已有签名 Secret，签名材料不下载到本地工作区。
