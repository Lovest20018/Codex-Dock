# 0.12.1 Codex 程序发现修复

0.12.0 仅在进程 PATH 与 `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin` 查找 `codex.exe`。桌面版可将原生运行时放在 `%LOCALAPPDATA%\OpenAI\Codex\bin\<版本目录>`；npm 通常在 PATH 暴露 cmd/PowerShell 包装器，原生 EXE 位于平台依赖包。原逻辑漏掉这两种布局，且错误提示没有展开所要求的选择控件。

新的发现器按正在运行的原生 CLI、PATH、桌面版运行时、独立 CLI、npm 的顺序查找。正在运行的桌面 GUI 不作为原生 CLI；候选必须为可访问文件。PATH 同时读取当前进程、用户与系统值，忽略空/相对项。桌面运行时只枚举已知 bin 目录的一层；npm 只检查已知原生包布局，支持当前 bin 与旧 codex 子目录。不启动 npm、shell 包装脚本或候选程序来探测，不下载或安装 Codex，不遍历 WindowsApps 或整个磁盘。

登录前异步查找并将实际路径显示在界面。无法发现或用户指定路径无效时，展开程序位置、滚动至该处并聚焦输入框，再显示可操作的错误。该路径不属于 Codex 连接草稿，发现程序不会改写认证、模型地址、用户环境或配置文件。

验证：

- 78 项核心回归通过，其中四项使用隔离假文件覆盖纯桌面安装与原生进程优先、npm 包装器安装、旧 vendor/自定义前缀/带引号 PATH，以及候选缺失；假程序从不执行。
- 实际用户环境中，默认发现与 PATH 为空的发现均返回桌面版原生运行时，`--version` 返回 `codex-cli 0.166.0-alpha.5.1`。该检查不登录、不读取令牌、不访问模型入口。
- 界面回归新增两项：自动路径显示，以及发现失败时自动展开程序选择。使用注入的假路径，不扫描真实程序或打开浏览器登录。
- 发布程序、隔离安装程序、包内隐私与散列由现有脚本验证；0.12.0 的真实模型能力边界保持，未因此重新声明任何工具或模型能力通过。

OpenAI Docs 的 [Windows 部署说明](https://learn.chatgpt.com/docs/enterprise/windows-deployment) 区分独立安装与 npm，并要求保留完整运行时。本机 npm 包装器源码确认了当前平台包下 `vendor/<target>/bin/codex.exe` 布局，旧布局作为兼容候选。原生桌面运行时位置由本机实际进程路径确认。
