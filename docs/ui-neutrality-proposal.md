# Codex Config 界面与配置模板优化方案

状态：已按此方案实施 0.7.0。本文保留最初基于 0.6.1 的问题分析与设计依据；交付说明见 `release-0.7.0.md`。

补充：2026-10-27 增加“配置说明与作用解释”，核对 OpenAI 官方文档后修正 Fast 模式和旧实验项的说明要求。下文原有七项表格记录的是现有模板，不应视为已验证适用于当前所有版本。

## 产品定位

Codex Config 是通用本地配置编辑器。服务商作为可选连接预设出现，社区配方作为可选配置模板出现。保留 Krill 用户已有的便利与兼容行为，但不让某一家服务商定义软件首页、全局分类或默认操作。

## 当前情况

1. 界面已经使用灰白底色、蓝色强调色与独立 Codex Config 图标。品牌偏向主要来自内容、导航和默认流程，无需重新设计整套配色。
2. 启动默认打开连接页；该页始终放置“应用 Krill 推荐配置”按钮、说明和推荐项展开区，无论当前连接是否属于 Krill。
3. 线路下拉框将“自定义服务”和三条 Krill 线路放在同一层级，服务商与服务商的线路混在一起。空白配置并非默认选中 Krill；程序会从已读地址识别预设。
4. 配置编辑器将“Krill 推荐”放在全局分类中，并为其提供跳过高级项隐藏规则的特殊逻辑。首次进入配置编辑页展示所有分类，常用设置没有成为默认入口。
5. 点击推荐按钮的调用路径为 `RecommendedClicked → KrillRecommendedSettings.Stage → Editor.Configure → ShowPage("catalog") → ShowKrillRecommended`。它只操作本地草稿，不请求 Krill 服务。真正的模型请求由“获取模型”触发，访问当前所选地址的 `/models`。
6. `Stage` 校验后直接将七个值写入共享字典；已有同名草稿会被替换，未先展示差异，也未过滤与有效值相同的项。返回信息固定为七项。现有“撤销修改”会撤销所有页面的修改，不是只撤销本次模板。
7. 保存仍需用户点击全局“保存配置”。推荐设置本身不更换服务地址或密钥；若用户同时修改过连接，统一保存会一起保存这些连接修改。

## 推荐布局

继续使用左侧导航、右侧内容和底部统一保存栏。

- 默认打开“配置编辑”，初始筛选“常用”。次级切换“全部”“已修改”；全量分类和搜索仍然保留。返回页面时保留搜索、分类、分页和滚动位置。
- “连接配置”作为第二个导航项。内容按“服务连接 / 默认模型”分组，移除常驻推荐模板区。
- “备份与恢复”保留第三个导航项。底部“配置位置”“使用说明”保留；版本说明由“配置与 PAT”改为“本地配置编辑器”。
- “配置编辑”页标题右侧提供次级按钮“配置模板”；模板是低频操作，不新增常驻一级导航。
- 全局底栏显示“未保存 N 项”，主按钮“保存配置”；保留“撤销修改”，增加“查看更改”。查看更改优先展示字段差异，完整脱敏文件预览作为其中一项功能。
- 表单主体宽度约 680–760 DIP，字段间距由当前普遍 22 DIP 调整为 16–18 DIP；分组间距 24 DIP。窄窗口按单列排列，保持底部保存栏可见。
- 常用设置保持中文标题与直接操作，技术字段与长说明折叠。高级列表保留每页最多 30 项及全量搜索，避免恢复一次渲染全部控件。

## 连接预设

表单将“服务线路”改为“服务商”：自定义服务、Krill。只有选择 Krill 时再显示“线路”：三网优化 CDN、海外线路、国内极速。Krill 名称在服务商字段出现一次，线路名称不重复品牌。

读取既有配置时继续按现有规则识别地址与旧域名；不能因为本次 UI 调整重写用户地址、认证或模型。空白配置不默认导入任何服务商。对于已识别的官方登录状态，显示准确状态并沿用原有保留行为；本阶段不增加未实现的官方登录按钮。

服务类型仍可查看和修改：Responses API / PAT 中转。凭据标签根据认证选择显示“API Key”“PAT”或“访问凭据”，避免所有场景都标为 API Key。选择线路只配置连接，不自动叠加任何行为模板。

可以在 Krill 连接下提供低强调文字入口“查看此服务的社区模板”，点击仍先打开模板详情。

## 模板流程

入口：配置编辑 → 配置模板 → Krill 社区方案 → 查看差异并选择项 → 加入草稿 → 全局保存。

“Krill 社区方案”保留真实来源，不改名冒充通用或官方推荐。“来源：Krill / Superba”“适用说明”“依据的配置目录版本”放在模板详情，默认页面不出现品牌推荐口号。第一版只收录已有这一套，后续模板经单独验证再增加。

详情展示字段中文名、当前有效值、模板目标值、状态与复选框。当前有效值应包含现有草稿。列表区分新增、替换、相同和草稿冲突；相同项不计入修改数，同名已有草稿默认保留，可逐项选择覆盖。打开或取消详情不修改草稿。

目前七项配方保持可查看、可选用。下表状态依据项目内置目录，不代表已对所有 Codex 版本完成兼容性验证。

| 配置 | 模板值 | 建议交互 |
| --- | --- | --- |
| web_search | "live" | 展示联网搜索方式的变化 |
| features.fast_mode | true | 展示 Fast 模式变化，不承诺对所有服务生效 |
| analytics.enabled | false | 单独说明关闭使用统计，不称为性能优化 |
| features.context_management | true | 目录标为开发中，默认不勾选 |
| features.token_budget.enabled | true | 目录标为开发中，默认不勾选 |
| features.token_budget.use_history_notes_extension | true | 目录标为开发中，默认不勾选 |
| suppress_unstable_features_warning | true | “隐藏实验功能提示”独立展示，默认不勾选 |

非实验项可预选，但已有草稿冲突项默认不选。需要原配方的用户可明确勾选全部七项；不在后台暗中应用实验项。

“加入草稿”只加入选中且实际不同的项目。操作后保持当前工作上下文，显示“已加入 N 项”，提供“查看已修改”和“撤销本次模板”。用户仍可手动编辑后再保存。

撤销本次模板应恢复模板操作前的草稿状态，保留其它页面先前修改；如果某项在应用模板后又被手动修改，不能静默用旧值覆盖，需保留后续编辑或提示逐项处理。

## 实现范围

配置说明同属本次改版范围，具体交互和文案见下文“配置说明与作用解释”。当前旧实验项先从默认常用列表移出；保留已存在的配置值供查看、编辑，不自动删除。模板保留原配方记录，但对无法确认兼容性的项目提示“待验证”，禁止默认选中。

建议作为下一版 0.7.0 实施，拆成两个可验证步骤：

1. 入口与布局：默认常用配置、服务商与线路分层、模板入口、去掉全局 Krill 分类和底栏 PAT 定位文字。保留原有网络请求、认证、保存和备份逻辑。
2. 模板引擎：用通用 `ConfigTemplate` 定义 ID、名称、来源、适用条件、配置项和说明；用 `BuildTemplateDiff` 生成预览，再由 `StageSelected` 合并选择结果。原 `KrillRecommendedSettings` 七项内容迁为内置模板数据。编辑器按模板字段集合展示，去掉 `ShowKrillRecommended` 与 `filter == "krill"` 分支，模板详情仍明确展示开发中状态。

服务连接预设与行为模板采用独立数据结构。无需引入插件系统、在线模板市场或多账户管理。

## 验收

- 默认首页、配置分类和自定义服务流程不出现 Krill 推荐入口；Krill 服务商、线路与社区模板仍可找到。
- 读取已有 Krill 连接、旧域名、自定义连接及官方认证文件时不发生自动迁移或重写。
- 打开/取消模板零修改、零网络请求；加入模板不改地址、凭据或环境变量；仅编辑配置项保存时保留认证。
- 模板可逐项应用、重复应用不制造无效修改、草稿冲突可见；撤销本次不抹掉其它修改。
- 开发中项与隐藏提示需明确选中；模板预览不把内置目录校验等同于运行时兼容性保证。
- 常用/全量搜索、分页及跨页草稿正常；高级页渲染保持有界，性能与 0.6.1 基线对比。
- 在 960×640、默认窗口、125% / 150% 缩放、深浅色与键盘操作下，表单和保存栏无遮挡。

## 配置说明与作用解释

### 呈现方式

每个配置项下固定显示一句“对 Codex 的作用”，点击“详细说明”展开更多内容。不能仅重复名称，例如“上下文管理：管理上下文”，也不把技术字段或大段英文默认铺满列表。

展开后依次展示：

1. **实际作用**：改变哪一部分行为；能力开关与实际启用分开描述。
2. **选项差异**：每个值的中文解释；数值注明单位。布尔值显示“开启 / 关闭 / 跟随默认”，仍可查看原始 TOML。
3. **何时调整**：给具体场景；涉及速度、用量、隐私或稳定性的权衡才补充对应说明。
4. **适用条件**：模型、客户端、认证方式或服务端支持要求，只写已核实的信息。
5. **默认与当前值**：区分文件值、草稿值、已知的文档默认；无法推导实际运行值时显示“运行值未检测”。
6. **来源**：官方文档链接、核对日期，或明确标为“历史目录说明 / 当前版本待验证”。

模板详情复用同一套说明，此外显示“当前值 → 模板值”和本次变化。说明可按需展开，避免七项模板变成七段长文。

### 首批中文说明文案

以下是拟用于界面的文案，不代表已经修改发行版。

| 配置项 | 常驻简述 | 展开说明重点 |
| --- | --- | --- |
| 联网搜索 `web_search` | 控制 Codex 使用哪种网页搜索方式。 | `disabled` 关闭搜索工具；`cached` 使用预索引结果；`indexed` 由搜索索引约束外网访问；`live` 获取最新网页内容。用途是调整搜索方式，不代表每轮都自动搜索。[官方说明](https://learn.chatgpt.com/docs/config-file/config-basic) |
| 推理强度 `model_reasoning_effort` | 设置模型处理问题时的推理投入。 | 档位按模型支持情况展示。复杂分析可考虑较高档位；不承诺提高后每个任务都更准确。未确认的模型不提供“一键最高档”。[官方说明](https://learn.chatgpt.com/docs/config-file/config-basic) |
| 允许 Fast 模式 `features.fast_mode` | 允许使用模型支持的 Fast 模式选项。 | 这是功能入口开关；实际选择快速服务档位是另一项设置。模型和账户仍需支持。[官方参考](https://learn.chatgpt.com/docs/config-file/config-reference) |
| 服务档位 `service_tier` | 设置请求优先使用的服务档位。 | 支持时可选择 Fast；官方持久化示例同时设置 `service_tier = "fast"` 和 `features.fast_mode = true`。快速档位可能增加用量消耗；第三方服务需另行确认支持情况与计费。[官方说明](https://learn.chatgpt.com/docs/agent-configuration/speed) |
| 上下文窗口 `model_context_window` | 配置模型可用的上下文容量，单位为 Token。 | 编辑器应提示核对模型实际容量，不把填写更大的数字描述成模型扩容。默认建议保留模型默认值。[官方参考](https://learn.chatgpt.com/docs/config-file/config-reference) |
| 自动压缩阈值 `model_auto_compact_token_limit` | 指定何时自动压缩会话历史，单位为 Token。 | 未设置时使用模型默认。界面以“达到阈值触发压缩”解释，不描述成总消费上限。[官方参考](https://learn.chatgpt.com/docs/config-file/config-reference) |
| 使用统计 `analytics.enabled` | 控制本机或当前配置的使用分析统计。 | 默认由客户端决定。当前官方文档说明 CLI 中关闭它也关闭自定义 OTLP 指标导出；旧目录文案与此不同，应按客户端和版本维护。不能把它描述成关闭所有网络通信。[官方参考](https://learn.chatgpt.com/docs/config-file/config-reference) |
| 隐藏实验功能提示 `suppress_unstable_features_warning` | 隐藏启用开发中功能时出现的警告。 | 只影响提示显示，不能把实验功能变为稳定功能。[官方参考](https://learn.chatgpt.com/docs/config-file/config-reference) |
| 旧实验性上下文管理 `features.context_management` | 历史实验配置，当前可用性需核实。 | 本项目历史目录曾描述为上下文预算与笔记能力的组合开关；当前官方参考仅明确列出 `.experimental_mode` 且标为暂不可用。不能照搬历史适用条件，也不能断言旧布尔写法一定生效。[当前官方参考](https://learn.chatgpt.com/docs/config-file/config-reference) |
| 旧上下文预算 `features.token_budget.enabled` | 历史目录描述：向模型提供上下文用量信息。 | 当前公开配置参考未检索到此字段；未验证前不承诺可用，更不能解释为 API 账单上限或自动省 Token。[本地历史目录](../config/config-schema.json) |
| 旧历史与笔记扩展 `features.token_budget.use_history_notes_extension` | 历史目录描述：向模型提供历史与笔记扩展。 | 当前公开配置参考未检索到此字段；标为待验证，不把历史适用条件当作当前保证，也不宣称可实现无限上下文或永久记忆。[本地历史目录](../config/config-schema.json) |

```text

```

### 数据与验收

- 用配置字段路径关联结构化中文帮助内容；与导入的配置 schema 分开维护，更新上游字段时不覆盖人工文案。
- 建议帮助数据包含 `summary`、`effect`、`valueHelp`、`usage`、`limitations`、`relatedKeys`、`sources`、`verifiedAt`、`verificationStatus`。不知道的默认值或版本范围留空。
- 搜索覆盖中文说明与字段路径。未收录字段仍可编辑，并明确显示“尚无经过核对的作用说明”，不能根据字段名称自动编造功能。
- “跟随默认”解释为移除本文件的覆盖值，可能受其它配置层影响。官方文档列明 CLI 覆盖、项目配置、Profile 等优先级，因此仅查看一个文件不能确认最终运行值。[配置优先级](https://learn.chatgpt.com/docs/config-file/config-basic)
- 不统一承诺所有设置保存后即时生效。按已核实的字段行为提示重载或新会话要求；未知时说明待客户端重新读取，并提示验证实际行为。
- 首批覆盖常用设置、连接字段与现有模板七项；其余字段逐步补齐，避免将笼统自动翻译当作可靠帮助内容。
- 验收重点：Fast 开关与服务档位不混淆；Token 预算与消费预算不混淆；默认值与运行值不混淆；旧实验功能不包装成通用推荐。
