# 手机连接

通过自己的 HTTPS 根域名，在 Lovest Code 安卓 App 或浏览器中使用 Codex 工作台。接入支持 Codex App、CLI 和已登记的 WSL / SSH。Windows 完整安装包附带手机后台及 Python 运行时。

## 电脑设置

1. 保持电脑与所选执行端可用。继续已有 App 聊天时保留原 owner；新建、继续 CLI 或远端任务使用工作台的显式操作。
2. 在 **手机连接 → 连接与配对** 填写 HTTPS 根域名和独立手机账号，密码须为 12–256 字符。入口格式为 `https://域名[:端口]`，例如 `https://codex.example.com:888`。沿用原账号时留空密码可保留原值。
3. **本机监听端口** 默认为 `13090`，范围为 `1024–65535`。如需修改，在入口表单展开高级设置，并同步修改反向代理目标。端口被占用时，启动步骤会提示错误。
4. 点击 **查看并保存入口**，再点击 **启动手机服务**。配置好反向代理后，点击 **检测 HTTPS 入口**，核对证书和实际服务实例。
5. 检测通过后点击 **生成配对码**，用 Lovest Code 扫码。也可以在 App 手动输入 HTTPS 域名，用上述账号密码登录。

手机访问设置和 Codex 主配置各自保存。

## 反向代理

如果群晖通过**公司公网 IP**转发到电脑，在路由器将 HTTP 端口映射到 Windows 电脑即可。Dock 无需填写公司或家里的公网来源 IP。旧设置中的代理 IP 在升级后不再限制连接。

端口可以分别使用：外部 HTTPS/FRP 入口 `888`，群晖目标为 `http://公司公网IP:13090`，公司侧转发到 Windows 的 `13090`。保持 Host 为外部域名及 `:888`。此链路中的公司公网端口转发必须能到达电脑，群晖的 frpc 本身不会自动开放公司侧网络。

手机 HTTP 端口监听所有 IPv4 接口。本机代理可转到 `http://127.0.0.1:13090`；群晖等设备填写电脑可达的局域网 IP 或公司公网 IP。Windows 防火墙如有拦截，需放行该端口。程序不自动修改路由器或防火墙。

`127.0.0.1` 指向使用该地址的设备自身。在群晖上填写它，目标就是群晖；除非群晖该端口已有通向电脑的通道，否则不能到达电脑。电脑和代理在不同网段时，还须存在可达的路由、VPN 或 FRP；只改变监听范围无法建立网络通道。

- 将整个 HTTPS 根站点转给手机 worker，包括 `/`、静态资源和 `/api/`；不支持路径前缀部署。
- 保留原始 `Host`，包含外部非默认端口；例如外部 `:888` 不能被替换为 `127.0.0.1:13090`，也不能丢掉 `:888`。
- 保留浏览器 `Origin`、Cookie、`X-CSRF-Token` 与安卓 `User-Agent`。远端代理的 `X-Forwarded-For` 不作为可信身份；登录限速和设备 IP 使用电脑实际收到的连接来源。因此设备列表可能显示代理或 NAT 地址，同一代理的多次错误登录共享新登录限制。0.13.3 起自动限制不会撤销已有设备授权，可在 Dock 解除登录限制。
- 使用有效且受手机信任的 TLS 证书。不要将 HTTPS 跳转到另一域名，也不要缓存 API 或网页内容。
- 发送操作可能等待原 Codex owner 响应，代理读取超时应大于 90 秒。历史和状态使用增量 / SSE 同步，禁用代理缓冲；终端需要 WebSocket，透传 `Upgrade`、`Connection` 和子协议，长连接读取超时至少 90 秒。
- 私有管理端口由程序单独选择，只供本机 Dock 控制；不要转发到公网。

502 表示入口未能连接到后台；检查服务运行状态、代理目标、端口映射和防火墙。403 表示已收到请求但 Host、Origin 或登录验证不匹配；核对完整外部 Host（含端口）和 Origin 转发。入口检测会区分这两类错误。

直接打开 `http://127.0.0.1:13090/` 会显示本机诊断页，并提供配置的 HTTPS 入口。该 HTTP 地址不提供登录和聊天 API。

## 工作台及账号

完整的聊天、项目、模型、权限、审批、消息队列、富文本、附件、文件预览、Git、终端和通知功能见 [功能对照](mobile-upstream-comparison.md)。界面根据执行端能力显示操作；阅读历史不会自动启动或接管执行端。

在电脑的 **连接与配对** 页面展开 **服务与访问**，点击 **选择允许手机访问的 Codex**，在本机浏览器登记账号与 CLI / WSL 接入。链接 60 秒内一次有效，授权 30 分钟，仅绑定 `127.0.0.1`。账号切换或恢复可能重启 Codex，按页面提示确认。手机端可查看和切换已保存的接入。

SSH 需要系统 ssh 与原有主机登记；WSL 需要可用发行版与执行端。通知需要主动配置渠道或安卓接收权限；入口通知在 HTTPS 检测通过后提供当前地址。程序不自动配置路由、证书或其他隧道。

## 启停、数据和升级

收起窗口或选择 **仅退出 Dock** 后，手机服务继续运行。在 **手机连接 → 服务设置** 可分别启动、重启和停止。重启使用已保存的设置，手机会短暂断开，原有登录保留。点击 **查看设置并保存启动** 可核对并保存当前表单。

设置、模型网关和托盘菜单都可打开 **退出…**。选择 **停止网关并退出** 或使用软件更新页的 **安装更新并退出** 时，Dock 会先处理草稿，并等待当前目录的两个网关退出。覆盖安装时，安装器会核对目标安装目录与手机后台进程的身份，再请求对应进程正常退出。

每个 Codex 配置目录独立保存手机设置与设备记录，位于 `%LOCALAPPDATA%\CodexConfig\mobile\<目录标识>`。Dock 启动设置使用当前 Windows 用户 DPAPI 加密，设备记录仅持久化令牌摘要。工作台账号、远端与通知配置按上游保存在同一私有数据目录；请整体备份此目录。更改密码、账号或域名后需要重新登录；撤销设备后，其保存的 Cookie 也不能恢复授权。

在手机服务设置中开启 **打开 Dock 时自动启动**，可让 Dock 在启动时运行当前目录的手机服务。此选项默认关闭，按配置目录保存。若需随 Windows 登录运行，还需在 Dock 的设置页开启开机启动。

升级前可从托盘选择停止网关并退出。升级后打开 **手机连接 → 连接与配对**，按当前步骤启动服务或检测入口。便携版本需完整解压并保留主程序旁的 `mobile` 目录。回退前应停止新服务并恢复升级前备份。升级保留个人 Codex 配置和手机数据。
