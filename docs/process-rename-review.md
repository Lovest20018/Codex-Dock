# Codex Dock 进程改名与代码 review

2026-10-28。范围：当前工作区的界面、网关生命周期改动，以及进程改名涉及的构建、打包、安装升级和验证脚本。

## 改名

- 主程序集为 `CodexDock.dll`，入口和任务管理器中的主进程为 `CodexDock.exe`。
- 网关通过当前程序路径启动，同样为 `CodexDock.exe --model-bridge ...`；未按进程名称终止其他程序。
- 安装器、启动入口、卸载图标、便携包和当前使用文档统一到新名称。
- 升级保留原 AppId、安装目录检测和用户数据目录，删除旧的五个应用入口文件，并更新快捷方式。`CodexConfig.Core.dll`、命名空间、provider ID、加密 entropy、连接文件和模板库路径保留兼容。
- 安装器通过 Inno Setup 的资源登记检测旧入口占用。此机制参考 [Inno Setup 官方说明](https://jrsoftware.org/ishelp/topic_isxfunc_registerextracloseapplicationsresource.htm)，使用本机 Inno Setup 6 的双参数签名。

## review 发现并修复

1. **P2：概览焦点丢失。** 网关每三秒检查时即使只变化计数也重建整页，键盘聚焦的按钮被移除。现在仅在已保存配置、网关状态或草稿状态实际改变时重建；检查覆盖计数刷新后控件实例和键盘焦点保留。
2. **P2：停止网关的异步结果串到其他目录。** 停止期间选择另一配置目录，旧结果仍能覆盖当前目录的状态。现在停止完成与失败都核对目录和连接快照；检查在真实隔离网关停止尚未完成时切换目录，确认新目录状态不变。
3. **P2：`package.ps1 -SkipPublish` 删除待打包目录。** 原脚本在判断此开关之前删除发布目录，导致随后找不到入口。现在只在重新发布时清理，且先验证清理路径位于 artifacts 内。

构建与 UI 报告同时绑定 EXE 和应用 DLL 的 SHA-256，避免 .NET apphost 不变但应用 DLL 已变化时沿用旧报告。

## 验证范围

- 核心配置、加密备份、代理、模型请求与 WebSocket：58 项隔离检查。
- 发布程序 UI 检查新增进程/程序集名称、概览焦点与跨目录停止竞争；保留原有 7 页、最小窗口、三档模拟缩放、模板、保存恢复和托盘检查。
- 安装验证在工作区独立目录预置旧入口文件及用户文件，确认旧入口清理、新程序文件一致、安装程序可运行，并验证卸载保留用户文件。
- `/VERIFYONLY` 不创建或删除真实桌面/开始菜单快捷方式，不改真实安装登记；快捷方式目标通过安装脚本审查，未对用户现有安装执行覆盖升级。
- DPI 检查使用 WPF LayoutTransform 模拟，未改变系统 DPI。未执行真实上游推理或官方账号登录。

## 最终结果

- 核心回归：58/58 通过；发布与安装后的 UI 回归各 72 项通过。
- 独立网关脚本：新进程名称、认证健康检查、非模型路由拒绝、正常停止、父进程退出后端口释放均通过。
- 安装验证逐文件对比 642 个发布文件，五个旧入口文件均清理，卸载保留用户文件，真实安装登记与用户认证环境变量未改变。
- `-SkipPublish` 的隔离目录保留检查通过。
- 本次审查未发现剩余阻断项。真实桌面快捷方式升级和真实系统 DPI 的限制如上，不据模拟与隔离检查宣称已覆盖。
