# 连接切换与网关管理（2026-11-11）

此记录对应当前本地开发构建，未修改版本号或发布 GitHub Release。

2026-11-12 后续认证调整以 [API Key 迁移](api-key-auth-migration-2026-11-12.md)和[官方登录收敛](official-login-convergence-2026-11-12.md)为准。原设备码和 CLI 登录流程已移除。

## 操作变化

- 连接方式改为两个有说明的选择卡片，同时显示当前文件使用的方式与尚未保存的切换。
- 来回选择 API Key 直连与官方账号模式，保留地址、模型、服务凭据、代理草稿及已读取或从备份暂存的官方登录。直连不会使用暂存的官方登录；回到原文件值不产生多余的未保存状态。
- 确认页明确显示认证方式的变化，保留差异确认、加密备份、外部冲突检测与重新读取核对。保存直连后，之前的官方登录可以通过原有备份恢复。
- 新增独立的“网关管理”导航。本机模型网关与手机网关分别提供状态、启动、停止、重启、设置入口和自动启动开关。顶部的状态按钮跳转到对应网关。
- 连接页只配置模型入口与官方身份，手机连接页保留 HTTPS 设置、保存并启动、入口检测、接入管理和配对；持续的网关启停统一在网关管理操作。
- 保存模型连接不再隐式启动网关。混合连接的保存成功页提供“前往网关管理”，引导先启动网关，再重新打开 Codex。

## 自动启动规则

两个“打开 Dock 时自动启动”选项默认关闭，按配置目录分别保存。仅在本次 Dock 启动时尝试一次；读取状态、切换页面、保存普通配置以及定时轮询不会启动已停止服务。一个网关失败不会阻止另一个启动，错误保留在对应卡片。

“登录 Windows 后启动 Dock”是独立选项，与应用设置共用同一启动项。它明确记录开启时的程序及配置目录；查看其他目录不会误显示该目录已开启。需要登录 Windows 后运行网关时，必须同时开启 Dock 的 Windows 启动项与该网关的自动启动。

开关立即保存，不保存连接草稿，也不立即启动或停止进程。关闭自动启动不影响当前已运行服务；手动停止后，在本次 Dock 运行期间不会被自动拉起。关闭窗口仍收起到托盘，普通退出保留已启动网关，显式“停止网关并退出”负责结束两者。

启动选项只包含两个布尔值，存于 `%LOCALAPPDATA%\CodexConfig\gateways\<目录标识>\startup.json`，不包含凭据，也不进入 Codex 配置。读取损坏或错误类型的选项会跳过自动启动并显示错误；保存使用临时文件替换，失败保留旧选项。
