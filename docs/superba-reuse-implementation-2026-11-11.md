# Superba 第一批合并与配置生效（2026-11-11）

本轮在 Windows 0.16.3 源码基线上实现配置资料、模板推荐、HTTP 确认和保存后桌面重启联动。对应发布版本为 Windows 0.17.0；打包和安装验收由发布流水线记录。模型目录管理和 PAT 项目恢复仍按评估单独推进。

资料更新只增加编辑选项，不会自动启用字段或把新版默认值写进用户文件。目录定义数包括父表和动态模板，不是同等数量的独立开关。

## 使用新配置

1. 使用包含本轮修改的 Dock 构建，在“全部配置”找到需要的字段。查看用途、类型与核查版本，再按需设置。
2. 点击“查看并确认修改”，核对文件目标和前后值，再确认写入。写入前自动加密备份，完成后重新读取核对。
3. 在成功页点击“重启 Codex 并应用”。确认提示中会列出桌面程序路径与本次配置目录；先完成正在运行的工作，再继续。
4. 重新打开后新建聊天核对。如果行为与文件不符，使用“查看配置来源”选择对应执行端、项目目录和 Profile 条件读取来源。

本机核查到的内核为 `0.167.0-alpha.3.2`，早于新增资料对应的 `0.168.0-alpha.4`。重启不会为旧内核增加字段支持；需要新字段时，应升级实际读取配置的桌面内核或 CLI，并再次核对。`verified_since` / `updated_in` 是资料核查标记，不宣称最早支持版本。

项目配置、所选 Profile、启动参数和组织要求仍可覆盖用户文件。官方的 [Config basics](https://learn.chatgpt.com/docs/config-file/config-basic) 列出了配置优先级；配置来源快照也不等于已打开聊天的会话参数。

## 重启行为与限制

- 识别当前会话内的 Codex 桌面 GUI，支持商店版 `OpenAI.Codex` 包中的 `ChatGPT.exe` / `Codex.exe`，以及已知标准目录内带 OpenAI 元数据的 `Codex.exe`；不把独立 CLI、Dock 或后台服务作为桌面退出目标。
- 保存结果保留当次文件快照。重启前及退出后再次比较；即使后台已重新读取其他程序的修改，也不会把它当成本次已确认保存的结果继续启动。
- 通过正常 `WM_CLOSE` 请求退出，等待捕获的桌面进程退出。取消、对话框阻拦、驻留托盘或超时均停止重启，不强制终止进程；配置仍已保存，可完成退出后重试。
- 实例使用 PID、启动时间和完整程序路径核对；出现新实例或多个根实例时停止，避免重启对象发生变化。
- 启动时明确传入本次 `CODEX_HOME` 和保存的 `CODEX_AUTHAPI_BASE_URL`，值为空时移除继承的旧覆盖。使用已识别的桌面程序直接启动，不依赖终端当前目录或旧的系统托盘环境。
- 使用普通桌面启动方式，未恢复自定义命令行参数。不管理 CLI、IDE、WSL / SSH 或手机执行端的重启；这些执行端需按各自方式重新加载。
- “已重新打开”只确认桌面进程出现，不宣称所有配置已被新聊天采用。没有在本次开发验证中退出或重启真实 Codex 桌面端。

HTTP 确认只约束 Dock 的探测和网关。API 直连时，Codex 根据已写入的地址自行发请求；撤销 Dock 的确认不会改写该地址或接管它的网络行为。需要停止直连，应在 Codex 停止任务，或更换地址并保存、重新打开。回环本机模型网关和手机反代沿用各自的本地连接契约。
