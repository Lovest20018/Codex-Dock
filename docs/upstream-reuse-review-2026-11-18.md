## 建议优先适配

| 优先级 | 内容 | Dock 现状与建议 |
| --- | --- | --- |
| P1 | **新模型与原生能力目录同步** | Dock 的模型列表读取此前只保留名称，而固定审核依赖受管目录内的映射。选择 `gpt-6.2-sol` 后旧目录缺少该模型，因此保存被拦。应保留当前服务明确返回的原生能力，与主模型及 `codex-auto-review` 映射一起预览、备份和保存。不得通过复制 6.1 元数据或关闭审核解锁保存。 |
| P1 | **Codex 启动的回环代理排除** | Codex++ 2.7.2 补齐启动环境的 `NO_PROXY`。Dock 自己的本机 HTTP 客户端已禁用代理，但 `CodexDesktop.CreateStartInfo` 目前仅设置配置和账号环境，未补充回环排除。适合保留原有 `NO_PROXY`，未设置时保留启用中的 WinINET `ProxyOverride` 语义，再补 localhost、IPv4/IPv6 回环；仅作用于 Dock 启动的子进程。 |
| P1/P2 | **Windows 商店包原生内核发现与可运行副本** | Superba alpha.2 校验包内文件、已有副本与自己的副本。Dock 已有商店 GUI 的执行别名启动，核心执行端查找仍主要依赖运行进程、PATH 和 `%LOCALAPPDATA%/OpenAI/Codex/bin`。值得补安装包发现及按 SHA-256 校验的匹配副本，区分 GUI 启动与 app-server 内核执行；先复现需要副本的系统条件，再决定是否引入约 490 MB 的复制缓存。 |
| P2 | **配置资料与常用项更新** | Superba 资料已覆盖 Codex 0.171.0-alpha.5 及桌面 26.1111 的 0.169.0-alpha.11.1。Dock 资料仍标记 11 月 11 日基线。可更新 schema、中文解释、兼容版本和常用项分组；新资料不自动开启新字段。 |
| P2 | **已验证的最终响应 ID** | Codex++ 新增最终 `finalResponseId`。Dock 目前主要保存计时、状态和计数，可增加有界的最终响应标识用于对照诊断。只接受完整完成事件，不保存正文，也不把请求 ID 当成响应 ID。 |

Codex++ [WebSocket 适配](https://github.com/BigPizzaV3/CodexPlusPlus/blob/70fb845eef3a44bfb2e44d382eb4b75fa7ec0204/crates/codex-plus-core/src/gateway/chatgpt_backend.rs)修复的是它在订阅后端转换中删除 `previous_response_id`、改写孤立工具结果的问题。Dock `ModelBridge.PumpAsync` 当前逐帧转发原字节，不执行这套转换，不能把上游修复直接算作 Dock 缺陷。404/405/426/501 握手状态也已保留给原生客户端判断回退。适合补针对性回归，暂不引入上游转换器或重试状态机。

上游对官方账号默认上下文的修复也不宜照搬硬编码：Dock 原生目录分支保留服务声明，未把官方窗口统一写成 272000。应继续尊重明确配置和当前来源；Superba 的 GPT-6.2 价格表和模型名不能证明某个第三方入口具有相同能力。

## 手机连接来自哪里、还可复用什么

手机后台与 Web 工作台来自该仓库；安卓外壳、应用身份、固定 HTTPS 接入和 Windows 配置控制由 Dock 维护。基础快照仍为 **2.1.7**，另有 2.2.0 / 2.2.1 选择移植和 **31 项显式 overlay**，因此看到旧基础版本并不代表缺少所有 2.2.1 修复。来源见 `src/CodexMobile/UPSTREAM.md`、`upstream-manifest.json` 与 `upstream-overlay.json`。

已具备的 v13 结构校验、跟随连接恢复、模型失败保留草稿、账号隔离、单个远端列表失败隔离，应继续使用，详情见[首批移植记录](mobile-upstream-backport-2026-11-15.md)。

| 建议顺序 | 可复用能力 | 适配边界 |
| --- | --- | --- |
| 下一批优先 | **聊天内交互图表 visualize** | 用户收益明显。需要同时移植会话鉴权接口、预览资源清单、隔离壳与自有安卓全屏导航；图表追问只加入草稿，由用户发送。不能只拷一个 iframe。 |
| 同批小项 | **`/` 命令菜单、可空的新聊天名称、原生消息时间** | 继续依据当前 Codex 接入实际能力，保持创建幂等、IME 防误提交和未知结果不重放。 |
| 定向核验 | **安卓连接探测期间可返回、整体探测时限和取消** | 上游使用多信道外壳，我们是自有固定入口外壳。先对照自己的 MainActivity 与 ConnectionDiscovery，补取消、迟到回调、失效凭据恢复及离线返回回归，再选必要改动。 |
| 后续专项 | **v13 附属会话归属与延迟输出** | 已移植部分并不等于完整支持 `attachedToThreadId` 和 `deferredOutputTurnId`。需要核对原生协议、历史读取和侧聊生命周期后单独实施。 |

保留 Dock 已有有效设备授权不被同 IP 新登录失败清退的规则、账号范围草稿、Codex-only 和固定入口策略。自有安卓继续使用既有包名和签名；上游 APK 不作为 Dock 的升级包。Antigravity、其他客户端、多信道部署、项目外文件浏览及 CLI 批量释放暂不随兼容修复带入。

## 暂缓的扩展

- Superba 多官方账号库、会话目录迁盘：有价值但会扩大凭据、任务审计、恢复和文件生命周期范围，适合独立方案与验收。
- 自动消息预测：上游每轮会增加模型请求；当前配置工具不应默认引入额外请求。
- 上传压缩及解码失败重发：需要传输协商和明确的不可执行拒绝证据。当前透明网关不为此新增自动重放。
- Codex++ main 的低价压缩模型、图片改发另一模型、供应商自定义头、微信专注会话：是新产品能力，尚未发布；不随新模型保存问题一起引入。
- API Key 分支聊天的 Statsig 兜底、Windows sandbox 状态重查：两者依赖特定桌面构建及页面内部行为。Dock 尚无对应模块注入流程，先在隔离构建复现，再决定适配。

建议实施次序为：**模型目录刷新 → 回环代理与执行端发现 → 配置资料 → 手机图表与小型交互 → 其他专项**。每批使用自己的隔离回归和交付记录，不能把上游发布说明当作我们已经完成的测试。
