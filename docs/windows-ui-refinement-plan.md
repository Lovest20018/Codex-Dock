# Codex Dock Windows 界面精修任务书

本轮在 Codex Dock 的原生 WinUI 3 界面中完善页头、首页、连接表单和高级工具。视觉基线采用已有的灰绿主题和常用操作层级。实现及验收范围见 [0.19.8 验收记录](review-0.19.8.md)。

## 依据与目标

| 页面 | 原窗口中看到的问题 | 本轮目标 |
| --- | --- | --- |
| 首页 | 配置目录按钮先于页标题出现。两块大白卡权重相近，第二块混排目录名、连接类型、地址、模型和运行状态。 | 先看到当前状态和下一步，再扫一列就能找到模型、地址和运行状态。 |
| 高级工具 | 十个入口都是大小随文字变化的描边按钮。宽屏内容集中在左上角，很像筛选条件。 | 三组工具横向利用可读区域，每个入口是一行可用键盘或鼠标打开的导航项。 |
| 连接与模型 | 页签、选择器、普通按钮的外形相近。宽屏表单横跨整张卡，服务认证和模型选择之间主要靠留白区分。 | 页签表达“我在哪一页”，输入框表达“我能填什么”，页脚明确“下一步做什么”。 |

## 1. 先整理共用页头与控件

- 标题作为内容区左上角的第一个视觉重点。宽窗口把当前配置目录放在同一行右侧，保留文件夹菜单和待处理修改入口。目录名过长时省略，打开菜单可读完整路径。优先保住页标题和待处理修改。空间不足时把目录和修改入口放到标题下的一行。
- 页头、搜索、卡片、表单和页脚的首个操作共用左侧基线。沿用内容区外边距 24 DIP、总宽上限约 1000 DIP。宽窗口增加的留白放在内容右侧。紧凑窗口可将外边距收至 16 DIP。页头和页脚应给中间滚动区留下足够空间。
- 沿用 `DockTheme.xaml` 的现有主题色。浅色以画布 `#F5F7F5`、表面 `#FFFFFF`、主操作 `#2C614F` 为基线。深色沿用画布 `#161E1A`、表面 `#202C26`、主操作 `#A3D1BB`。普通说明文字使用主题前景资源，字符与不同表面组合时保持清晰。错误、警告、成功以及键盘焦点继续使用有明确语义的原生状态。
- 页标题 26–28 DIP，紧凑窗口 24 DIP。区标题 16–18 DIP、半粗，正文与输入值 14 DIP。说明与字段标签 13–14 DIP。字段内部间隔约 6 DIP，相关操作间隔 8 DIP，区块间隔 16–20 DIP。常规卡片沿用 10 DIP 圆角，输入框和按钮沿用约 7 DIP。

## 2. 首页优先解决信息层级

- 第一块保留动态状态标题、状态说明和已有操作。使用很浅的灰绿底，深色使用略亮于画布的绿灰表面。动态下一步是唯一实心主按钮，例如“打开 Codex”“设置连接”或“继续编辑”。“更换模型”“连接手机”使用次级文字操作。取消读取、应用详情和异步反馈出现时在操作区自然换行。
- 第二块采用白色或深色中性表面。标题直接使用当前连接类型，例如“API Key 直连”，右上为“编辑连接”。下方按“默认模型、服务地址、配置名称、Codex 状态”排列。标签和值各自左对齐，标签列约 80–96 DIP，值列填充剩余宽度。保留动态配置名及实际状态含义，长地址、路径和模型 ID 可换行。消除同一行标签与值的重复前缀。
- “更多操作”继续折叠。首次设置、配置读取失败、待恢复、模型已保存待应用等状态走原有分支。任何颜色提示均有文字对应。

## 3. 高级工具改成分组导航

- 搜索框位于页标题下方，宽度上限 480 DIP，带放大镜。保留 Ctrl+F、别名匹配、无结果提示以及跳转到全部配置搜索字段的路径。
- 使用现有三组和十个目的地。配置组包含全部配置、Profile 文件、配置方案。网关与增强组包含 Codex 与增强、模型网关、手机服务设置。诊断与恢复组包含配置来源、聊天参数、已保存文件、备份与恢复。
- 每组是一个轻描边表面，内边距约 14–16 DIP，组名半粗。组内每个入口占一行，文字靠左，小箭头靠右，整行可点击。行高至少 38 DIP。悬停有底色，键盘焦点可见，Enter 或空格可打开。箭头作为装饰从读屏名称中排除。
- 按**工具区实际可用宽度**排版。推荐起点为 ≥760 DIP 三列、500 至 759 DIP 两列、低于 500 DIP 一列，列间距 12 DIP。按配置、网关与增强、诊断与恢复的顺序换行。搜索后只显示有结果的组；单项结果沿用当前列宽、靠左显示。调整窗口宽度时保留查询和焦点。

## 4. 连接表单收紧阅读宽度

- 宽窗口将“连接 / 模型与行为”呈现为一行页签，用选中标记区分当前页。沿用已有窄窗口下拉切页机制。身份方式选项继续作为互斥选择控件，和页签有不同的视觉表现。
- API 表单以“连接方式、服务地址、API Key”为第一组，“默认模型、读取可用模型、更多选项”为第二组。已有内容自然表达主题时，用细分隔线或间距分组即可。API 字段区域建议最大宽度 680–720 DIP，紧凑窗口填满可用宽度。保留从读取、选择、手填到核对保存的原有顺序。
- 可编辑字段用稳定的底色和轮廓，聚焦时沿用原生输入焦点。服务地址、密钥、默认模型的值和占位文字应能区分。底部“核对连接”作为当前任务的主操作，撤销作为次操作。窗口缩小时按钮要能换行并保持可达。

## 实现与验收

优先定位 `src/CodexConfig.WinUI/` 下的 `MainWindow.xaml`、`DockTheme.xaml`、`WorkspaceNavigationUi.cs`。按需调整首页字段的显示格式。保留 WinUI 原生控件的交互、主题切换、系统高对比度、读屏名称和键盘操作。本次交付聚焦 Windows 界面，不涉及调整模型、保存、登录或网关的业务规则。

1. 以 1120 × 820 的普通窗口检查首页、连接页和高级工具。首页主操作、连接摘要与字段值可以扫读。连接页的方式、地址和密钥仍能在首屏看到。
2. 以 1840 × 900 的宽窗口检查高级工具。标题、搜索和分组左边缘对齐，十个目的地分布在三组。搜索“回滚”只剩“备份与恢复”，搜索配置字段仍能到达相应编辑器。
3. 以 720 × 540 的窄窗口检查深色连接页和高级工具。页头、待处理修改及页脚可达，工具按实际宽度换列。另检查更小的逻辑可用宽度，覆盖单列工具和长模型名、长目录名的折行。
4. 更新 `WorkspaceConsolidationSmoke.cs` 中绑定旧按钮组几何形状的断言，改验列数、组顺序、焦点和入口边界。保留十个入口、搜索别名、键盘跳转、草稿独立性等行为检查。
5. 在可用的 Windows 桌面环境运行仓库的 `scripts/build-winui-preview.ps1 -Verify`。交付实际窗口截图，至少覆盖普通首页、宽屏高级工具、深色窄屏连接页。报告列出窗口尺寸、检查结果和未实测的模式。
