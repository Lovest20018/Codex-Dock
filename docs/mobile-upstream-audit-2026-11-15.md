| 优先级 | 改动与实际影响 | 当前代码证据与适配范围 |

## 安卓端如何跟进

当前产品使用 `src/CodexAndroid` 自有 MainActivity、三页原生导航和常驻 WebView，并复用部分上游 Java 辅助类。

- `DeviceBinding.java` 与 `EventClient.java` 在当前受管理快照和 2.2.1 中字节一致；当前自有 MainActivity 也已有凭据恢复、连接时限和退出时取消任务。不能把发布说明里的“Cookie 恢复”全部算作我们尚未实现。
- 2.2.1 的大量新增 Cookie／网关身份逻辑服务于多信道和地址别名合并，位于上游 MainActivity／GatewayChannels。我们的固定 HTTPS 入口无需直接采用这套体系。
- 可以单独复核 `ConnectionDiscovery.java` 的整体读取时限和取消机制；对固定入口、凭据恢复迟到回调、撤销设备后禁止恢复、离线返回电脑页补充回归，再决定是否需要原生改动。
- **第一批协议修复主要在 Windows 手机网关后端**，不以更换安卓包名或重做界面为前提。新增原生图表导航等功能才需要配套更新自有 APK。
- 上游 2.2.1 安卓包沿用了预览应用的独立身份，其与旧上游 2.2.0 的绑定和草稿不自动迁移。我们的升级必须继续使用 `io.github.lovest20018.codexdock`、既有签名和数据目录；不使用上游安装包替换自有应用。

安卓视觉和 Logo 仍按此前约定，等 Windows 工作完成后统一处理。

## 不需要重复同步或整体带入的内容

已移植的通知事件拆分与去重、冷启动样式就绪、阅读位置保留、首次复制、原图下载、reasoning content 和 Unicode 模型 ID，继续沿用当前实现。详细证据见 [2026-11-09 移植记录](mobile-upstream-backport-2026-11-09.md)。

Antigravity、Claude、DeepSeek、ZCode、新网络信道、UU、iOS／macOS 专属修复、上游桌面 Qt 更新器不属于本轮 Codex Dock 手机连接需求。上游自有服务器 SSH 部署的自定义 HTTPS 端口 UI，也不应替换我们现有的固定入口配置。

**发现了一处整体覆盖会造成的行为回退：**当前 `bridge/features/auth/auth.py` 的 Dock overlay 将新登录失败限制与已有设备授权分开。2.2.1 上游仍在同来源 IP 达到失败阈值时删除该 IP 的有效会话，并在 permitted 中应用自动封禁。对于共享代理或出口，这会影响其他已授权手机。移植必须保留我们的隔离规则，不能覆盖此 overlay；设备撤销、账号／密码变化仍按现有明确规则失效授权。

同样保留账号范围草稿、最后聊天、IME 防误提交、未知操作不重放、被动读取不启动会话、Codex-only 和固定入口策略。`upstream-manifest.json` 不应被简单改成 2.2.1；选择性移植继续逐项记录来源与摘要。

## 建议执行顺序与验收

1. **先更新 Windows 网关的协议兼容及最小连接恢复链。**验证 v11／v13、兼容的后续结构、未知结构只读、审批和任务状态、snapshot／patch 修订、断线后显式恢复、桌面重启与冷启动；发送结果不明时不得重发。
2. **再补模型、列表容错与闲置观察。**验证目录删除后模型读取、空结果不覆盖有效缓存、账号／provider／host／cwd 隔离、手动选项和草稿保留、单主机初始化失败、WSL 状态不明时不启动。
3. **随后处理自有安卓需要的功能与原生导航。**继续原包升级，验证电脑列表、登录、设备撤销、草稿、通知、后台恢复与断网返回；图表另补鉴权和隔离回归。视觉优化按 Windows 完成后的原定顺序进行。

这是更新清单与移植边界，以上验收是后续实施的要求，本次没有把它们记为已通过。
